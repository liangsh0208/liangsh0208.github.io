# FP8 量化系统：Recipe 与 Scaling Factor

> 源码路径：`transformer_engine/common/recipe/__init__.py`  
> `transformer_engine/pytorch/quantization.py`

---

## 1. 为什么需要 FP8

FP32（32-bit）→ BF16（16-bit）→ **FP8（8-bit）** 是 LLM 训练精度演进的主线。

FP8 的核心挑战：**8-bit 能表示的数值范围极小**，必须为每个 Tensor 计算一个合适的 scaling factor，将浮点数映射到 FP8 的数值域内，否则会出现大规模溢出（overflow）或下溢（underflow）。

TE 的解决方案是 **Recipe 系统**：自动管理 scaling factor 的计算与更新，对用户完全透明。

---

## 2. FP8 数值格式

```python
class Format(Enum):
    E2M1  = _FormatHelper(max_fwd=6,     max_bwd=6)      # FP4
    E4M3  = _FormatHelper(max_fwd=448,   max_bwd=448)    # FP8，更高精度
    E5M2  = _FormatHelper(max_fwd=57344, max_bwd=57344)  # FP8，更大范围
    HYBRID = _FormatHelper(max_fwd=E4M3.max_fwd, max_bwd=E5M2.max_bwd)
```

| 格式 | 指数位 | 尾数位 | 最大值 | 适用场景 |
|------|--------|--------|--------|---------|
| E4M3 | 4 | 3 | 448 | 前向传播（激活/权重，精度优先） |
| E5M2 | 5 | 2 | 57344 | 反向传播（梯度，范围优先） |
| HYBRID | — | — | — | 前向 E4M3 + 反向 E5M2（默认推荐） |

**HYBRID 是训练首选**：前向用 E4M3（精度更高，激活值范围较小），反向用 E5M2（范围更大，梯度值域宽）。

## 3. Scaling Factor 计算原理

### 3.1 核心公式

```
scale = FP8_MAX / (amax * 2^margin)
```

其中：
- `FP8_MAX`：该 FP8 格式的最大可表示值（E4M3 = 448，E5M2 = 57344）
- `amax`：Tensor 中元素的绝对值最大值（max absolute value）
- `margin`：安全裕量，默认 0，增大可防止溢出

**量化过程**：
```
fp8_tensor = round_to_fp8(fp32_tensor * scale)
```

**反量化过程**：
```
fp32_tensor = fp8_tensor / scale  # 即 fp8_tensor * scale_inv
```

### 3.2 amax 的作用

amax 决定了 scale 的大小，直接影响量化精度：
- amax 过大 → scale 过小 → 小值精度差（集中在零附近的区域）
- amax 过小 → scale 过大 → 大值溢出（截断为 FP8_MAX）

## 4. Recipe 类型详解

### 4.1 DelayedScaling（延迟缩放，最常用）

```python
from transformer_engine.common import recipe

fp8_recipe = recipe.DelayedScaling(
    margin=0,                    # scale 裕量（对数空间）
    fp8_format=recipe.Format.HYBRID,
    amax_history_len=1024,       # 历史窗口长度
    amax_compute_algo="max",     # "max" 或 "most_recent"
    reduce_amax=True,            # 分布式场景跨卡同步 amax
    fp8_dpa=False,               # 是否对 Attention 也用 FP8
    fp8_mha=False,               # 是否完整 MHA 链路用 FP8
)
```

**工作流程：**

```
第 t 步：
  1. 使用上一步（t-1）计算好的 scale 进行量化
  2. 在量化过程中记录当前 amax
  3. 将 amax 存入长度为 amax_history_len 的循环队列
  4. 每隔 interval 步，从历史队列中选 amax：
     - "max"：取整个窗口的最大值（保守，防止溢出）
     - "most_recent"：取最近一次（激进，精度高但易溢出）
  5. 用新 amax 计算下一步的 scale
```

**为什么"延迟"**：第 t 步用的是第 t-1 步的 scale，这是刻意设计——避免在每步训练中引入额外的 reduce 同步，提升训练效率。

**amax 分布式同步**（`reduce_amax=True`）：
```
当 torch.distributed 已初始化时：
  amax = AllReduce(local_amax, group=amax_reduction_group)
  
保证所有 TP/DP 并行 rank 使用相同的 scale
```

### 4.2 Float8CurrentScaling（即时缩放）

```python
fp8_recipe = recipe.Float8CurrentScaling(
    fp8_format=recipe.Format.HYBRID,
    use_power_2_scales=False,   # 是否将 scale 约束为 2 的幂
)
```

**与 DelayedScaling 的区别**：

| 特性 | DelayedScaling | CurrentScaling |
|------|---------------|----------------|
| scale 来源 | 上一步历史 | 当前步实时计算 |
| amax 同步 | 异步（下一步用） | 同步（本步就用） |
| 计算开销 | 低 | 略高（需实时 amax reduce） |
| 精度稳定性 | 高（历史平滑） | 高（实时准确） |
| GEMM 参数 | `use_split_accumulator=False`(fprop) | 分情况 |

CurrentScaling 中三个 GEMM 方向的 `use_split_accumulator` 设置不同：
```python
fp8_gemm_fprop: MMParams = MMParams(use_split_accumulator=False)
fp8_gemm_dgrad: MMParams = MMParams(use_split_accumulator=True)
fp8_gemm_wgrad: MMParams = MMParams(use_split_accumulator=True)
```

### 4.3 Float8BlockScaling（块级缩放）

```python
fp8_recipe = recipe.Float8BlockScaling(
    fp8_format=recipe.Format.E4M3,
    x_block_scaling_dim=1,      # 输入按 1D 块缩放
    w_block_scaling_dim=2,      # 权重按 2D 块缩放
    grad_block_scaling_dim=1,
    use_f32_scales=False,       # scale 约束为 2 的幂（默认）
)
```

**原理**：将 Tensor 切成若干块，每块独立计算 scale：

```
Tensor shape: [M, K]
x_block_scaling_dim=1 → 每行 128 个元素为一块 → scales shape: [M, K/128]
```

**优势**：解决了 per-tensor scale 在分布不均匀时的精度损失问题（某些行范围很大，但整体 scale 被压缩后，小值精度极差）。

**约束**：Block scaling 要求所有 GEMM 都使用 `use_split_accumulator=True`，且不支持 FP8 Attention。

### 4.4 MXFP8BlockScaling（Blackwell 专用）

```python
fp8_recipe = recipe.MXFP8BlockScaling(
    fp8_format=recipe.Format.E4M3,
)
```

**OCP MX 规格**：每 32 个连续值共享一个 E8M0 格式的 scale（即 scale 是 2 的幂次）。

```
块大小 = 32 个元素
scale 类型 = E8M0（8-bit 纯指数，等价于 2^n，n ∈ [-127, 127]）
```

**关键设计决策**：由于 scale 是按行或列方向组织的，量化后的 Tensor 和它的转置**数值不等价**（按行量化的 scale 不能直接用于转置的按列量化）。因此当同时需要正向和转置矩阵时，TE 从高精度输入同时计算两个版本：

```
fp32_input ──┬──→ quantize_rowwise  → fp8_tensor
             └──→ quantize_colwise  → fp8_tensor_T
```

### 4.5 NVFP4BlockScaling（Blackwell 专用，4-bit）

```python
fp8_recipe = recipe.NVFP4BlockScaling()
```

**双层量化结构**：

```
Level 1（局部）：每 16 个连续值 → 一个 E4M3 scale（8-bit）
Level 2（全局）：整个 Tensor  → 一个 FP32 scale

最终存储 = FP4(E2M1) 数据 + E4M3 局部 scale + FP32 全局 scale
```

**三大训练技巧**（来自 NVFP4 论文）：

1. **权重 2D 量化**：权重按 16×16 二维块共享 scale，更好利用权重的局部相关性
2. **梯度随机舍入（Stochastic Rounding）**：量化梯度时以概率方式舍入，消除量化偏置
3. **随机 Hadamard 变换（RHT）**：量化前对输入/梯度施加随机 Hadamard 变换，平滑分布中的异常值

```python
# NVFP4 自动配置各张量的量化策略
self.fp4_quant_fwd_inp = QParams(
    random_hadamard_transform=True,   # 输入：RHT
    stochastic_rounding=False,
    fp4_2d_quantization=False,        # 1D 块
)
self.fp4_quant_fwd_weight = QParams(
    random_hadamard_transform=False,
    stochastic_rounding=False,
    fp4_2d_quantization=True,         # 权重：2D 块
)
self.fp4_quant_bwd_grad = QParams(
    random_hadamard_transform=True,   # 梯度：RHT
    stochastic_rounding=True,         # 梯度：随机舍入
    fp4_2d_quantization=False,
)
```

## 5. FP8GlobalStateManager：全局状态管理

`FP8GlobalStateManager` 是贯穿整个 FP8 训练的单例状态机，负责：

- 维护当前激活的 Recipe 实例
- 在 `fp8_autocast` context 开始/结束时设置/清除 FP8 状态
- 维护所有模块的 `RecipeState`（每层的 scale/amax history）
- 触发 amax 更新和 scale 重新计算

```python
# 内部状态（简化）
class FP8GlobalStateManager:
    _fp8_enabled: bool = False
    _fp8_recipe: Optional[Recipe] = None
    _fp8_autocast_depth: int = 0          # 嵌套 context 深度
    _amax_reduction_group: ProcessGroup
    _fp8_tensors_recompute_buffer: list   # activation recompute 缓冲
```

### RecipeState：每层独立状态

每个 TE 模块拥有自己的 `RecipeState` 实例，存储该层的量化状态：

```python
# DelayedScaling 对应的 RecipeState
class DelayedScalingRecipeState:
    # 每个 FP8 Tensor 的 scale（前向输入、前向权重、反向梯度等）
    scale: Dict[str, torch.Tensor]
    # amax 历史循环队列，shape: [amax_history_len]
    amax_history: Dict[str, torch.Tensor]
```

## 6. fp8_autocast Context Manager

```python
with te.fp8_autocast(
    enabled=True,
    fp8_recipe=fp8_recipe,
    fp8_group=tensor_parallel_group,   # amax 同步的通信组
):
    output = model(input)
```

**进入 context 时**：
1. `FP8GlobalStateManager._fp8_enabled = True`
2. 设置当前 recipe 和通信组
3. 增加嵌套深度计数

**退出 context 时**：
1. 触发 `_amax_and_scale_update()`
2. 对所有注册模块，执行：
   ```python
   # 1. 从历史队列选出 amax
   amax = amax_compute_algo(amax_history)
   # 2. 计算新 scale
   new_scale = (FP8_MAX / amax) / (2 ** margin)
   # 3. 更新 scale（将用于下一步量化）
   scale.copy_(new_scale)
   ```
3. 若 `reduce_amax=True`，先 AllReduce amax 再更新

## 7. 量化兼容性检查

```python
# 运行时检查 GPU 是否支持
from transformer_engine.pytorch import is_fp8_available, is_mxfp8_available, is_nvfp4_available

fp8_ok, reason = is_fp8_available()
# FP8 需要: sm >= 8.9 (Ada) 或 sm >= 9.0 (Hopper)

mxfp8_ok, reason = is_mxfp8_available()
# MXFP8 需要: sm >= 10.0 (Blackwell)

nvfp4_ok, reason = is_nvfp4_available()
# NVFP4 需要: sm >= 10.0 (Blackwell)
```

```python
def _compute_fp8_support():
    if get_device_compute_capability() >= (9, 0):  # Hopper
        return True, ""
    if get_device_compute_capability() < (8, 9):   # pre-Ada
        return False, "需要 sm 8.9+"
    # Ada: 额外检查 cuBLASLt 和 CUDA 版本
    if tex.get_cublasLt_version() < 120103:
        return False, "cuBLASLt >= 12.1.3 required"
    if float(torch.version.cuda) < 12.1:
        return False, "CUDA >= 12.1 required"
    return True, ""
```

## 8. CustomRecipe：自定义量化策略

```python
def my_quantizer_factory(role: str):
    """role: "linear_input", "linear_weight", "linear_output",
              "linear_grad_output", "linear_grad_input"
    """
    if role == "linear_weight":
        return MyBlockQuantizer(block_size=64)
    return MyPerTensorQuantizer()

fp8_recipe = recipe.CustomRecipe(qfactory=my_quantizer_factory)
```

CustomRecipe 允许为每种语义角色（输入、权重、输出、梯度）指定不同的量化器，适用于研究自定义量化方案。

---

## 9. 各 Recipe 选型指南

| 场景 | 推荐 Recipe | 原因 |
|------|------------|------|
| 常规 LLM 训练（H100） | `DelayedScaling(HYBRID)` | 开销最低，精度稳定 |
| 对精度敏感的训练 | `Float8CurrentScaling` | 实时 scale，更准确 |
| 权重分布不均匀 | `Float8BlockScaling` | 块级 scale 更精细 |
| Blackwell 极致性能 | `MXFP8BlockScaling` | 硬件原生，零软件开销 |
| Blackwell 4-bit | `NVFP4BlockScaling` | 最高效率，精度接近 FP16 |
| 研究自定义方案 | `CustomRecipe` | 完全控制量化粒度 |
