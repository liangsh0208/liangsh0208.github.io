# 06 构建系统与扩展接口

> 源文件：`setup.py`、`csrc/deep_ep.cpp`（pybind11 绑定）、`csrc/kernels/launch.cuh`、`csrc/kernels/utils.cuh`

---

## 1. 模块作用与设计动机

DeepEP 使用 PyTorch 的 `CUDAExtension` 机制将 CUDA kernel 编译为 Python 可调用的 C++ 扩展（`.so` 文件）。这一层是整个系统的"胶水层"，负责：
- 编译期特性开关（SM80/SM90、NVSHMEM 启用/禁用、FP8、aggressive PTX）
- pybind11 接口绑定（Python 类 ↔ C++ 类的一一对应）
- 类型安全的 Python-C++ 桥接（`torch::Tensor`、`pybind11::bytearray` 等）

## 2. 构建系统（`setup.py`）

### 2.1 条件编译矩阵

```python
# 根据环境变量控制编译特性
disable_nvshmem = (NVSHMEM_DIR is None)

sources = ['csrc/deep_ep.cpp', 'csrc/kernels/runtime.cu',
           'csrc/kernels/layout.cu', 'csrc/kernels/intranode.cu']

if not disable_nvshmem:
    # 跨节点和低延迟内核依赖 NVSHMEM
    sources += ['csrc/kernels/internode.cu', 'csrc/kernels/internode_ll.cu']
```

| 环境变量 | 作用 | 默认值 |
|---------|------|-------|
| `NVSHMEM_DIR` | NVSHMEM 安装路径 | 未设置 → 禁用跨节点 |
| `DISABLE_SM90_FEATURES` | 禁用 Hopper 特性（FP8/TMA/cudaLaunchKernelEx） | 0（启用）|
| `TORCH_CUDA_ARCH_LIST` | 目标 GPU 架构 | "9.0"（SM90） |
| `DISABLE_AGGRESSIVE_PTX_INSTRS` | 禁用 ld.nc/st.na PTX | 1（非 SM90 时禁用）|
| `TOPK_IDX_BITS` | topk_idx 的位宽（32 或 64） | 64 |

### 2.2 SM90 特性控制

```python
if int(os.getenv('DISABLE_SM90_FEATURES', 0)):
    # A100 场景：退化到 SM80 模式
    # - 无 FP8（cuda_fp8.h 不可用）
    # - 无 TMA（cp.async.bulk 指令）
    # - 无 cudaLaunchKernelEx（Cluster 启动）
    # - 无 elect.sync PTX 指令
    cxx_flags.append('-DDISABLE_SM90_FEATURES')
    nvcc_flags.append('-DDISABLE_SM90_FEATURES')
    assert disable_nvshmem  # SM80 不支持跨节点
```

### 2.3 关键编译标志

```python
cxx_flags = ['-O3', '-Wno-deprecated-declarations', ...]
nvcc_flags = ['-O3', '-Xcompiler', '-O3']

# SM90 特有
nvcc_flags += [
    '-rdc=true',                          # Relocatable Device Code（NVSHMEM 设备端符号）
    '--ptxas-options=--register-usage-level=10'  # 限制寄存器用量，提高 occupancy
]

# NVSHMEM 链接（设备端静态库 + 主机端动态库）
nvcc_dlink = ['-dlink', '-lnvshmem_device']
extra_link_args = ['-l:libnvshmem_host.so.X', '-l:libnvshmem_device.a', '-Wl,-rpath,...']
```

### 2.4 NVSHMEM 设备代码链接

`-rdc=true`（Relocatable Device Code）允许不同 `.cu` 文件中的设备函数互相引用。这对 NVSHMEM 是必须的，因为 NVSHMEM 设备端符号（如 `nvshmemi_ibgda_device_state_d`）在 `libnvshmem_device.a` 中定义，需要链接阶段解析：

```python
nvcc_dlink = ['-dlink', f'-L{nvshmem_dir}/lib', '-lnvshmem_device']
```

`-dlink` 标志告诉 nvcc 执行设备端链接（Device Link）步骤。

## 3. pybind11 绑定（`csrc/deep_ep.cpp`）

### 3.1 Python 模块结构

```cpp
PYBIND11_MODULE(TORCH_EXTENSION_NAME, m) {
    // Config 类绑定
    py::class_<Config>(m, "Config")
        .def(py::init<int, int, int, int, int>())  // (num_sms, nvl_send, nvl_recv, rdma_send, rdma_recv)
        .def("get_nvl_buffer_size_hint", &Config::get_nvl_buffer_size_hint)
        .def("get_rdma_buffer_size_hint", &Config::get_rdma_buffer_size_hint);

    // EventHandle 类绑定
    py::class_<EventHandle>(m, "EventHandle")
        .def(py::init<>())
        .def("current_stream_wait", &EventHandle::current_stream_wait);

    // Buffer 类绑定（主体）
    py::class_<Buffer>(m, "Buffer")
        .def(py::init<int, int, int64_t, int64_t, bool, bool, bool, bool>())
        .def("get_dispatch_layout", ...)
        .def("intranode_dispatch", ...)
        .def("intranode_combine", ...)
        .def("internode_dispatch", ...)
        .def("internode_combine", ...)
        .def("low_latency_dispatch", ...)
        .def("low_latency_combine", ...)
        // ...
    
    // 全局函数
    m.def("get_low_latency_rdma_size_hint", &get_low_latency_rdma_size_hint);
    m.def("is_sm90_compiled", []() -> bool {
#ifndef DISABLE_SM90_FEATURES
        return true;
#else
        return false;
#endif
    });
}
```

### 3.2 张量类型处理

Python 侧传入 `torch.Tensor`，C++ 侧接收 `torch::Tensor`，内部取出原始指针：

```cpp
// BF16 张量
auto x_ptr = reinterpret_cast<const void*>(x.data_ptr());

// FP8 张量（x_scales 为可选）
const std::optional<torch::Tensor>& x_scales_opt = ...;
float* x_scales = x_scales_opt.has_value() ? x_scales_opt->data_ptr<float>() : nullptr;

// 对于 FP8 dispatch，Python 侧传入 tuple(fp8_tensor, scale_tensor)
# Python:
x, x_scales = x if isinstance(x, tuple) else (x, None)
```

### 3.3 Callable Hook 绑定

低延迟内核返回 `std::function<void()>` 作为接收 hook：

```cpp
// C++ 侧
std::optional<std::function<void()>> hook;
// 如果 return_recv_hook=True，构造 hook 并返回
hook = [stream, event]() {
    event.current_stream_wait();
};

// pybind11 自动将 std::function<void()> 转为 Python callable
```

## 4. Kernel 启动基础设施（`launch.cuh`）

### 4.1 SM90 Cooperative Launch（集群启动）

```cpp
#ifndef DISABLE_SM90_FEATURES
#define SETUP_LAUNCH_CONFIG(num_sms, num_threads, stream)           \
    cudaLaunchConfig_t cfg = {num_sms, num_threads, 0, stream, ...}; \
    cudaLaunchAttribute attr[2];                                    \
    attr[0].id = cudaLaunchAttributeCooperative;                    \
    attr[0].val.cooperative = 1;    /* 允许 grid.sync() */          \
    attr[1].id = cudaLaunchAttributeClusterDimension;               \
    attr[1].val.clusterDim.x = (num_sms % 2 == 0 ? 2 : 1); /* 2 SM/cluster */
```

`cudaLaunchAttributeCooperative` 允许 kernel 内部使用 `cg::this_grid().sync()` 进行全 grid 同步，LL dispatch kernel 在发送阶段和接收阶段之间用此进行同步。

### 4.2 SWITCH_RANKS 宏：编译期模板路由

由于 `kNumRanks` 是 kernel 模板参数，必须在编译期确定：

```cpp
#define SWITCH_RANKS(case_macro)      \
    switch (num_ranks) {              \
        case 2:  case_macro(2); break; \
        case 4:  case_macro(4); break; \
        case 8:  case_macro(8); break; \
        default: EP_HOST_ASSERT(false and "Unsupported ranks"); \
    }
```

调用时：
```cpp
#define DISPATCH_LAUNCH_CASE(ranks) \
    LAUNCH_KERNEL(&cfg, dispatch<ranks, 768, 8192>, ...)  \
    break

SWITCH_RANKS(DISPATCH_LAUNCH_CASE);
```

类似地，`SWITCH_RDMA_RANKS` 支持 2/3/4/6/8/12/16/18/20 个 RDMA rank，`SWITCH_HIDDEN` 支持 2048/2560/3072/4096/5120/6144/7168/8192 的隐藏维度。

## 5. 核心 PTX 技巧详解（`utils.cuh`）

### 5.1 ld_nc_global 的"未定义行为"优化

```cpp
#ifndef DISABLE_AGGRESSIVE_PTX_INSTRS
#define LD_NC_FUNC "ld.global.nc.L1::no_allocate.L2::256B"
#else
#define LD_NC_FUNC "ld.volatile.global"
#endif

template <> __device__ int4 ld_nc_global(const int4* ptr) {
    int4 ret;
    asm volatile(LD_NC_FUNC ".v4.s32 {%0,%1,%2,%3}, [%4];"
                 : "=r"(ret.x), "=r"(ret.y), "=r"(ret.z), "=r"(ret.w)
                 : "l"(ptr));
    return ret;
}
```

**为什么这是"未定义行为"**：
- `.nc`（non-coherent）修饰符表示使用非一致性缓存读取，理论上不保证读到最新数据
- DeepEP 将其与 `.L1::no_allocate` 结合使用
- 在 Hopper 架构上，非一致性缓存与 L1 是统一的，`.L1::no_allocate` 的强制语义保证了正确性
- 相比 `ld.volatile`，这种写法触发了额外的编译器优化（自动展开等），性能显著更好

### 5.2 内存序语义

```cpp
// GPU scope 原子操作（节点内通信）
__device__ int ld_acquire_global(const int* ptr)  // 带 acquire 语义的 GPU-scope 读
__device__ int ld_acquire_sys_global(const int* ptr) // 带 acquire 语义的 system-scope 读
__device__ void st_release_sys_global(const int* ptr, int val)  // 带 release 语义的写

// CTA scope（块内同步）
__device__ void st_release_cta(const int* ptr, int val)
```

正确使用 acquire/release 语义是保证通信正确性的关键：
- `tail` 更新：使用 `st_release`，确保数据写入对接收方可见后才推进 tail
- `tail` 读取：使用 `ld_acquire`，确保读到 tail 后数据已经对本地可见

### 5.3 FP8 量化工具

```cpp
__forceinline__ __device__ void calculate_fp8_scales(
    float amax, float& scale, float& scale_inv, bool round_scale) {
    if (round_scale) {
        // 将缩放因子舍入为 2 的幂次（UE8M0 格式）
        auto exp = fast_log2_ceil(amax * kFinfoAmaxInvE4M3);  // = log2(amax/448)
        scale = fast_pow2(-exp);      // = 2^(-exp)
        scale_inv = fast_pow2(exp);   // = 2^(exp) = 448/amax
    } else {
        scale_inv = amax * (1.0/448.0f);  // 标准 FP8 E4M3 amax
        scale = 448.0f / amax;
    }
}

// 快速 2 的幂次操作（避免浮点乘除）
__device__ float fast_pow2(int x) {
    uint32_t bits = (x + 127) << 23;  // IEEE 754 指数偏置
    return *reinterpret_cast<float*>(&bits);
}
```

    └── from deep_ep.buffer import Buffer
