## 1. 项目定位

verl（Volcano Engine Reinforcement Learning）是字节跳动火山引擎开源的**大语言模型强化学习训练框架**，专为 RLHF（基于人类反馈的强化学习）及 GRPO、PPO、REINFORCE++ 等算法设计，支持从单机多卡到千卡集群的弹性扩展。

核心设计目标：

| 目标 | 说明 |
|------|------|
| **算法与系统解耦** | 优势计算、损失函数等算法逻辑在 Driver 进程单机执行；前向/后向/推理封装在 Worker 内，通过 Ray RPC 调用 |
| **多后端统一接口** | 训练侧支持 FSDP2 / Megatron-LM / MindSpeed；推理侧支持 vLLM / SGLang / TRT-LLM，通过统一 Engine / Rollout 接口互换 |
| **单控制器多 Worker** | Driver 是唯一控制流，Worker 只暴露"远程可调用方法"，无需在 Worker 内写控制逻辑 |
| **Hybrid Engine** | Actor 训练与 Rollout 推理共享同一组 GPU，通过 ShardingManager 动态切换，避免为推理单独分配资源 |

## 4. Ray 分布式调度与通信机制

### 4.1 Worker 是如何被调度到 GPU 的

> 源码：`verl/single_controller/ray/base.py:112` `RayResourcePool`  
> 源码：`verl/single_controller/ray/base.py:182` `ResourcePoolManager`  
> 源码：`verl/single_controller/ray/base.py:412` `RayWorkerGroup`

```
ResourcePoolManager
  └─ RayResourcePool(process_on_nodes=[8, 8])   # 2 节点，每节点 8 GPU
       └─ PlacementGroup × 2（STRICT_PACK）
            每个 PG 内 8 个 bundle，每 bundle = {CPU: 10, GPU: 1}

init_workers() 时：
  for i in range(world_size):                    # world_size = 16
      Worker_i = ActorRolloutRefWorker.options(
          scheduling_strategy=PlacementGroupSchedulingStrategy(
              placement_group=pg[node_idx],
              bundle_index=gpu_idx_within_node
          ),
          num_gpus=1
      ).remote(config, role="actor_rollout")
```

- **一个 Worker = 一个 GPU 上的 Ray Actor 进程**，持有模型参数的一个 shard
- 节点内用 `STRICT_PACK` 策略，保证同一节点的 Worker 落在同一 PG，支持 NVLink 通信
- 各 Worker 启动后通过 `MASTER_ADDR/MASTER_PORT` 完成 `torch.distributed.init_process_group`，之后 Worker 间可用 NCCL 直接通信（all-reduce / all-gather 等）

```
节点 0                         节点 1
┌────────────────────────┐    ┌────────────────────────┐
│ GPU0  GPU1  GPU2  GPU3 │    │ GPU4  GPU5  GPU6  GPU7 │
│  W0    W1    W2    W3  │    │  W4    W5    W6    W7  │
│       ← NVLink →       │    │       ← NVLink →       │
└──────────┬─────────────┘    └────────────┬───────────┘
           └──────── InfiniBand/RoCE ───────┘
                      ▲
              Driver (Ray RPC / Object Store)
```

### 4.2 Driver → WorkerGroup RPC 调用机制

verl 的核心抽象是 **`@register` 装饰器 + `RayWorkerGroup`**，将"在所有 Worker 上调用同一方法"简化为一行函数调用。

> 源码：`verl/single_controller/base/decorator.py:398` `@register` 装饰器  
> 源码：`verl/single_controller/base/decorator.py:26` `Dispatch` 枚举  
> 源码：`verl/single_controller/base/decorator.py:167` `dispatch_dp_compute_data_proto()`  
> 源码：`verl/single_controller/ray/base.py:48` `func_generator()`（RPC 执行引擎）  
> 源码：`verl/single_controller/ray/base.py:834` `execute_all()`

#### 调用链路

```
Driver:  actor_rollout_wg.update_actor(batch)
             │
             ▼
  func_generator 生成的 Functor.__call__()        # ray/base.py:48
     ├─ 1. dispatch_fn(worker_group, batch)        # decorator.py:167 按 DP 切分
     ├─ 2. execute_fn("update_actor", *shards)     # ray/base.py:834 execute_all()
     │       └─ [W0.update_actor.remote(shard_0),
     │            W1.update_actor.remote(shard_1), ...]
     ├─ 3. ray.get([future_0, future_1, ...])  (blocking=True)
     └─ 4. collect_fn(outputs)                     # decorator.py:191 concat 回 DataProto
```

#### Dispatch 模式速查

| 模式 | 用于哪些方法 | Driver 行为 | 源码 |
|------|------------|------------|------|
| `ONE_TO_ALL` | `init_model`, 权重加载, rollout 配置 | 同一份数据广播给所有 Worker | `decorator.py:120` |
| `DP_COMPUTE_PROTO` | `compute_log_prob`, `compute_values` | DataProto 按 batch 维度平均切分，自动 padding | `decorator.py:167` |
| `nd_compute(mesh_name=)` | `update_actor`(actor), `generate_sequences`(rollout), `update_critic`(critic) | 按 mesh DP 维度切分，支持 TP/PP 内广播 | `decorator.py:250` |
| `ALL_TO_ALL` | 内部低层调用 | 数据已预先切分，直接下发 | `decorator.py:130` |

Worker 方法上的 dispatch 标注示例（`fsdp_workers.py`）：
```python
@register(dispatch_mode=Dispatch.ONE_TO_ALL)                              # :887 init_model
@register(dispatch_mode=make_nd_compute_dataproto_dispatch_fn("actor"))   # :1027 update_actor
@register(dispatch_mode=make_nd_compute_dataproto_dispatch_fn("rollout")) # :1073 generate_sequences
@register(dispatch_mode=make_nd_compute_dataproto_dispatch_fn("actor"))   # :1123 compute_log_prob
@register(dispatch_mode=make_nd_compute_dataproto_dispatch_fn("critic"))  # :1676 compute_values
@register(dispatch_mode=make_nd_compute_dataproto_dispatch_fn("critic"))  # :1696 update_critic
```

#### 具体示例：4 GPU，DP=4，batch_size=16

```
Driver DataProto [B=16]
    │  dispatch_dp_compute_data_proto → chunk(4)
    ├── shard[0] [B=4] → W0.compute_log_prob.remote(shard_0)
    ├── shard[1] [B=4] → W1.compute_log_prob.remote(shard_1)
    ├── shard[2] [B=4] → W2.compute_log_prob.remote(shard_2)
    └── shard[3] [B=4] → W3.compute_log_prob.remote(shard_3)
                                │
                         ray.get([f0,f1,f2,f3])
                                │
                    collect: concat([out0,out1,out2,out3])
                                │
                         DataProto [B=16]  ← 返回给 Driver
```

### 4.3 Worker 内部通信（NCCL）

> 源码：`verl/workers/fsdp_workers.py:147` `ActorRolloutRefWorker`（FSDP 训练+推理合体）  
> 源码：`verl/workers/actor/dp_actor.py` `DataParallelPPOActor`（FSDP Actor 算法逻辑）  
> 源码：`verl/workers/critic/dp_critic.py` `DataParallelPPOCritic`（FSDP Critic 算法逻辑）

Worker 内部不经过 Ray，直接走 torch.distributed / NCCL：

```
Worker 层（NCCL 通信）：

ActorRolloutRefWorker (FSDP)
  ├─ forward()         → all-reduce 梯度（跨所有 DP rank）
  ├─ all-gather param  → FSDP 在前向时拼完整参数
  └─ compute_log_prob  → 各 rank 独立计算，无需通信

ShardingManager（权重同步，训练→推理）
  └─ all_gather(fsdp_shards) →  complete weights
       └─ inject into vLLM/SGLang engine（同进程内内存拷贝）
```

### 4.4 Hybrid Engine：同 GPU 上训练与推理的切换

> 源码：`verl/workers/fsdp_workers.py:759` `rollout_mode()` async context manager  
> 源码：`verl/workers/fsdp_workers.py:888` `init_model()`（初始化 FSDP + Rollout 双引擎）  
> 源码：`verl/workers/sharding_manager/base.py:21` `BaseShardingManager.__enter__/__exit__`  
> 源码：`verl/workers/rollout/vllm_rollout/vllm_rollout.py` `VLLMRollout`  
> 源码：`verl/workers/rollout/sglang_rollout/sglang_rollout.py` `SGLangRollout`

```
同一个 ActorRolloutRefWorker 进程内：

  rollout 阶段                    train 阶段
  ┌─────────────────────┐         ┌─────────────────────┐
  │ vLLM/SGLang Engine  │         │  FSDP Actor Model   │
  │  (完整参数，推理)    │         │  (sharded，训练)    │
  └──────────┬──────────┘         └──────────┬──────────┘
             │                               │
             │ ← ShardingManager.__exit__()  │
             │    释放推理引擎内存            │
             │                               │
             │ → ShardingManager.__enter__() │
             │    all-gather → 注入推理引擎  │
             └───────────────────────────────┘
                        ↕ async_rollout_manager 调度
```

**时序**：每个 global step 内，`generate_sequences` 阶段激活推理引擎；`update_actor` 阶段激活 FSDP 训练；两阶段通过 `checkpoint_manager.sleep_replicas()` / `update_weights()` 切换。

## 5. 一批样本的完整数据流

以 **batch_size=4 个 prompt，rollout.n=2（每条生成 2 条回复），DP=2 个 GPU** 为例：

    │
    │  dispatch_fn (rollout mesh, DP=2):
    │    shard_0 = [p0,p0, p1,p1]  → W0 (vLLM/SGLang)

### 阶段 ⑤⑥：Value & Advantage（Driver 本地）

> 源码：`verl/workers/fsdp_workers.py:1678` `CriticWorker.compute_values()`  
> 源码：`verl/workers/critic/dp_critic.py` `DataParallelPPOCritic.compute_values()`

```
⑤ CriticWorker.compute_values(batch)   # 仅 PPO
    │  DP split → Critic 前向 → concat
    │  输出: values [B=8, seq_len]
    ▼
⑥ compute_advantage(batch)             # 完全在 Driver CPU 上执行
    │
    │  GRPO 模式：
    │    按 uid 分组（每组 2 条）
    │    group_rewards = [r(p0r0a), r(p0r0b)]
    │    advantage = (r - mean(group)) / std(group)
    │    → advantages [B=8]
    │
    │  PPO/GAE 模式：
    │    advantage[t] = delta[t] + γλ·advantage[t+1]
    │    returns[t] = advantage[t] + values[t]
    ▼
batch 新增: advantages [B=8], returns [B=8]
```

> 源码：`verl/checkpoint_engine/nixl_checkpoint_engine.py` `NixlCheckpointEngine`

```
⑨ checkpoint_manager.update_weights(global_step)
    │
    │  对每个 ActorRolloutRefWorker：
    │    ShardingManager.__enter__()
    │      1. fsdp.all_gather()  → 在 GPU 上拼出完整参数
    │      2. 将完整参数 assign 到 vLLM/SGLang model weights
    │    ShardingManager.__exit__()
    │      3. 释放 all-gather buffer，回到 FSDP shard 状态
    ▼
下一 step 的 generate_sequences 使用更新后的权重
```
