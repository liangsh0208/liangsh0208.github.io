# Slime 调度与资源管理模块实现原理与性能优化

> **【源码定位】** `slime/ray/placement_group.py`, `slime/ray/rollout.py`, `slime/ray/rollout.py:RolloutManager`  
> **【阅读建议】** 需理解 Ray Actor、Placement Group 资源调度机制  
> **【前置知识】** Ray 分布式基础、GPU 拓扑、SGLang 引擎架构

## 1. 模块概述

调度与资源管理模块是 Slime 分布式训练框架的**协调中心**，负责任务调度、GPU 资源分配、Rollout 与 Training 的交替控制以及系统健康监控。该模块基于 **Ray 分布式框架** 构建，通过 **Placement Group** 实现 GPU 拓扑优化，通过 **Actor 模型** 实现任务的异步调度。

**关键设计决策【重点】**：
1. **拓扑感知分配**：Placement Group 确保 Actor/Critic/Rollout 的 GPU 按物理拓扑分配
2. **Weight Streaming**：训练后立即同步权重到 SGLang，无需重启引擎
3. **内存复用**：Colocate 模式通过 Offload/Onload 在训练和推理间切换显存
4. **健康监控**：自动检测 SGLang 引擎死亡并重启，保证训练不中断

## 3. Placement Group GPU 资源管理

### 3.1 Placement Group 创建流程

```python
def create_placement_groups(args):
    """创建 Placement Group，实现 GPU 资源的拓扑优化

    流程：
    1. 计算所需 GPU 总数
    2. 创建 Placement Group（PACK 策略）
    3. 排序 bundle 确保确定性分布
    4. 返回逻辑 -> 物理的映射关系
    """
    # 计算总 GPU 数量
    num_gpus = 0
    if args.colocate:
        # Actor 和 Rollout 共享 GPU
        num_gpus = args.actor_num_nodes * args.actor_num_gpus_per_node
    else:
        # 分离部署
        num_gpus = (args.actor_num_nodes * args.actor_num_gpus_per_node +
                    args.rollout_num_gpus)

    # 创建 Placement Group
    bundles = [{"GPU": 1, "CPU": 1} for _ in range(num_gpus)]
    pg = placement_group(bundles, strategy="PACK")  # PACK 策略：尽可能紧凑
    ray.get(pg.ready())

    # 获取实际 GPU 分配信息
    gpu_ids = ray.get([actor.get_ip_and_gpu_id.remote() for actor in info_actors])

    # 按 (node_ip, gpu_id) 排序，确保确定性
    sorted_bundle_infos = sorted(bundle_infos, key=sort_key)

    return {
        "actor": (pg, actor_bundle_indices, actor_gpu_ids),
        "rollout": (pg, rollout_bundle_indices, rollout_gpu_ids),
        "critic": (pg, critic_bundle_indices, critic_gpu_ids),
    }
```

### 3.2 GPU 排序策略

```python
def sort_key(x):
    """GPU 排序键，确保跨节点部署的确定性

    排序优先级：
    1. 节点 IP 地址（数值比较）
    2. GPU ID（同一节点内）
    """
    index, node_identifier, gpu_id = x

    # 尝试解析为 IP 地址
    try:
        ip_address = node_identifier
        node_ip_parts = list(map(int, ip_address.split(".")))
    except ValueError:
        # 尝试 DNS 解析
        try:
            ip_address = socket.gethostbyname(node_identifier)
            node_ip_parts = list(map(int, ip_address.split(".")))
        except socket.gaierror:
            # 使用字符串 ASCII 值
            node_ip_parts = [ord(c) for c in node_identifier]

    return (node_ip_parts, gpu_id)
```

## 4. Rollout Manager 调度

### 4.1 RolloutManager 职责

```python
@ray.remote(num_cpus=1, num_gpus=0)
class RolloutManager:
    """Rollout 数据生成的协调中心

    职责：
    1. 管理 SGLang 推理引擎生命周期
    2. 协调多引擎的负载均衡
    3. 分发 Rollout 数据到各训练进程
    4. 执行评估和健康检查
    """

    def generate(self, rollout_id):
        """生成 Rollout 数据

        流程：
        1. 从数据源获取 prompt
        2. 分发到各 SGLang 引擎并行推理
        3. 收集结果并计算奖励
        4. 分区数据到各 DP rank
        """
        # 并行推理
        futures = [
            engine.generate.remote(prompts[i], ...)
            for i, engine in enumerate(self.engines)
        ]
        results = ray.get(futures)

        # 数据分区
        partitioned_data = self._partition_data(results, dp_size)

        return partitioned_data

    def update_weights(self):
        """同步训练权重到推理引擎"""
        actor_weights = ray.get(self.actor_model.get_weights.remote())
        for engine in self.engines:
            engine.update_weights.remote(actor_weights)
```

### 4.2 ServerGroup 引擎管理

```python
@dataclasses.dataclass
class ServerGroup:
    """一组同构的 SGLang 引擎

    属性：
    - engines: 引擎 Actor 列表
    - tp_size: 张量并行度
    - nodes_per_engine: 每引擎节点数
    - pg: 绑定的 Placement Group
    """

    def __init__(self, config: ServerGroupConfig, pg):
        # 创建引擎
        for engine_id in range(num_engines):
            # 每个 engine 可能跨多个节点 (tp_size > 单节点 GPU 数)
            for node_id in range(nodes_per_engine):
                bundle_index = base_bundle_index + node_id
                engine_actor = SGLangEngine.options(
                    scheduling_strategy=PlacementGroupSchedulingStrategy(
                        placement_group=pg,
                        placement_group_bundle_index=bundle_index,
                    )
                ).remote(config, engine_id, node_id)

                self.all_engines.append(engine_actor)
```

## 5. Rollout-Training 交替调度

### 5.1 同步训练流程

```python
def train(args):
    """同步训练主循环

    特点：
    - Rollout 和 Training 串行执行
    - 每个 rollout_id 依次生成数据、训练、更新权重
    - 适合调试和资源受限场景
    """
    # 初始化
    pgs = create_placement_groups(args)
    rollout_manager = create_rollout_manager(args, pgs["rollout"])
    actor_model, critic_model = create_training_models(args, pgs, rollout_manager)

    # 训练循环
    for rollout_id in range(args.num_rollout):
        # 1. 生成 Rollout 数据（阻塞）
        rollout_data_ref = ray.get(rollout_manager.generate.remote(rollout_id))

        # 2. 训练 Critic（如果启用）
        if args.use_critic:
            ray.get(critic_model.async_train(rollout_id, rollout_data_ref))

        # 3. 训练 Actor
        ray.get(actor_model.async_train(rollout_id, rollout_data_ref))

        # 4. 同步权重到 Rollout 引擎
        actor_model.update_weights()

        # 5. 保存 Checkpoint
        if should_save(rollout_id):
            actor_model.save_model(rollout_id)
```

### 5.2 异步训练流程

```python
def train_async(args):
    """异步训练主循环

    特点：
    - Rollout 和 Training 可并行执行
    - 使用流水线模式提高 GPU 利用率
    - 适合大规模训练场景
    """
    # 初始化...

    # 流水线训练
    train_handle = None
    for rollout_id in range(args.num_rollout):
        # 1. 异步生成 Rollout 数据
        generate_handle = rollout_manager.generate.remote(rollout_id)

        # 2. 等待上一轮训练完成
        if train_handle is not None:
            ray.get(train_handle)

        # 3. 获取 Rollout 数据
        rollout_data_ref = ray.get(generate_handle)

        # 4. 异步启动训练
        train_handle = actor_model.async_train.remote(rollout_id, rollout_data_ref)

    # 等待最后一轮训练完成
    ray.get(train_handle)
```

### 5.3 Offload 调度策略

```python
def offload_train(rollout_id):
    """GPU Offload 策略

    场景：Actor 和 Rollout 共享 GPU (colocate)
    策略：训练时 offload Rollout，推理时 onload Rollout
    """
    if args.offload_train:
        # 训练阶段：offload Actor 模型
        actor_model.offload()
    else:
        # 仅清理显存（不 offload 到 CPU）
        actor_model.clear_memory()

# 训练循环中的调度
for rollout_id in range(args.num_rollout):
    # 生成阶段
    rollout_data = rollout_manager.generate(rollout_id)

    if args.offload_rollout:
        # Offload Rollout 引擎
        rollout_manager.offload()

    # 训练阶段
    actor_model.train(rollout_data)
    offload_train(rollout_id)

    if args.offload_rollout:
        # Onload Rollout 引擎
        rollout_manager.onload_weights()
        rollout_manager.onload_kv()

    # 权重同步
    actor_model.update_weights()
```

## 6. 健康监控与容错

### 6.1 RolloutHealthMonitor 设计

```python
class RolloutHealthMonitor:
    """Rolout 引擎健康监控器

    功能：
    1. 周期性健康检查（轻量级推理）
    2. 检测无响应或异常引擎
    3. 自动熔断并重建故障引擎

    生命周期：
    - start(): 启动监控线程
    - pause(): 暂停检查（offload 时）
    - resume(): 恢复检查（onload 时）
    - stop(): 停止监控
    """

    def __init__(self, server_group, args):
        self._check_interval = args.rollout_health_check_interval
        self._check_timeout = args.rollout_health_check_timeout
        self._check_first_wait = args.rollout_health_check_first_wait

    def _health_monitor_loop(self):
        """健康检查主循环"""
        while not self._stop_event.is_set():
            # 等待暂停解除
            while self._pause_event.is_set() and not self._stop_event.is_set():
                self._stop_event.wait(timeout=0.5)

            # 首次等待（大 MoE 模型预热）
            if self._need_first_wait:
                self._stop_event.wait(self._check_first_wait)
                self._need_first_wait = False

            # 执行健康检查
            if not self._pause_event.is_set():
                self._run_health_checks()

            # 等待下次检查
            self._stop_event.wait(self._check_interval)

    def _check_engine_health(self, rollout_engine_id, engine):
        """检查单个引擎健康状态"""
        try:
            # 轻量级推理测试
            ray.get(engine.health_generate.remote(timeout=self._check_timeout))
        except Exception as e:
            logger.error(f"Health check failed for engine {rollout_engine_id}")
            self._kill_engine(rollout_engine_id)

    def _kill_engine(self, rollout_engine_id):
        """熔断并移除故障引擎"""
        logger.info(f"Killing engine {rollout_engine_id}...")
        engine = self._server_group.engines[rollout_engine_id]
        try:
            ray.get(engine.shutdown.remote())  # 优雅关闭
            ray.kill(engine)                    # 强制终止
        except Exception as e:
            logger.warning(f"Failed to kill engine: {e}")
        self._server_group.engines[rollout_engine_id] = None
```

## 7. 异步执行与并发控制

### 7.1 AsyncLoopThread 设计

```python
class AsyncLoopThread:
    """后台异步事件循环线程

    用途：在同步主流程中调用异步函数
    场景：HTTP 请求、异步 I/O 等

    原理：
    1. 创建独立线程运行 asyncio 事件循环
    2. 通过 run_coroutine_threadsafe 提交协程
    3. 阻塞等待结果返回
    """

    def __init__(self):
        self._loop = asyncio.new_event_loop()
        self._thread = threading.Thread(
            target=self._loop.run_forever,
            daemon=True
        )
        self._thread.start()

    def run(self, coro):
        """运行协程并返回结果"""
        future = asyncio.run_coroutine_threadsafe(coro, self._loop)
        return future.result()

# 使用示例
async_loop = AsyncLoopThread()

def sync_http_request(url):
    """在同步函数中调用异步 HTTP 请求"""
    return async_loop.run(async_http_get(url))
```

### 8.4 常见问题与解决方案

#### 问题1：GPU 分配不均匀
```
现象：部分 GPU 显存满载，其他空闲
原因：Placement Group 排序不稳定
解决：确保节点 IP 可解析，检查 sort_key 逻辑
```

#### 问题2：健康检查误报
```
现象：引擎被频繁 kill
原因：健康检查超时设置过短
解决：调大 --rollout-health-check-timeout
      增加 --rollout-health-check-first-wait（MoE 模型）
```

#### 问题3：异步训练死锁
```
现象：训练卡住不前进
原因：ray.get() 嵌套调用导致死锁
解决：检查异步调用链，避免循环依赖
```

## 10. 调度配置实战速查

### 10.1 部署模式配置对比

| 模式 | GPU 分配 | 配置参数 | 适用场景 | 优缺点 |
|------|---------|---------|---------|--------|
| **Separated** (分离) | Actor: 16, Rollout: 16 | 默认配置 | 资源充足，低延迟 | 独立优化，占用 GPU 多 |
| **Colocate** (共享) | Actor: 16 (Rollout 复用) | `--colocate` | 资源受限 | 省 GPU，需频繁 Offload |
| **Fully Async** (全异步) | Actor: 16, Rollout: 16 | `train_async.py` | 吞吐优先 | Pipeline 并行训练/推理 |

### 10.2 常见 Placement 配置

```bash
# 4 节点，每节点 8 GPU，分离部署
--actor-num-nodes 2 \
--actor-num-gpus-per-node 8 \
--rollout-num-gpus 16 \
--rollout-num-gpus-per-engine 4 \
--rollout-tp-size 4
# Result: 节点 1-2 给 Actor, 节点 3-4 给 Rollout

# 4 节点，Colocate 共享
--colocate \
--actor-num-nodes 4 \
--actor-num-gpus-per-node 8 \
--offload-train \
--offload-rollout
# Result: 所有节点均运行 Actor+Rollout，时间片轮转

# 多机多卡 Critic 分离
--use-critic \
--actor-num-nodes 2 \
--actor-num-gpus-per-node 8 \
--critic-num-nodes 1 \
--critic-num-gpus-per-node 8 \
--rollout-num-gpus 16
```

### 10.3 SGLang 引擎调优参数

```bash
# 高吞吐配置
--sglang-max-num-seqs 1024 \
--sglang-schedule-policy fcfs \
--sglang-chunked-prefill-size 2048

# 低延迟配置
--sglang-max-num-seqs 64 \
--sglang-schedule-policy srpt  # 最短剩余时间优先
--sglang-enable-pd-disaggregation  # PD 分离
```
