> **【阅读建议】** 配合 00_整体架构概览.md → 3.2 数据模块  一起阅读

## 1. 模块概述

数据模块是 Slime 训练框架的基础组件，负责**数据的加载、预处理、Rollout 生成以及训练数据的组织**。该模块采用**生产者-消费者模式**，将数据生成（Rollout）与模型训练解耦，支持大规模分布式训练场景。

**关键设计决策【重点】**：
1. **Sample 统一抽象**：`Sample` 类型贯穿全流程，包含 prompt、multimodal_inputs、metadata、tokens、rewards 等字段
2. **Lazy Loading**：使用生成器模式，避免大数据集内存爆炸
3. **动态批次**：根据序列长度动态调整微批次大小，最大化 GPU 利用率
4. **负载均衡**：DP 组内自动均衡样本分配，结合 Flash Attention 的 THD 格式避免填充浪费

### 2.2 Dataset 类实现

```python
class Dataset:
    def __init__(
        self,
        path,                    # 数据文件路径
        tokenizer,               # HuggingFace tokenizer
        processor,               # 多模态 processor（可选）
        max_length,              # 最大长度限制
        *,
        prompt_key="text",       # prompt 字段名
        multimodal_keys=None,    # 多模态字段映射
        apply_chat_template=False,  # 是否应用聊天模板
    ):
        # 1. 使用生成器逐行读取数据
        for data in read_file(path):
            # 2. 构建消息格式
            prompt = _build_messages(data, prompt_key, ...)

            # 3. 应用聊天模板
            if apply_chat_template:
                output_prompt = tokenizer.apply_chat_template(
                    prompt, tokenize=False, add_generation_prompt=True
                )

            # 4. 处理多模态输入
            if processor:
                multimodal_inputs = process_vision_info(prompt, processor)

            # 5. 创建样本对象
            origin_samples.append(Sample(
                prompt=output_prompt,
                metadata=metadata,
                multimodal_inputs=multimodal_inputs,
            ))

        # 6. 过滤过长样本
        self.origin_samples = filter_long_prompt(origin_samples, tokenizer, processor, max_length)
```

**关键设计点**：
- **生成器模式**：避免一次性加载到内存，支持大数据集
- **惰性处理**：多模态数据按需处理，减少初始化开销
- **确定性洗牌**：使用 seed + epoch_id 确保可复现

### 3.2 Rollout 类型总览

Slime 的 `slime/rollout/` 目录包含多种 Rollout 实现，每种对应不同的训练场景：

| 文件 | 类型 | 适用场景 | 核心差异 |
|------|------|---------|---------|
| `sglang_rollout.py` | **默认 Rollout** | 通用 RL 训练（PPO/GRPO/DPO） | 调用 SGLang 引擎在线生成 response，计算 log_probs、rewards |
| `sft_rollout.py` | **SFT Rollout** | 监督微调 | 不调用推理引擎，直接从数据集中的 response 构建 loss_mask |
| `on_policy_distillation.py` | **OPD Rollout** | 在线策略蒸馏 | 使用教师模型（SGLang Engine）计算 log_probs 作为蒸馏目标，reward 通常为 0 |
| `sleep_rollout.py` | **Sleep Rollout** | 调试/基准测试 | 不实际调用引擎，直接返回预定义数据，用于验证训练逻辑 |

### 3.3 SFT Rollout 实现（示例）

`slime/rollout/sft_rollout.py` 提供了一个基于规则的 Rollout 实现：

```python
def generate_rollout(args, rollout_id, data_buffer, evaluation=False):
    """基于 SFT 数据的 Rollout 生成（不使用模型推理）"""

    # 全局缓存 tokenizer/processor（避免重复加载）
    global TOKENIZER, PROCESSOR, MASK_GENERATOR
    if TOKENIZER is None:
        TOKENIZER = load_tokenizer(args.hf_checkpoint)
        MASK_GENERATOR = MultiTurnLossMaskGenerator(TOKENIZER)

    # 从数据缓冲区获取样本
    samples = data_buffer.get_samples(args.rollout_batch_size)

    for sample in samples:
        messages = sample.prompt
        tools = sample.metadata.get("tools", None)

        # 计算 loss mask（确定哪些 token 计算损失）
        token_ids, loss_mask = MASK_GENERATOR.get_loss_mask(messages, tools=tools)
        response_length = MASK_GENERATOR.get_response_lengths([loss_mask])[0]

        # 填充样本数据
        sample.tokens = token_ids
        sample.response_length = response_length
        sample.reward = 0
        sample.loss_mask = loss_mask[-response_length:]  # 仅保留 response 部分

    return samples
```

**Loss Mask 计算原理**：
```
输入消息格式：
[
  {"role": "user", "content": "问题"},
  {"role": "assistant", "content": "回答1"},
  {"role": "user", "content": "追问"},
  {"role": "assistant", "content": "回答2"}
]

Loss Mask 生成：
- user token: mask = 0 (不计算损失)
- assistant token: mask = 1 (计算损失)
```

## 4. 训练数据组织

### 4.1 DataIterator 设计

```python
class DataIterator:
    """微批次迭代器，支持固定大小和动态调度两种模式"""

    def __init__(
        self,
        rollout_data,           # Rollout 数据字典
        micro_batch_size=None,  # 固定微批次大小
        micro_batch_indices=None,  # 动态调度的索引列表
    ):
        self.rollout_data = rollout_data
        self.micro_batch_size = micro_batch_size
        self.micro_batch_indices = micro_batch_indices
        self.offset = 0

    def get_next(self, keys):
        """获取下一个微批次数据"""
        batch = {}
        for key in keys:
            vals = self.rollout_data.get(key, None)
            if self.micro_batch_indices is not None:
                # 动态调度：按索引选择样本
                indices = self.micro_batch_indices[self.offset]
                batch[key] = [vals[i] for i in indices]
            else:
                # 固定大小：连续切片
                batch[key] = vals[self.offset : self.offset + self.micro_batch_size]
        return batch
```

### 4.2 动态批次大小优化

**问题**：变长序列导致 GPU 显存利用率不均衡，造成气泡（bubble）

**解决方案**：基于序列长度的负载均衡

```python
def get_data_iterator(args, model, rollout_data):
    """创建数据迭代器，支持动态批次大小"""

    if not args.use_dynamic_batch_size:
        # 固定批次大小模式
        num_microbatches = [num_local_gbs // args.micro_batch_size]
        data_iterator = DataIterator(rollout_data, args.micro_batch_size)
    else:
        # 动态批次大小模式
        # 1. 计算每个 step 需要的微批次数量
        num_microbatches = []
        for samples in rollout_steps:
            num_mbs = get_minimum_num_micro_batch_size(
                samples, args.max_tokens_per_gpu * cp_size
            )
            num_microbatches.append(num_mbs)

        # 2. AllReduce 取最大值，确保所有 DP rank 同步
        dist.all_reduce(num_microbatches, op=dist.ReduceOp.MAX)

        # 3. 按序列长度均衡分配样本到各微批次
        micro_batch_indices = []
        for step_samples, num_mbs in zip(rollout_steps, num_microbatches):
            partitions = get_seqlen_balanced_partitions(
                step_samples, num_mbs, equal_size=False
            )
            micro_batch_indices.extend(partitions)

        data_iterator = DataIterator(rollout_data, None, micro_batch_indices)

    return data_iterator, num_microbatches
```

**均衡算法**：First Fit Decreasing (FFD)
```python
def get_seqlen_balanced_partitions(samples, num_partitions, equal_size=False):
    """
    将样本分配到 num_partitions 个分区，使各分区的总 token 数尽可能均衡

    算法：贪心 + 优先队列
    1. 按长度降序排列样本
    2. 将每个样本分配到当前总长度最小的分区
    """
    samples_with_idx = sorted(enumerate(samples), key=lambda x: x[1], reverse=True)
    partition_sizes = [0] * num_partitions
    partitions = [[] for _ in range(num_partitions)]

    for idx, length in samples_with_idx:
        # 找到当前最小的分区
        min_partition = partition_sizes.index(min(partition_sizes))
        partitions[min_partition].append(idx)
        partition_sizes[min_partition] += length

    return partitions
```

## 5. Context Parallel 数据处理

### 5.1 CP 数据切片

Context Parallel 需要将序列切片分发到不同 rank：

```python
def get_batch(data_iterator, keys, pad_multiplier, qkv_format, allgather_cp):
    """生成 CP-ready 的微批次数据"""

    tokens = batch["tokens"]
    cp_size = mpu.get_context_parallel_world_size()
    cp_rank = mpu.get_context_parallel_rank()

    if allgather_cp:
        # DSA 模式：先拼接所有序列，再整体切片
        cu_seqlens = [0]
        for t in tokens:
            cu_seqlens.append(cu_seqlens[-1] + t.size(0))
        tokens = torch.cat(tokens, dim=0)

        # 全局填充，确保能均匀切分
        global_pad_size = cp_size * pad_multiplier
        pad = (global_pad_size - tokens.size(0) % global_pad_size) % global_pad_size
        tokens = F.pad(tokens, (0, pad), value=pad_token_id)

        # 按 CP rank 切片
        tokens = tokens.chunk(cp_size, dim=0)[cp_rank]
    else:
        # 标准模式：每个序列单独切片
        tokens = [slice_with_cp(t, pad_token_id, qkv_format) for t in tokens]
        tokens = torch.cat(tokens)

    # 构建 PackedSeqParams（用于 Flash Attention）
    packed_seq_params = PackedSeqParams(
        cu_seqlens_q=cu_seqlens * cp_size,  # 调整 cu_seqlens
        cu_seqlens_kv=cu_seqlens * cp_size,
        max_seqlen_q=max_seqlen,
        max_seqlen_kv=max_seqlen,
        qkv_format="thd",
    )

    return batch
```

### 5.2 THD 格式说明

THD（Time-Head-Dimension）是 Flash Attention 支持的变长序列格式：

```
传统格式（BSHD）：[Batch, SeqLen, Head, Dim]
├── Batch 维度固定
└── 每个样本独立存储

THD 格式：[TotalTokens, Head, Dim] + cu_seqlens
├── 所有样本拼接为一个张量
├── cu_seqlens 记录每个样本的边界
└── 适合变长序列的高效计算

示例：
样本1: [1, 2, 3]     (长度=3)
样本2: [4, 5]        (长度=2)
样本3: [6, 7, 8, 9]  (长度=4)

THD 拼接: [1, 2, 3, 4, 5, 6, 7, 8, 9]
cu_seqlens: [0, 3, 5, 9]  # 累积长度
```

### 6.2 全局统计量计算

PPO 训练需要对 advantages 进行全局归一化：

```python
def distributed_masked_whiten(values, mask, process_group=None, shift_mean=True):
    """
    使用全局统计量进行白化归一化

    1. 计算 local 统计量
    2. AllReduce 聚合全局统计量
    3. 使用全局统计量进行本地归一化
    """
    # 计算本地统计量
    local_sum = (values * mask).sum()
    local_sum_sq = ((values**2) * mask).sum()
    local_mask_sum = mask.sum()

    # 聚合全局统计量
    stats_tensor = torch.tensor([local_sum, local_sum_sq, local_mask_sum], device=values.device)
    dist.all_reduce(stats_tensor, group=process_group)

    # 计算全局均值和方差
    global_sum, global_sum_sq, global_mask_sum = stats_tensor
    global_mean = global_sum / global_mask_sum
    global_var = global_sum_sq / global_mask_sum - global_mean**2

    # Bessel 校正
    if global_mask_sum >= 2:
        global_var *= global_mask_sum / (global_mask_sum - 1)

    # 白化
    whitened = (values - global_mean) * torch.rsqrt(global_var + epsilon)
    return whitened
```

## 7. 性能优化注意事项

### 7.1 内存优化

| 优化策略 | 实现方式 | 效果 |
|---------|---------|------|
| 生成器读取 | `read_file()` 使用 `yield` | 避免全量加载，支持超大文件 |
| 惰性处理 | 多模态数据按需加载 | 减少初始化时间和内存占用 |
| 分区清理 | `clear_memory()` 显式回收 | 减少显存碎片 |
| 全局缓存 | tokenizer/processor 单例 | 避免重复加载 |

### 7.2 计算优化

| 优化策略 | 实现方式 | 效果 |
|---------|---------|------|
| 动态批次 | 按序列长度均衡分配 | 提高GPU利用率，减少气泡 |
| CP 数据填充 | 按 pad_multiplier 对齐 | 减少内存碎片 |
| THD 格式 | Packed Sequence | 避免填充浪费，加速注意力计算 |
| 异步收集 | `dist.gather_object` | CPU 通信不阻塞 GPU |

### 7.3 通信优化

```python
# 优化前：同步通信阻塞训练
for tensor in tensors:
    dist.all_reduce(tensor)  # 每次都阻塞

# 优化后：异步通信
handles = []
for tensor in tensors:
    handles.append(dist.all_reduce(tensor, async_op=True))
# ... 执行其他计算 ...
for handle in handles:
    handle.wait()  # 最后统一等待
```

def custom_rollout(args, rollout_id, data_buffer, evaluation=False):

        sample.log_probs = output_logprobs[i]

### 8.4 从 HuggingFace Datasets 自定义数据加载器

```python
from slime.rollout.data_source import DataSource
from datasets import load_dataset

class HuggingFaceDataSource(DataSource):
    """使用 HuggingFace datasets 库加载数据"""

    def __init__(self, args, dataset_name, split="train"):
        super().__init__(args)
        self.dataset = load_dataset(dataset_name, split=split, streaming=True)
        self.iterator = iter(self.dataset)

    def get_samples(self, n):
        """获取 n 个样本"""
        samples = []
        for _ in range(n):
            try:
                item = next(self.iterator)
                # 转换为 Slime 的 Sample 格式
                sample = Sample(
                    prompt=item["text"],
                    metadata={"source": "huggingface"},
                )
                samples.append(sample)
            except StopIteration:
                break
        return samples
```

## 10. 常见问题与解决方案

### 10.1 内存不足 (OOM)

**原因分析**：
1. 单个样本过长，超出 max_length
2. 微批次累积 token 超出 GPU 显存
3. CP 切片后填充过多

**解决方案**：
```python
# 1. 调整长度过滤阈值
--max-length 4096

# 2. 降低 max_tokens_per_gpu
--max-tokens-per-gpu 16384

# 3. 使用动态批次大小
--use-dynamic-batch-size
```

### 10.2 负载不均衡

**现象**：部分 GPU 显存满载，其他 GPU 空闲

**诊断**：
```python
# 在训练脚本中添加监控
from slime.utils.health_monitor import log_memory_stats
# 定期调用查看各 rank 显存分布
```

**解决方案**：
```python
# 1. 启用动态批次和序列长度均衡
--use-dynamic-batch-size
--seqlen-balancing

# 2. 检查数据分布
# 确保样本长度分布不是极端偏斜（如大量超长样本）

# 3. 调整 cp-pad-multiplier
# 确保 (seq_length / cp_size) % pad_multiplier == 0
```

### 10.3 数据加载瓶颈

**现象**：GPU 利用率低（`nvidia-smi` 显示 GPU 频繁空闲）

**诊断**：
```python
# 在 data_iterator 中计时
import time
def get_next(self, keys):
    start = time.time()
    batch = self._get_batch(keys)
    print(f"Data loading time: {time.time() - start:.3f}s")
    return batch
```

**解决方案**：
```python
# 1. 使用 Parquet 格式（比 JSONL 更快，且支持列式读取）
# 2. 数据缓存到本地 SSD/NVMe
--train-data-path "/local_ssd/data/train.jsonl"  # 而不是远程存储

# 3. 检查存储 I/O 带宽
# 建议：训练数据至少在 500MB/s+ 的存储上

# 4. 使用数据预加载（如果支持）
--num-data-loader-workers 4  # 增加数据加载工作进程
```

### 10.4 Reward 计算不一致

**现象**：不同 DP rank 的奖励值差异大，训练不稳定

**原因**：全局归一化未正确配置

**解决方案**：
```python
# 确保使用全局统计量归一化
--use-distributed-advantages  # 启用分布式 advantage 计算

# 自定义 RM 时确保正确处理 mask
# 参考 slime/utils/distributed_utils.py 的 distributed_masked_whiten
```
