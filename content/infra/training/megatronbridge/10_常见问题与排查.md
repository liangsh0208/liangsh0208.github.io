## 1. 安装与环境

### Q: 如何安装 Megatron-Bridge？

```bash
# 克隆仓库
git clone https://github.com/NVIDIA/Megatron-Bridge.git
cd Megatron-Bridge

# 初始化子模块（Megatron-LM）
git submodule update --init

# 使用 uv 安装依赖
uv sync --group dev

# 验证安装
uv run python -c "import megatron.bridge; print('OK')"
```

### Q: 需要特定的 PyTorch 版本吗？

是的，Megatron-Bridge 需要 PyTorch >= 2.6.0，且推荐使用 CUDA 12.4+：

| 组件 | 推荐版本 | 说明 |
|------|---------|------|
| PyTorch | >= 2.6.0 | 需要 `torch.nn.functional.scaled_dot_product_attention` |
| CUDA | 12.4+ | Transformer Engine 需要 |
| Transformers | 5.0.0 - 5.3.0 | 过高版本可能导致不兼容 |
| Python | >= 3.12 | 类型注解和 `|` 语法 |

### Q: 运行时提示 `No module named 'transformer_engine'`？

这是可选依赖。如需 FP8 混合精度：

```bash
pip install transformer-engine[pytorch]
# 或
uv pip install transformer-engine[pytorch]
```

### Q: 如何切换 Megatron-LM 子模块版本？

```bash
# 查看可用版本
./scripts/switch_mcore.sh --list

# 切换到稳定分支
./scripts/switch_mcore.sh main

# 切换到开发分支
./scripts/switch_mcore.sh dev
```

## 2. 模型加载与转换

### Q: 如何确认我的模型是否被支持？

```python
from megatron.bridge.models.conversion.auto_bridge import AutoBridge

# 检查支持性
print(AutoBridge.can_handle("meta-llama/Meta-Llama-3-8B"))

# 列出所有支持的架构
print(AutoBridge.list_supported_models())
```

### Q: 提示 `Model architecture not supported`？

```
ValueError: Model architecture not supported by AutoBridge
Supported architectures: ForCausalLM, ForConditionalGeneration
```

**解决方案**:
1. 确保模型架构后缀在 `ForCausalLM` / `ForConditionalGeneration` 中
2. 如果是自定义模型，确认 `config.architectures` 已正确设置
3. 如果是 `auto_map` 模型，需要手动注册 Bridge：

```python
# 注册自定义 Bridge
from megatron.bridge.models.conversion.mapping_registry import register_bridge
@register_bridge
class MyCustomBridge(MegatronModelBridge):
    pass
```

### Q: OOM 加载大模型？

```python
# 方案 1: 使用 device_map 自动分配
AutoBridge.from_hf_pretrained(
    "meta-llama/Meta-Llama-3-70B",
    device_map="auto",
    low_cpu_mem_usage=True,
)

# 方案 2: 指定最大内存
AutoBridge.from_hf_pretrained(
    "meta-llama/Meta-Llama-3-70B",
    max_memory={0: "40GB", 1: "40GB"},
    device_map="balanced",
)

# 方案 3: 仅加载配置
AutoBridge.from_hf_config(config)
```

### Q: 权重转换后数值精度不一致？

**原因**:
- BF16 `tie_word_embeddings` 精度损失
- 极端数值分布（如接近0的权重）

**解决方案**:

```python
# 验证转换精度
with torch.no_grad():
    hf_out = hf_model(input_ids).logits
    megatron_out = megatron_model[0](input_ids)
    
    # 检查最大差异
    max_diff = torch.abs(hf_out - megatron_out).max()
    print(f"Max diff: {max_diff}")  # 应 < 1e-3 for BF16
    
    # 如果差异大，检查 tie_word_embeddings
    assert max_diff < 1e-3, "Conversion precision issue detected"
```

## 3. 训练启动

### Q: 配置验证失败？

```
AssertionError: has_train_iters and has_train_samples cannot both be set
```

**原因**: `train_iters` 和 `train_samples` 互斥。

**解决方案**:

```python
# 方案 1: 按迭代训练
cfg.train.train_iters = 300000
cfg.train.train_samples = None  # 必须显式设为 None

# 方案 2: 按样本训练
cfg.train.train_iters = None    # 必须显式设为 None
cfg.train.train_samples = 100_000_000

# 方案 3: 运行时自动计算
if cfg.train.train_samples is not None:
    cfg.train.train_iters = cfg.train.train_samples // cfg.train.global_batch_size
```

### Q: 如何启动多节点训练？

```bash
# 单机多卡
uv run python -m torch.distributed.run \
    --nproc_per_node=8 \
    pretrain.py --config-file config.yaml

# 多节点（2 节点，每节点 8 卡）
uv run python -m torch.distributed.run \
    --nnodes=2 \
    --node_rank=0 \
    --nproc_per_node=8 \
    --master_addr=192.168.1.1 \
    --master_port=29500 \
    pretrain.py --config-file config.yaml

# 使用 Slurm
srun -N 2 --ntasks-per-node=8 \
    uv run python pretrain.py --config-file config.yaml
```

### Q: 训练开始时报 `NCCL` 错误？

常见错误及解决方案：

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| `NCCL init failed` | NCCL 版本不兼容 | 升级 NCCL: `pip install nvidia-nccl-cu12` |
| `Socket connect failed` | 网络配置问题 | 设置 `NCCL_SOCKET_IFNAME=eth0` |
| `Bus error` | 共享内存不足 | 增大 `/dev/shm` 或设置 `--ipc=host` |
| `Timeout` | 某 rank 卡住 | 检查数据加载器死锁、设置 `NCCL_TIMEOUT` |

## 4. 检查点与恢复

### Q: 检查点目录结构应如何组织？

```
checkpoints/
├── latest_train_state.pt       # 最新训练状态
├── run_config.yaml             # 运行配置
├── latest_checkpointed_iteration.txt  # Megatron-LM 兼容
└── iter_0100000/               # 第 100k 迭代检查点
    ├── train_state.pt
    ├── run_config.yaml
    ├── model/                   # torch_dist 格式
    │   ├── rank_0/
    │   ├── rank_1/
    │   └── ...
    ├── common.pt                # 公共状态
    └── optimizer/
```

### Q: 从 Megatron-LM 检查点恢复？

Megatron-Bridge 兼容 Megatron-LM 检查点：

```python
cfg.checkpoint.load = "/path/to/megatron_lm_ckpt"

# 自动检测格式
if checkpoint_exists(cfg.checkpoint.load):
    iteration, flops = load_checkpoint(state, model, optimizer, scheduler)
else:
    print("Checkpoint not found, starting from scratch")
```

### Q: 检查点加载提示 `checkpoint version mismatch`？

```python
# 方案 1: 指定加载严格模式
cfg.checkpoint.ckpt_format_strictness = "log_unexpected"

# 方案 2: 忽略版本（开发调试用）
set_checkpoint_version(get_checkpoint_version())  # 手动同步版本
```

### Q: 异步检查点未保存成功？

```python
# 检查异步队列状态
if not is_empty_async_queue(state):
    print("WARNING: Unfinalized async checkpoint saves")
    # 强制同步完成
    maybe_finalize_async_save(state, cfg.checkpoint, blocking=True)

# 配置建议
cfg.checkpoint.async_save = True
cfg.checkpoint.save_interval = 1000  # 确保间隔 > 异步保存时间
```

## 5. 分布式并行问题

### Q: 如何选择并行策略？

决策流程：

```
单 GPU 可放下？
├── 是 → 使用 DDP (Data Parallel)
└── 否 → 层数多？
    ├── 是 → PP (Pipeline Parallel) + TP (Tensor Parallel)
    └── 否 → TP (Tensor Parallel)
        └── 序列很长？
            ├── 是 → CP (Context Parallel)
            └── 否 → (纯 TP/PP)
                └── MoE 模型？
                    ├── 是 → EP (Expert Parallel)
                    └── 否 → 完成
```

### Q: TP/PP 配置与检查点不匹配？

```python
# 从检查点读取原始并行配置
run_config = read_run_config(checkpoint_dir)
ckpt_tp = run_config["model"]["tensor_model_parallel_size"]
ckpt_pp = run_config["model"]["pipeline_model_parallel_size"]

# 检查匹配性
if cfg.model.tensor_model_parallel_size != ckpt_tp:
    print(f"WARNING: TP mismatch: running={cfg.model.tensor_model_parallel_size}, checkpoint={ckpt_tp}")
    # 设置加载配置
    cfg.checkpoint.finetune = True  # 忽略不匹配
```

### Q: 流水线并行气泡过大？

```python
# 方案 1: 增加 micro_batch_size
cfg.train.micro_batch_size = 4  # 增大减少气泡

# 方案 2: 启用虚拟流水线
# 需要 virtual_pipeline_model_parallel_size > 1
cfg.model.virtual_pipeline_model_parallel_size = 5

# 方案 3: 启用交错的 1F1B
cfg.model.virtual_pipeline_model_parallel_size = 2
cfg.model.num_layers_per_virtual_pipeline_stage = 2
```

## 6. PEFT 微调问题

### Q: LoRA 微调后如何合并权重？

```python
from megatron.bridge.peft import LoRA, VLMLoRA

# 方式 1: Bridge 自动合并
bridge.save_hf_pretrained(
    model,
    "./output",
    merge_adapter_weights=True,  # 自动合并到基础权重
)

# 方式 2: 手动合并
lora = LoRA(target_modules=["linear_qkv"], dim=8)
merged_state = lora.merge(base_weight, linear_out, linear_in, alpha, dim)
```

### Q: LoRA 检查点只保存了适配器，没有基础模型？

**原因**: PEFT 配置启用了 `adapter_key_filter`。

**解决方案**:

```python
# 保存完整模型（含基础权重 + 适配器）
cfg.peft = None  # 临时禁用 PEFT
# 然后保存检查点

# 或分别保存
# 1. 保存 LoRA 适配器
bridge.save_hf_adapter(model, "./adapter", peft_config=lora)

# 2. 保存完整合并模型
bridge.save_hf_pretrained(model, "./full_model", merge_adapter_weights=True)
```

### Q: PEFT 微调学习率如何设置？

| 场景 | 学习率 | 说明 |
|------|--------|------|
| LoRA (小模型) | 1e-4 ~ 5e-4 | 较高，因为训练参数少 |
| LoRA (大模型) | 5e-5 ~ 1e-4 | 较低，避免过拟合 |
| DoRA | 1e-4 | 比 LoRA 稍高 |
| SFT (全参数) | 1e-6 ~ 1e-5 | 非常低，避免灾难性遗忘 |

## 7. 性能优化

### Q: GPU 利用率低？

诊断步骤：

```bash
# 1. 检查 GPU 利用率
nvidia-smi dmon -s u -d 1

# 2. 检查 CPU 负载
top -p $(pgrep -d',' python)

# 3. 检查数据加载瓶颈
# 如果 CPU 负载高而 GPU 低，数据加载是瓶颈
```

常见原因和解决方案：

| 症状 | 原因 | 解决方案 |
|------|------|---------|
| GPU 利用率 < 50% | 数据加载慢 | 增加 `num_workers`, 使用 `pin_memory=True` |
| GPU 利用率波动大 | 小 micro_batch_size | 增大 `micro_batch_size` |
| 全卡利用率低 | TP/PP 通信瓶颈 | 启用 `TP comm overlap`, `sequence_parallel` |
| 特定 rank 慢 | Straggler | 启用 Straggler 检测 |

### Q: 如何启用通信重叠？

```python
cfg.ddp = DistributedDataParallelConfig(
    use_distributed_optimizer=True,
    overlap_grad_reduce=True,      # 梯度 all-reduce 重叠
    overlap_param_gather=True,    # 参数 all-gather 重叠
)

cfg.comm_overlap = CommOverlapConfig(
    tp_comm_overlap=True,          # TP 通信重叠
    tp_comm_overlap_cfg=userbuffers_bf16_h100_h8192_tp4_mbs1_seqlen8192,
)
```

## 8. 数据相关问题

### Q: 数据混合比例如何调整？

```python
# 使用权重调整采样比例
cfg.dataset.blend = [
    ("/data/en/train.bin", 0.5),      # 英文 50%
    ("/data/cn/train.bin", 0.3),      # 中文 30%
    ("/data/code/train.bin", 0.2),    # 代码 20%
]

# 注意: 权重之和不需要等于 1，内部会归一化
```

### Q: 自定义 Tokenizer？

```python
# 方案 1: 使用 HF Tokenizer
cfg.tokenizer = TokenizerConfig(
    tokenizer_type="HuggingFaceTokenizer",
    tokenizer_model="meta-llama/Meta-Llama-3-8B",
)

# 方案 2: 使用 SentencePiece
cfg.tokenizer = TokenizerConfig(
    tokenizer_type="SentencePieceTokenizer",
    tokenizer_model="./tokenizer.model",
)

# 方案 3: VLM 使用 NullTokenizer
cfg.tokenizer = TokenizerConfig(
    tokenizer_type="NullTokenizer",
    vocab_size=128256,  # 仅用于占位
)
```

### Q: 数据分片策略？

```python
# 启用数据分片（推荐用于多节点）
cfg.dataset.data_sharding = True

# 分片逻辑：
# 1. 数据按 DP rank 分片
# 2. 每个 DP rank 只读取自己的数据切片
# 3. 避免所有 rank 读取相同数据导致 IO 瓶颈
```
