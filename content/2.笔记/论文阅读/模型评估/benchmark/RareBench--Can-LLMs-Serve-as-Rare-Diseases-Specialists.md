# RareBench: Can LLMs Serve as Rare Diseases Specialists?

## 一句话总结
RareBench 是首个系统性评估 LLM 罕见病诊疗能力的基准，涵盖表型提取、疾病筛查、常见病与罕见病鉴别、以及面向 421 种罕见病的全谱系鉴别诊断四个任务；实验表明 GPT-4 的罕见病鉴别诊断能力与资深专科医生相当，而基于 Information Content 的动态 few-shot 方法可将小模型 top-1 召回率平均提升 108%。

![](RareBench_fig1_overview.png)

> **Figure 1**: RareBench 评估框架总览：四个核心任务——(1) EHR 表型提取、(2) 特定罕见病筛查、(3) 常见病 vs 罕见病鉴别、(4) 全谱系罕见病鉴别诊断。

---

## 1. 研究背景与动机

### 1.1 问题定义

罕见病（Rare Diseases）指发病率极低的疾病，全球已知超过 7,000 种，约 80% 为遗传性疾病，影响约 **3 亿人**。罕见病患者面临极高的误诊和漏诊率，确诊前的平均等待时间长达数年。

诊断困难的核心原因：
- 医生缺乏罕见病诊疗经验（低暴露率）
- 不同罕见病之间存在显著的**表型重叠**（phenotypic overlap）
- 罕见病与常见病的症状也存在高度相似性

### 1.2 现有方法的不足

| 不足维度 | 具体表现 |
|---------|---------|
| **数据来源局限** | 现有计算诊断方法多在模拟病例或小规模数据集上验证，缺乏真实临床场景的检验 |
| **知识库不完整** | HPO、OMIM、Orphanet 等知识库对罕见病的表型注释不完整 |
| **LLM 评估空白** | 虽有 MedQA、PubMedQA 等医学基准，但**罕见病领域缺乏系统性 LLM 评估** |
| **表型提取难题** | 临床文本中表型记录方式多样，HPO 术语超过 17,000 个，精确映射极具挑战 |

现实案例更是凸显了 LLM 在罕见病诊断中的潜力——"ChatGPT 在 17 名医生失败后正确诊断了一个 4 岁儿童的罕见病"。但学术界对 LLM 在罕见病诊断中的系统评估仍然缺失。

## 2. RareBench 框架

### 2.1 四个核心任务

![](RareBench_fig2_tasks.png)

> **Figure 2**: 以 ALS（肌萎缩侧索硬化症）患者为例，展示 RareBench 的四个评估任务流程。

RareBench 设计了四个由浅入深的评估任务，全面覆盖罕见病临床诊断的关键环节：

| 任务 | 目标 | 数据量 | 数据来源 |
|------|------|--------|---------|
| **Task 1: 表型提取** | 从 EHR 中精确提取标准化 HPO 表型 | 87 例，34 种病 | PUMCH |
| **Task 2: 罕见病筛查** | 基于病史和辅助检查筛查特定罕见病 | 33 例，3 种病 | PUMCH |
| **Task 3: 常见病 vs 罕见病鉴别** | 区分症状相似的常见/罕见病 | 527 例，77 种病 | PUMCH |
| **Task 4: 全谱系罕见病鉴别诊断** | 在全部已知罕见病中进行系统鉴别 | **2,185 例，421 种病** | PUMCH + 公开数据集 |

其中 **Task 4 是核心和最具前瞻性的任务**，直接反映 LLM 在真实临床复杂场景下的诊断上限。

### 2.2 数据集构成

**PUMCH（北京协和医院）数据集**：
- 共 1,650 例病例，包含 1,183 例罕见病 + 467 例常见病
- 所有病例经医生审查，去除个人隐私信息
- 过滤标准：诊断不确定、信息缺失（<3 个表型）的病例被剔除

**公开数据集**：
- MME、LIRICAL、HMS、RAMEDIS 四个数据集
- 共 1,122 例，覆盖 362 种罕见病

**最终数据分布**：

| 数据集 | 类型 | 疾病数 | 病例数 |
|--------|------|--------|--------|
| Task 1 | EHRs | 34 | 87 |
| Task 2 | EHRs | 3 | 33 |
| Task 3 | EHRs | 77 | 527 |
| Task 4 | EHRs / 表型 | 421 | 2,185 |

## 3. 方法：知识整合动态 Few-shot

### 3.1 核心思想

作者提出一种基于**罕见病知识图谱**的**动态 few-shot 提示策略**，核心直觉是：
- 专科医生的诊断能力来源于**医学知识 + 过往临床经验**
- 动态 few-shot 能为 LLM 提供一种"浓缩的临床经验"
- 通过**表型特异性**（Information Content, IC）指导随机游走，能更好地捕捉罕见病诊断所需的关键表型关联

### 3.2 罕见病知识图谱构建

整合四大知识库构建统一知识图谱：

| 知识库 | 类型 | 节点/边数 |
|--------|------|----------|
| HPO | 表型本体（DAG 结构） | 17,232 表型；21,505 P-P 边 |
| OMIM | 疾病-表型关联 | 54,169 P-RD 边 |
| Orphanet | 疾病-表型关联 | 98,031 P-RD 边 |
| CCRD | 中国罕见病目录 | 4,223 P-RD 边 |
| **总计** | — | **9,260 疾病；172,662 关联** |

图谱包含两类边：
1. **表型-表型边**：来自 HPO 层次结构（IS-A 关系）
2. **疾病-表型边**：来自四个知识库的疾病-表型注释

### 3.3 IC-Based Random Walk

**Information Content (IC)** 的定义与 IDF 类似，衡量一个表型对特定疾病的特异性：

$$
IC(t) = -\log \frac{n(t)}{N}
$$

其中 $n(t)$ 为注释了表型 $t$ 或其下游表型的疾病数，$N = 9,260$ 为总疾病数。

> **直觉**：表型越靠近 HPO 根节点（描述越宽泛），或关联疾病越多（越常见），IC 越低；表型越特异于某种罕见病，IC 越高。

**IC 引导的随机游走**：

在 Node2vec 的随机游走框架上，作者将搜索偏置 $\alpha$ 与 IC 值关联：

| 游走方向 | 搜索偏置 |
|---------|---------|
| 表型 $t_1$ → 表型 $t_2$ | $\alpha = IC(t_2)$ |
| 表型 $t_1$ → 疾病 $d_1$ | $\alpha = IC(t_1)$ |

> **设计动机**：高 IC 的特异性表型在游走中获得更多关注，从而放大其与相关罕见病节点之间的关联。

### 3.4 动态 Few-shot 策略

**患者表征**：

对一个患者 $p = \{t_{x_1}, t_{x_2}, \ldots, t_{x_n}\}$，其嵌入为表型嵌入的 **IC 加权平均**：

$$
Embedding(p) = \frac{1}{\sum_{i=1}^{n} IC(t_{x_i})} \sum_{i=1}^{n} IC(t_{x_i}) \cdot f(t_{x_i})
$$

**动态检索**：
- 使用上述患者表征，基于余弦相似度检索训练集中最相似的 $m$ 个样例
- 将其作为 few-shot 示例输入 LLM

> 相比 MedPrompt（使用通用文本嵌入模型 text-embedding-ada-002），本方法利用了罕见病领域的深层表型关联，因此能检索到更具诊断参考价值的"相似病例"。

## 4. 实验结果

### 4.1 评估模型

共评估 11 个模型（5 个 API-based + 6 个开源，<10B 参数）：

| 类型 | 模型 |
|------|------|
| API-based | GPT-4, GPT-3.5-Turbo, Gemini Pro, GLM4, GLM3-Turbo |
| 通用开源 | Mistral-7B, Llama2-7B, ChatGLM3-6B |
| 医疗开源 | BioMistral-7B, HuatuoGPT2-7B, MedAlpaca-7B |

### 4.2 四个任务的主实验结果

| 模型 | Task 1 (F1) | Task 2 (Recall) | Task 3 (hit@1) | Task 4 (hit@1) |
|------|------------|-------------------|----------------|----------------|
| GPT-4 0-shot | 24.5% | 60.3% (平均) | 46.1% | **32.3%** |
| GPT-4 CoT | 25.1% | 62.1% (平均) | **47.4%** | **33.2%** |
| GPT-3.5-Turbo | 17.2% | 41.6% (平均) | 33.2% | 21.1% |
| Gemini Pro | 10.1% | 29.0% (平均) | 24.3% | 14.6% |
| GLM4 | 15.9% | 47.6% (平均) | 31.3% | 19.1% |
| Mistral-7B | 3.3% | 8.3% (平均) | 13.7% | 7.2% |
| HuatuoGPT2-7B | 3.7% | 17.4% (平均) | 18.6% | 11.4% |
| 医疗模型（其他） | <5% | <15% | <17% | <8.5% |

**关键发现**：

1. **GPT-4 全面领先**，但开源小模型在罕见病任务上表现极差（Task 4 top-1 < 12%）
2. **CoT 对 GPT-4 有稳定提升**，但对小模型效果有限
3. **表型标准化是最大瓶颈**：Task 1 中 GPT-4 F1 仅 24.5%，而通用实体提取 F1 达 64.9%，说明 LLM 提取实体能力强但**映射到标准化 HPO 术语困难**
4. **Task 4 最具区分度**：2,185 例、421 种罕见病的大规模鉴别诊断最能拉开模型差距

### 4.3 动态 Few-shot 效果（Task 4）

![](RareBench_fig4_dynamic_fewshot.png)

> **Figure 4**: 知识整合动态 few-shot 在 Task 4 上的效果对比。动态 3-shot 显著优于零样本、随机 3-shot、MedPrompt 和 Auto-CoT。

**75 例高质量子集上的对比**（来自 PUMCH）：

| 方法 | Gemini Pro | GLM4 | GLM3-Turbo | Llama2-7B |
|------|-----------|------|-----------|-----------|
| zero-shot | 36.0 / 56.0 / 65.3 | 37.3 / 53.3 / 62.7 | 21.3 / 41.3 / 60.0 | 21.3 / 37.3 / 49.4 |
| random 3-shot | 37.3 / 53.3 / 73.3 | 40.0 / 52.0 / 65.3 | 25.3 / 41.3 / 54.7 | 16.0 / 25.3 / 38.7 |
| MedPrompt | 56.0 / 66.7 / 73.3 | 52.0 / 64.0 / 72.0 | 40.0 / 60.0 / 74.7 | **61.3 / 78.7 / 81.3** |
| Auto-CoT | 40.0 / 61.3 / 76.0 | 36.0 / 50.7 / 66.7 | 36.0 / 42.7 / 54.7 | 20.0 / 30.7 / 40.0 |
| **dynamic 3-shot (ours)** | **62.7 / 74.7 / 82.7** | **62.7 / 70.7 / 76.0** | **72.0 / 77.3 / 84.0** | **66.7 / 73.3 / 80.0** |

> 数据格式：hit@1 / hit@3 / hit@10 (%)

**核心结论**：
- 动态 few-shot 平均使 6 个 LLM 的 top-1 recall 提升 **108%**
- GLM4 在动态 few-shot 下（62.7%）**超过 GPT-4 零样本**（~32%），甚至可能超越专科医生
- Llama2-7B（7B 参数）在动态 few-shot 下达到 66.7% 的 hit@1，远超其零样本的 21.3%
- **MedPrompt 对 Llama2-7B 有效但对其他模型不足**，Auto-CoT 在小模型上表现差（推理质量依赖模型能力）

### 4.4 人机对比：GPT-4 vs 专科医生

![](RareBench_fig5_dept_comparison.png)

> **Figure 5**: GPT-4 与专科医生在 5 个科室（心内科、血液科、肾内科、神经科、儿科）的诊断表现对比。GPT-4 在所有科室均超越了医生水平，儿科表现最好，心内科最具挑战。

**实验设计**：
- 75 例病例，来自 5 个科室，16 种疾病
- 50 名医生（每科 10 名），来自 23 家三甲医院
- 每例由 4 名医生诊断，可借助外部辅助工具

**结果**：

| 方法 | hit@1 | hit@3 | hit@10 |
|------|-------|-------|--------|
| GPT-4（表型输入） | **52.0%** | **74.7%** | **82.7%** |
| GPT-4（EHR 文本输入） | 45.3% | 69.3% | 80.0% |
| 医生（无辅助） | 40.7% | 46.8% | 48.1% |
| 医生（有辅助） | 44.7% | 51.1% | 52.4% |

**关键发现**：
- **GPT-4 使用表型输入优于 EHR 文本输入**（52.0% vs 45.3%），说明提取的表型能消除无关信息干扰
- **GPT-4 全面超越专科医生**，即使医生借助外部工具也未能赶上
- 科室差异显著：儿科表现最好（信息全面），心内科最差（依赖影像学等客观检查）
- 提示未来方向：结合多模态大模型纳入影像、病理等更全面信息

## 5. 案例分析

### 5.1 表型提取 — 正面案例

- **高精度实体提取**：GPT-4 能有效避免提取与疾病无关的信息（如医院名称、用药详情）
- **否定表型识别**：能准确识别否定描述（如"no fever"），不提取"fever"

### 5.2 表型提取 — 负面案例

- **描述性实体丢失**：将"Shortness of breath after walking up three flights of stairs"简化为"shortness of breath"，丢失了关键上下文
- **实验室异常值识别不足**：未能识别"K 3.26 mmol/L ↓"等异常指标，导致相关表型遗漏

## 6. 局限性与未来方向

| 局限 | 说明 |
|------|------|
| **可解释性不足** | LLM 诊断决策过程不透明，临床医生和患者难以完全信任 |
| **数据偏差** | 罕见病数据稀缺且分布不均，训练数据偏差可能影响预测 |
| **泛化能力** | 模型在新环境下的表现可能下降，影响实际临床应用 |
| **仅作为辅助** | 由于幻觉等问题，LLM 目前只能作为临床辅助工具 |
| **多模态缺失** | 当前仅基于文本/表型，未纳入影像、病理等关键诊断信息 |

**未来方向**：
- 结合多模态大模型（LMMs）纳入影像、病理、电生理等数据
- 提升表型提取的精确度和完整性
- 构建更大规模、更多样化的罕见病数据集
- 增强 LLM 诊断推理的可解释性

## 7. 个人思考

### 方法的亮点
1. **任务设计层次清晰**：从表型提取 → 疾病筛查 → 鉴别诊断，由浅入深地评估 LLM 在罕见病诊断各环节的能力
2. **知识融入的优雅性**：IC-based random walk 看似简单，但巧妙地利用了罕见病领域表型特异性的核心概念——特异性越高的表型越值得"关注"
3. **人机对比实验设计扎实**：75 例×4 医生×5 科室的交叉设计，结果具有临床说服力

### 对 LLM 医学应用的启示
- **表型提取是瓶颈**：即使 GPT-4 的 HPO 映射 F1 也只有 24.5%，说明从自由文本到标准化术语的映射仍是医学 NLP 的硬骨头
- **"临床经验"可以通过检索模拟**：动态 few-shot 的本质是给 LLM 提供"类似病例"的参考，效果惊人。这说明 **RAG 在医学诊断中的潜力巨大**
- **GPT-4 vs 医生**：虽然 GPT-4 在 hit@1 上超越医生，但临床诊断是一个涉及医患沟通、伦理决策、动态观察的复杂过程，不能完全用 top-k recall 衡量
