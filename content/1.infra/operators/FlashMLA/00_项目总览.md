> 官方仓库：https://github.com/deepseek-ai/FlashMLA  
> 版本：v1.0.0（2025年9月）

## 1. 项目定位

FlashMLA 是 DeepSeek 开源的**高性能注意力 CUDA 内核库**，专为 DeepSeek-V3 / V3.1 / V3.2 系列大语言模型的推理与训练加速而设计。它承载了 DeepSeek 在线推理系统中全部注意力计算，是 DeepSeek 开源基础设施的核心组件之一。

该项目实现了四类内核，覆盖了模型推理的两个阶段（Prefill 和 Decoding）以及两种稀疏度（Dense 和 Sparse）：

| 内核类型 | GPU 架构 | MLA 模式 | KV Cache 格式 | 峰值性能 |
|---------|---------|---------|--------------|---------|
| 密集解码（Dense Decode）| SM90（H800/H100） | MQA | BF16 / FP16 | 3000 GB/s（内存限制）/ 660 TFlops（计算限制）|
| 稀疏解码（Sparse Decode）| SM90 & SM100 | MQA | FP8（含量化缩放因子）| 410 TFlops (H800) |
| 密集预填充（Dense Prefill）| SM100（B200） | MHA | — | 1460 TFlops 前向 / 1000 TFlops 反向 |
| 稀疏预填充（Sparse Prefill）| SM90 & SM100 | MQA | BF16 | 640 TFlops (H800) / 1450 TFlops (B200) |

## 2. MLA（Multi-head Latent Attention）原理

### 2.1 标准 MHA 的问题

在标准多头注意力（Multi-Head Attention, MHA）中，KV Cache 的大小为：

```
KV Cache 大小 = 2 × B × S × h × d × sizeof(dtype)
```

对于 DeepSeek-V3（`h=128`，`d=128`，BF16），128K 上下文的单条请求 KV Cache 约 **8.72 GiB**，内存压力极大。

### 2.2 MLA 的降维压缩思路

MLA 通过**低秩压缩**大幅减少 KV Cache。DeepSeek-V3 的 MLA 具体做法是：

1. **训练阶段**：将 Key 和 Value 压缩到一个低维的"潜在向量"（latent vector）`c_KV`：
   ```
   c_KV = W_c · x          # 压缩投影，维度 = 512（压缩后）
   K = W_K · c_KV           # 恢复 Key
   V = W_V · c_KV           # 恢复 Value
   ```

2. **推理阶段的关键变换**：由于线性代数的结合律，可以将解压矩阵吸收到 Query 投影中：
   ```
   QK^T = Q · (W_K · c_KV)^T = (Q · W_K^T) · c_KV^T
   
   令 Q' = Q · W_K^T，则  QK^T = Q' · c_KV^T
   ```
   这意味着**只需缓存 `c_KV` 而非完整的 K/V**，KV Cache 大小从 `2×h×d` 降至 `d_c`（约 512 维），节约约 **85%** 的内存。

3. **RoPE（旋转位置编码）的特殊处理**：RoPE 无法被吸收到 Q 投影中（因为它依赖 token 位置），所以额外保留一个小的 RoPE 部分（64 维），单独存储在 KV Cache 中。

### 2.3 FlashMLA 中的 MLA 两种计算模式

| 模式 | head_dim_k | head_dim_v | 适用 |
|------|-----------|-----------|------|
| **MQA 模式**（DeepSeek-V3.x 推理）| 576 = 512(NoPE) + 64(RoPE) | 512 | 解码阶段、稀疏预填充 |
| **MHA 模式**（SM100 密集预填充）| 192 或 128 | 128 | B200 上的训练/预填充 |

在 MQA 模式下，`h_q = 128`，`h_kv = 1`，即 128 个 Query 头共享 1 个 KV 头（Multi-Query Attention），计算-带宽比约为 `2 × h_q = 256`，远超 H800 的平衡点（≈ 128），因此解码阶段是**计算瓶颈而非内存瓶颈**——这是 FlashMLA 内核设计的核心前提。

## 3. 与 FlashAttention 的关系

FlashMLA 受 FlashAttention-2/3 的启发，但针对 MLA 的特性（超大 head_dim、MQA 模式）做了深度改造：

| 特性 | FlashAttention-2/3 | FlashMLA |
|------|---------------------|---------|
| 目标场景 | 通用注意力（训练+推理）| MLA 推理解码（主要）+ 训练预填充 |
| head_dim | 64~256 | 512~576（NoPE+RoPE）|
| Q/KV 头比 | GQA（多对多）| MQA（128:1）|
| 寄存器压力 | 可双缓冲 O 矩阵 | O 矩阵 64×512 占 32768 寄存器，无法双缓冲 |
| 关键技术 | Ping-pong 双缓冲调度 | Seesaw 调度（单矩阵跷跷板）|
| Sparse 支持 | 无 | DSA（DeepSeek Sparse Attention）|
| FP8 KV Cache | 部分支持 | 专用格式（tile-level 量化 + RoPE 不量化）|

### 3.1 Online Softmax 的共同基础

FlashMLA 与 FlashAttention 共享 Online Softmax 的数学基础：

```
初始化：m = -∞，l = 0，O = 0

对每个 KV 块 K_j, V_j：
  S_j = Q · K_j^T / sqrt(d)          # 局部 attention scores
  m_new = max(m, max(S_j))            # 更新全局最大值
  l = exp(m - m_new) · l + sum(exp(S_j - m_new))  # 更新归一化常数
  O = exp(m - m_new) · O + exp(S_j - m_new) · V_j  # 滚动更新输出
  m = m_new

最终：O = O / l
```

这样只需 O(S) 的显存，无需完整存储 S×S 的注意力矩阵。

### 3.2 FlashMLA 的关键创新：Seesaw 调度

由于 head_dim=512，输出矩阵 `O (64×512)` 占 32768 个 32-bit 寄存器，恰好是每个 SM 寄存器总量（65536）的一半，无法同时容纳两个 O 矩阵做 ping-pong。FlashMLA 将 O 纵向切分为 `O_L (64×256)` 和 `O_R (64×256)`，由两个 warpgroup 交替持有，形成 **Seesaw（跷跷板）调度**（详见 `03_Dense解码内核.md`）。

## 4. 项目整体架构

### 4.1 目录结构

```
FlashMLA/
├── flash_mla/                      # Python 接口层
│   ├── __init__.py                 # 导出公开 API
│   └── flash_mla_interface.py      # 主接口：4 个公开函数 + FlashMLASchedMeta
├── csrc/                           # C++/CUDA 源码
│   ├── api/                        # C++ 分发层（Python 绑定入口）
│   │   ├── api.cpp                 # pybind11 模块定义
│   │   ├── common.h                # 架构检测、dispatch 宏、ImplBase
│   │   ├── dense_decode.h          # 密集解码分发
│   │   ├── sparse_decode.h         # 稀疏解码分发（含 DecodeImplBase）
│   │   ├── dense_fwd.h             # SM100 密集预填充分发
│   │   └── sparse_fwd.h            # 稀疏预填充分发
│   ├── params.h                    # 所有 kernel 参数结构体
│   ├── defines.h                   # 基础类型别名（bf16, fp8, etc.）
│   ├── utils.h                     # 工具宏、RingBufferState
│   ├── sm90/                       # SM90（Hopper, H800/H100）专用 kernel
│   │   ├── helpers.h               # WGMMA 辅助、TMA 封装、DSM 相关
│   │   ├── decode/dense/           # 密集 MLA 解码
│   │   ├── decode/sparse_fp8/      # FP8 稀疏 MLA 解码（含 Crossover）
│   │   └── prefill/sparse/         # 稀疏 MLA 预填充
│   ├── sm100/                      # SM100（Blackwell, B200）专用 kernel
│   │   ├── helpers.h               # FP8 转换辅助
│   │   ├── prefill/dense/          # 密集 MHA 前向+反向（来自 NVIDIA PR）
│   │   ├── prefill/sparse/         # 稀疏 MLA 预填充
│   │   └── decode/                 # SM100 稀疏解码
│   └── smxx/                       # 架构通用辅助 kernel
│       └── decode/
│           ├── get_decoding_sched_meta/  # Tile Scheduler 元数据计算
│           └── combine/                 # Split-KV 结果合并
├── benchmark/
│   ├── bench_flash_mla.py          # 多后端（FlashMLA/FlashInfer/Triton）对比基准
│   └── visualize.py                # 性能结果可视化
├── tests/
│   ├── test_flash_mla_dense_decoding.py    # 密集解码正确性+性能测试
│   ├── test_flash_mla_sparse_decoding.py   # 稀疏解码正确性+性能测试
│   ├── test_flash_mla_sparse_prefill.py    # 稀疏预填充测试
│   ├── test_fmha_sm100.py                  # SM100 密集 MHA 测试
│   ├── ref.py                              # PyTorch 参考实现
│   ├── quant.py                            # FP8 量化/反量化工具
│   ├── lib.py                              # 测试参数结构体
│   └── kernelkit/                          # 性能测量工具包
├── docs/
│   ├── 20250422-new-kernel-deep-dive.md    # 密集解码新内核技术博客
│   └── 20250929-hopper-fp8-sparse-deep-dive.md  # FP8 稀疏解码技术博客
└── setup.py                        # 编译配置（NVCC 多架构目标）
```

### 4.2 调用链总览

```
Python 代码
    ↓
flash_mla_interface.py
  flash_mla_with_kvcache() / flash_mla_sparse_fwd()
    ↓ 调用 flash_mla.cuda.xxx_fwd()（pybind11）
csrc/api/
  dense_decode.h / sparse_decode.h / sparse_fwd.h / dense_fwd.h
    ↓ 架构检测 → 选择 ImplXxx 实现类
    ↓ run_xxx_kernel<MODEL_TYPE, NUM_HEADS>(params)
csrc/sm90/ 或 csrc/sm100/
    CUDA kernel（Hopper WGMMA + TMA）
    ↓
csrc/smxx/decode/combine/
    合并 Split-KV 分片结果
```

## 5. 公开 API 一览

```python
from flash_mla import (
    get_mla_metadata,           # 构造 FlashMLASchedMeta 对象（懒初始化）
    flash_mla_with_kvcache,     # 密集解码 + 稀疏解码（统一入口）
    flash_mla_sparse_fwd,       # 稀疏预填充
    flash_attn_varlen_func,         # SM100 密集 MHA 前向（变长序列）
    flash_attn_varlen_qkvpacked_func,  # SM100 MHA，QKV packed 格式
    flash_attn_varlen_kvpacked_func,   # SM100 MHA，KV packed 格式
)
```

### 核心参数规格（DeepSeek-V3 / V3.2 配置）

| 参数 | 值 | 说明 |
|------|----|------|
| `h_q` | 128 | Query 头数 |
| `h_kv` | 1 | KV 头数（MQA）|
| `head_dim_k` | 576 = 512 + 64 | K 的维度（NoPE + RoPE）|
| `head_dim_v` | 512 | V 的维度（纯 NoPE）|
| `page_block_size` | 64 | Paged KV Cache 每页 token 数 |

## 6. 硬件需求与编译

### 支持矩阵

| 架构 | GPU 型号 | CUDA 最低版本 |
|------|---------|--------------|
| SM90a | H100 / H800 | 12.8 |
| SM100f | B200 | 12.9 |

### 编译参数

```bash
# 标准编译（支持 SM90 + SM100）
pip install -v .

# 仅编译 SM90（跳过 SM100）
FLASH_MLA_DISABLE_SM100=1 pip install -v .

# 加速编译（32 线程并行）
NVCC_THREADS=32 pip install -v .
```

`setup.py` 使用了一系列 NVCC 优化标志：
```
-O3 --use_fast_math                 # 最高优化
--expt-relaxed-constexpr            # 放宽 constexpr 限制
--ptxas-options=--register-usage-level=10  # 寄存器使用级别控制
--warn-on-spills                    # 寄存器溢出警告（开发调试用）
```
