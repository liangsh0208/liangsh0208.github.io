# 稀疏注意力预填充内核

> 源码路径：`csrc/sm90/prefill/sparse/`、`csrc/sm100/prefill/sparse/`  
> Python 接口：`flash_mla_sparse_fwd()`、`FlashAttnVarlenFunc`

---

## 1. 预填充阶段的挑战

解码阶段（decode）每次只生成一个 token（seq_q=1），而预填充阶段（prefill）需要处理整个输入序列（seq_q=S_q），计算完整的注意力矩阵。

对于超长上下文（128K token），完整的注意力矩阵 S_q×S_k 会占用极大的显存和计算量。DeepSeek-V3.2 采用 **DSA（DeepSeek Sparse Attention）** 在预填充阶段也只关注最相关的 K/V tokens。

---

## 2. 稀疏预填充 API

```python
from flash_mla import flash_mla_sparse_fwd

out, max_logits, lse = flash_mla_sparse_fwd(
    q,               # [s_q, h_q, d_qk], bfloat16
    kv,              # [s_kv, h_kv, d_qk], bfloat16（注意：不是 paged，直接连续）
    indices,         # [s_q, h_kv, topk], int32
    sm_scale,        # float，= 1/sqrt(d_qk)
    d_v=512,
    attn_sink=None,  # [h_q], float32，可选
    topk_length=None,# [s_q], int32，可选（每个 q token 的实际 topk）
)
```

**与解码的关键差异**：

| 维度 | 解码（decode） | 预填充（prefill） |
|------|--------------|----------------|
| `q` 形状 | `[b, s_q, h_q, d_qk]` | `[s_q, h_q, d_qk]`（无 batch 维） |
| `kv` 形状 | Paged: `[num_blocks, page_block_size, ...]` | 连续: `[s_kv, h_kv, d_qk]` |
| `indices` 形状 | `[b, s_q, topk]` | `[s_q, h_kv, topk]`（多了 h_kv 维度）|
| FP8 KV Cache | 支持 | 不支持（预填充用 BF16）|

---

## 3. Indices 格式详解

预填充的 indices 有三个维度：`[s_q, h_kv, topk]`：

```
indices[i, j, k] = KV token 索引

每个 q token（第 i 个）、每个 KV head（第 j 个），选出 topk 个 KV token
```

注意 `h_kv` 维度：在 MQA 中 h_kv=1，每个 q token 对应一组 topk 索引；在 GQA/MHA 中不同 KV head 可有不同的稀疏模式。

**无效索引标记**：值为 -1 或 >= s_kv 的索引会被忽略，用于 padding 到固定 topk 大小：

```python
# 示例：s_q=4, h_kv=1, topk=8
# 有些 q token 实际只有 5 个有效邻居
indices = torch.tensor([
    [[10, 20, 30, 40, 50, -1, -1, -1]],  # q[0]: 5 个有效邻居
    [[5,  15, 25, 35, 45, 55, 65, 75]],  # q[1]: 8 个有效邻居
    [[-1, -1, -1, -1, -1, -1, -1, -1]],  # q[2]: 无邻居（padding token）
    [[100, 200, 300, 400, 500, -1, -1, -1]], # q[3]: 5 个有效邻居
], dtype=torch.int32)
```

## 4. 稀疏预填充内核实现

### 4.1 SM90（H100/H800）实现

源码：`csrc/sm90/prefill/sparse/`

关键文件：
- `fwd.h`：kernel 主体，处理 tiling 和 CTA 分配
- `phase1.h`：注意力计算的 Phase 1（QK GEMM + softmax）
- `config.h`：模板参数（BLOCK_SIZE_M、BLOCK_SIZE_N 等）

**计算模式**：

```
对每个 q token block（大小 BLOCK_SIZE_M）：
  对 indices 中的每个 KV token（按 topk 顺序）：
    1. 加载 K block（从 kv[indices[i]]）
    2. QK GEMM → 注意力分数
    3. Online softmax 更新 m, l
    4. 加载 V block（从 kv[indices[i]] 的 V 部分）
    5. PV GEMM → 累积 O
  6. O /= l（归一化）
  7. 写出 O 到 global memory
```

与密集注意力的主要差异：K/V 的加载是**不连续的随机访问**（按照 indices 跳转），而非顺序扫描。这对 L2/L1 缓存不友好，但通过稀疏性大幅减少了总计算量。

### 4.2 SparseAttnFwdParams 结构体

```cpp
struct SparseAttnFwdParams {
    // 序列和头维度
    int s_q, s_kv, h_q, h_kv, d_qk, d_v, topk;
    float sm_scale, sm_scale_div_log2;  // sm_scale_div_log2 = sm_scale / log(2)

    // 输入张量（连续）
    cutlass::bfloat16_t* q;      // [s_q, h_q, d_qk]
    cutlass::bfloat16_t* kv;     // [s_kv, h_kv, d_qk]  ← KV 融合存储
    int* indices;                 // [s_q, h_kv, topk]
    float* attn_sink;            // [h_q], 可为 nullptr
    int* topk_length;            // [s_q], 可为 nullptr

    // 步长（stride，支持非连续存储）
    int stride_q_s_q;   int stride_q_h_q;
    int stride_kv_s_kv; int stride_kv_h_kv;
    int stride_indices_s_q; int stride_indices_h_kv;

    // 输出张量
    cutlass::bfloat16_t* out;   // [s_q, h_q, d_v]
    float* max_logits;          // [s_q, h_q]  ← 与解码不同，预填充额外返回 max_logits
    float* lse;                 // [s_q, h_q]

    int num_sm;
    cudaStream_t stream;
};
```

注意 KV 融合存储：K 和 V 合并在一个张量中，`kv[i, j, :]` 包含了 token i、head j 的 K 和 V 拼接（`d_qk = d_k + d_v = 576`，前 576 维是 K，后 512 维是 V，但在 MLA 中 K 和 V 使用同一张量的不同切片）。

### 4.3 SparseAttnFwdMode 模板参数

```cpp
enum class SparseAttnFwdMode {
    Prefill,            // 标准预填充
    DecodeWithSplitKV,  // 解码模式（某些内核支持两种模式）
};

// 通过模板参数在编译时选择模式
template<SparseAttnFwdMode FWD_MODE>
void launch_sparse_attention_kernel(SparseFwdArgT<FWD_MODE>& params) { ... }
```

## 5. SM100（B200）稀疏预填充

B200 使用 SM100 架构，引入了新的 `tcgen05` UMMA（Uniform Matrix Multiply Accumulate）指令，与 H100 的 WGMMA 不同：

```
SM90 WGMMA：warpgroup 级别的矩阵乘法（4个warp一组）
SM100 tcgen05 UMMA：更大的 tile，更高吞吐量
```

B200 上的稀疏预填充性能：**~1450 TFlops**（对比 H800 的 640 TFlops）。

## 6. SM100 密集预填充（FlashAttnVarlenFunc）

针对 B200 的密集 MHA 预填充提供了完整的前向+反向支持：

### 6.1 前向接口

```python
from flash_mla import flash_attn_varlen_func

out, lse = flash_attn_varlen_func(
    q,                          # [total_q, h_q, d_qk]，packed 格式
    k,                          # [total_kv, h_kv, d_qk]
    v,                          # [total_kv, h_kv, d_v]
    cu_seqlens_qo,              # [batch+1]，q 序列的累积长度
    cu_seqlens_kv,              # [batch+1]，kv 序列的累积长度
    max_seqlen_qo=max_q,
    max_seqlen_kv=max_kv,
    causal=True,                # 是否使用 causal mask
    softmax_scale=None,         # 默认 1/sqrt(d_qk)
)
```

变长序列（varlen）格式：将 batch 中所有序列拼接为一个长序列，用 `cu_seqlens` 标记每条序列的边界。这是 FlashAttention 的标准接口格式，避免了 padding 的显存浪费。

### 6.2 反向接口

```python
dq, dk, dv = _flash_attn_varlen_backward(
    do, q, k, v, out, lse,
    cu_seqlens_qo, cu_seqlens_kv,
    max_seqlen_qo, max_seqlen_kv,
    causal=causal, softmax_scale=softmax_scale,
)
```

**注意**：SM100 反向不支持 GQA（`num_qo_heads != num_kv_heads` 时会报错）。这是当前版本的限制，未来版本会修复。

### 6.3 反向的 workspace 计算

```python
# 反向需要较大的工作空间
workspace_bytes += 4 * bs * max_seqlen_qo_aligned * num_qo_heads * head_dim_qk  # dQ_acc
workspace_bytes += 4 * max_seqlen_qo_aligned * bs * num_qo_heads * 2           # sum_OdO + scaled_lse
```

前向只需 32MB workspace，反向根据 batch 大小动态计算。

## 7. 完整训练流程示例（SM100 预填充）

```python
from flash_mla import flash_attn_varlen_func

class FlashMLALayer(torch.nn.Module):
    def __init__(self, h_q, h_kv, d_qk, d_v):
        super().__init__()
        self.q_proj = nn.Linear(hidden, h_q * d_qk, bias=False)
        self.kv_proj = nn.Linear(hidden, h_kv * d_qk, bias=False)
        self.o_proj = nn.Linear(h_q * d_v, hidden, bias=False)
        self.sm_scale = d_qk ** -0.5
    
    def forward(self, hidden_states, cu_seqlens, max_seqlen):
        total_q = hidden_states.shape[0]
        
        q = self.q_proj(hidden_states).view(total_q, -1, d_qk)
        kv = self.kv_proj(hidden_states).view(total_q, -1, d_qk)
        k, v = kv[:, :, :d_k], kv[:, :, d_k:]
        
        # 调用 FlashMLA 预填充（SM100 forward+backward）
        out, lse = flash_attn_varlen_func(
            q, k, v,
            cu_seqlens, cu_seqlens,
            max_seqlen, max_seqlen,
            causal=True,
            softmax_scale=self.sm_scale,
        )
        
        out = out.view(total_q, -1)
        return self.o_proj(out)
```

## 8. 性能汇总

| 内核 | GPU | 模式 | 方向 | 性能 |
|------|-----|------|------|------|
| 稀疏预填充 | H800（SM90）| MQA + BF16 | 前向 | ~640 TFlops |
| 稀疏预填充 | B200（SM100）| MQA + BF16 | 前向 | ~1450 TFlops |
| 密集 MHA 预填充 | B200（SM100）| MHA + BF16 | 前向 | ~1460 TFlops |
| 密集 MHA 预填充 | B200（SM100）| MHA + BF16 | 反向 | ~1000 TFlops |

B200 的预填充吞吐约为 H800 的 **2.2×**，体现了 SM100 架构在矩阵计算上的代际提升。
