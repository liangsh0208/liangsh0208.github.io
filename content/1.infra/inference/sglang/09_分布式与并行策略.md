# 第九章：分布式与并行策略

## 一、概述

SGLang 支持多种并行策略以适应不同规模和场景的推理需求。本章详细分析张量并行 (TP)、流水线并行 (PP)、数据并行 (DP)、专家并行 (EP) 以及分离式推理的实现。

## 二、并行策略总览

### 2.1 并行策略对比

| 策略 | 缩写 | 切分维度 | 适用场景 |
|------|------|----------|----------|
| 张量并行 | TP | 模型层内 | 单机多卡 |
| 流水线并行 | PP | 模型层间 | 多机/显存不足 |
| 数据并行 | DP | 请求 | 高吞吐场景 |
| 专家并行 | EP | MoE 专家 | MoE 模型 |
| 上下文并行 | CP | 序列长度 | 超长序列 |
| 分离式推理 | Disagg | Prefill/Decode | 低延迟场景 |

## 三、张量并行 (TP)

### 3.1 原理

张量并行将模型层内的计算按维度切分到多个 GPU：

```
标准线性层: Y = XW

Column Parallel: 将 W 按列切分
  W = [W_0 | W_1]
  Y_0 = XW_0  (GPU 0)
  Y_1 = XW_1  (GPU 1)
  Y = [Y_0 | Y_1] (AllGather)

Row Parallel: 将 W 按行切分
  W = [W_0]
      [W_1]
  Y_0 = X_0W_0 (GPU 0)
  Y_1 = X_1W_1 (GPU 1)
  Y = Y_0 + Y_1 (AllReduce)
```

### 3.2 实现

**文件位置**：`python/sglang/srt/distributed/parallel_state.py`

```python
class TensorParallelGroup:
    """张量并行组管理"""

    def __init__(self, tp_size: int):
        self.tp_size = tp_size
        self.group = torch.distributed.new_group(
            ranks=list(range(tp_size)),
        )

    def all_reduce(self, tensor: torch.Tensor) -> torch.Tensor:
        """组内 AllReduce"""
        torch.distributed.all_reduce(tensor, group=self.group)
        return tensor
```

### 3.3 线性层并行

**文件位置**：`python/sglang/srt/layers/linear.py`

```python
class ColumnParallelLinear(nn.Module):
    """列并行线性层 - 输出维度切分"""

    def __init__(self, input_size: int, output_size: int, tp_size: int):
        self.tp_size = tp_size
        self.output_size_per_partition = output_size // tp_size

        # 每个 GPU 只存储一部分权重
        self.weight = nn.Parameter(torch.empty(
            self.output_size_per_partition,
            input_size,
        ))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # 每个 GPU 计算自己的部分
        output = F.linear(x, self.weight)
        # 不需要 AllReduce，输出直接使用
        return output


class RowParallelLinear(nn.Module):
    """行并行线性层 - 输入维度切分"""

    def __init__(self, input_size: int, output_size: int, tp_size: int):
        self.tp_size = tp_size
        self.input_size_per_partition = input_size // tp_size

        self.weight = nn.Parameter(torch.empty(
            output_size,
            self.input_size_per_partition,
        ))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # 每个 GPU 计算自己的部分
        output = F.linear(x, self.weight)
        # AllReduce 合并结果
        output = tensor_parallel_all_reduce(output)
        return output
```

### 3.4 典型 Transformer 层并行

```python
class ParallelTransformerBlock(nn.Module):
    """并行 Transformer 层"""

    def forward(self, hidden_states: torch.Tensor):
        # Attention
        # QKV 使用 Column Parallel (输出切分)
        qkv = self.qkv_proj(hidden_states)  # [batch, seq, 3*hidden/tp]

        # Attention 计算 (每个 GPU 处理部分 head)
        attn_output = self.attention(qkv)

        # Output 投影使用 Row Parallel (AllReduce)
        hidden_states = hidden_states + self.o_proj(attn_output)

        # MLP
        # Gate/Up 使用 Column Parallel
        gate_up = self.gate_up_proj(hidden_states)  # [batch, seq, 2*inter/tp]
        gate, up = gate_up.chunk(2, dim=-1)
        mlp_output = F.silu(gate) * up

        # Down 使用 Row Parallel (AllReduce)
        hidden_states = hidden_states + self.down_proj(mlp_output)

        return hidden_states
```

## 四、流水线并行 (PP)

### 4.1 原理

流水线并行将模型的层分配到不同 GPU，形成流水线执行：

```
GPU 0: Layers 0-7   (Stage 0)
GPU 1: Layers 8-15  (Stage 1)
GPU 2: Layers 16-23 (Stage 2)
GPU 3: Layers 24-31 (Stage 3)

Pipeline Schedule:
Time ─────────────────────────────────────────────────────────────────────►

Micro-batch 1: Stage0 → Stage1 → Stage2 → Stage3
Micro-batch 2:      Stage0 → Stage1 → Stage2 → Stage3
Micro-batch 3:           Stage0 → Stage1 → Stage2 → Stage3
```

### 4.2 Scheduler PP Mixin

**文件位置**：`python/sglang/srt/managers/scheduler_pp_mixin.py`

```python
class SchedulerPPMixin:
    """流水线并行调度 Mixin"""

    def event_loop_pp(self):
        """PP 事件循环"""

        while True:
            # 1. 接收请求
            recv_reqs = self.recv_requests()
            self.process_input_requests(recv_reqs)

            # 2. 获取批次
            batch = self.get_next_batch_to_run()

            # 3. 执行前向传播
            if batch:
                if self.is_last_pp_rank:
                    # 最后一个 stage: 完成并返回
                    result = self.run_batch(batch)
                    self.process_batch_result(batch, result)
                else:
                    # 中间 stage: 发送到下一个 stage
                    self.send_to_next_pp_stage(batch)
            else:
                # 空闲时检查是否有来自上一个 stage 的数据
                self.recv_from_prev_pp_stage()

    def send_to_next_pp_stage(self, batch: ScheduleBatch):
        """发送到下一个 PP Stage"""
        # 发送隐藏状态和元数据
        send_dict = {
            "hidden_states": batch.hidden_states,
            "req_pool_indices": batch.req_pool_indices,
            "seq_lens": batch.seq_lens,
            ...
        }
        torch.distributed.send_obj_dict(send_dict, dst=self.next_pp_rank)

    def recv_from_prev_pp_stage(self):
        """从上一个 PP Stage 接收"""
        recv_dict = torch.distributed.recv_obj_dict(src=self.prev_pp_rank)
        # 处理接收的数据
        ...
```

### 4.3 PP 通信

```python
# PP Stage 之间的通信
# 使用 PyTorch distributed send/recv

def p2p_communication(
    tensor: torch.Tensor,
    src_rank: int,
    dst_rank: int,
    is_send: bool,
):
    """点对点通信"""
    if is_send:
        torch.distributed.send(tensor, dst=dst_rank)
    else:
        torch.distributed.recv(tensor, src=src_rank)
```

## 五、数据并行 (DP)

### 5.1 原理

数据并行复制整个模型到多个 GPU，每个 GPU 处理不同的请求：

```
请求分发:
┌─────────────────┐
│   Request Queue │
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐ ┌───────┐
│ DP 0  │ │ DP 1  │
│ Full  │ │ Full  │
│ Model │ │ Model │
└───────┘ └───────┘
```

```python
class DataParallelController:
    """数据并行控制器"""

    def __init__(self, server_args: ServerArgs, port_args: PortArgs):
        self.dp_size = server_args.dp_size

        # 启动多个 Scheduler 进程 (每个 DP rank 一个)
        self.schedulers = []
        for dp_rank in range(self.dp_size):
            scheduler = start_scheduler_process(dp_rank=dp_rank, ...)
            self.schedulers.append(scheduler)

        # 请求分发器
        self.request_dispatcher = RequestDispatcher(
            policy=server_args.dp_attention_policy,
        )

    def dispatch_request(self, request):
        """分发请求到 DP rank"""

        # 根据负载均衡策略选择 DP rank
        dp_rank = self.request_dispatcher.select_rank(request)

        # 发送请求
        send_to_scheduler(request, dp_rank)
```

### 5.3 负载均衡策略

```python
class RequestDispatcher:
    """请求分发器"""

    def select_rank(self, request) -> int:
        """选择 DP rank"""

        if self.policy == "round_robin":
            # 轮询
            return self.current_rank % self.dp_size

        elif self.policy == "least_loaded":
            # 选择负载最小的 rank
            loads = [self.get_rank_load(r) for r in range(self.dp_size)]
            return argmin(loads)

        elif self.policy == "random":
            # 随机选择
            return random.randint(0, self.dp_size - 1)
```

### 6.1 原理

MoE (Mixture of Experts) 模型的专家可以分布到不同 GPU：

```
MoE Layer:

│                      Expert Router                           │
│                          │                                   │

│     │  (GPU 0) │  │  (GPU 0) │  │  (GPU 1) │               │
│     └──────────┘  └──────────┘  └──────────┘               │
│           │              │              │                   │
│           └──────────────┼──────────────┘                   │

```

```python
def expert_all2all(
    hidden_states: torch.Tensor,
    router_indices: torch.Tensor,
    ep_group: torch.distributed.ProcessGroup,
):
    """专家并行 All-to-All 通信"""

    # 1. 根据路由索引重排 token
    dispatched = dispatch_tokens(hidden_states, router_indices)

    # 2. All-to-All 发送到对应 expert 所在的 rank
    received = torch.distributed.all_to_all(dispatched, group=ep_group)

    # 3. 每个 rank 处理自己的专家
    expert_output = experts(received)

    # 4. All-to-All 返回
    combined = torch.distributed.all_to_all(expert_output, group=ep_group)

    # 5. 还原 token 顺序
    output = combine_tokens(combined, router_indices)

    return output
```

## 七、上下文并行 (CP)

### 7.1 原理

上下文并行将超长序列的注意力计算分布到多个 GPU，每个 GPU 只存储序列的一个局部切片，但计算全局注意力：

```
序列长度 = 128K, CP Size = 4

GPU 0: Q[0:32K],     K[0:32K],     V[0:32K]
GPU 1: Q[32K:64K],   K[32K:64K],   V[32K:64K]
GPU 2: Q[64K:96K],   K[64K:96K],   V[64K:96K]
GPU 3: Q[96K:128K],  K[96K:128K],  V[96K:128K]

Q 只保留本地切片，K/V 通过 Ring 通信依次传递给所有 rank，
每个 rank 逐步计算本地 Q 与全局 K/V 的注意力。
```

### 7.2 Ring Attention 实现

**文件位置**：`python/sglang/srt/layers/dp_attention.py`

标准 AllGather CP 需要将完整的 K/V 收集到每个 GPU，显存占用为 O(seq_len × hidden_size × cp_size)，在长序列下不可接受。**Ring Attention**（或 Striped/RoPE-aware Ring Attention）将显存降低到 O(seq_len / cp_size × hidden_size)：

```
Ring Attention Schedule:
Step 0: GPU 0 计算 Q0·K0, GPU 1 计算 Q1·K1, ...
Step 1: K/V 向右轮转: GPU 0 收到 K1, 计算 Q0·K1
Step 2: K/V 继续轮转: GPU 0 收到 K2, 计算 Q0·K2
...
Step N-1: 所有 rank 都计算了本地 Q 与全部 K/V partition 的注意力

通信与计算重叠：下一次 K/V 传输与当前注意力 Softmax 计算并行
```

```python
def context_parallel_attention_ring(
    q: torch.Tensor,       # [local_seq_len, num_heads, head_dim]
    k: torch.Tensor,       # [local_seq_len, num_kv_heads, head_dim]
    v: torch.Tensor,       # [local_seq_len, num_kv_heads, head_dim]
    cp_group: torch.distributed.ProcessGroup,
    cp_size: int,
):
    """Ring Attention 实现"""

    # 使用在线 Softmax 合并局部结果
    # 不需要一次性收集所有 K/V
    local_output, local_sum, local_max = attention_online_softmax(q, k, v)

    for _ in range(cp_size - 1):
        # 异步发送当前 K/V 给下一个 rank，同时接收前一个 rank 的 K/V
        recv_k, recv_v = ring_p2p_communication(k, v, cp_group)

        # 计算本地 Q 与轮转来的 K/V 的注意力
        part_output, part_sum, part_max = attention_online_softmax(q, recv_k, recv_v)

        # 使用在线 Softmax 规则合并结果
        local_output, local_sum, local_max = merge_online_softmax(
            local_output, local_sum, local_max,
            part_output, part_sum, part_max,
        )

        k, v = recv_k, recv_v

    return local_output
```

### 7.3 通信开销分析

标准 Self-Attention 的 FLOPs 为 O(batch × seq_len² × hidden_size)。CP 将序列分到 cp_size 个 rank：

| 指标 | 无 CP | CP (AllGather) | CP (Ring) |
|-----|-------|----------------|-----------|
| 单卡 KV 显存 | O(S×H) | O(S×H) | O(S/cp_size × H) |
| 通信量/步 | 0 | O(S×H×(cp_size-1)) | O(S/cp_size × H × 2) |
| 是否可与计算重叠 | - | 否 | 是 |
| 适用场景 | 短序列 < 32K | 中序列 32K-64K | 超长序列 > 64K |

其中 S=seq_len, H=hidden_size。

## 八、分离式推理 (Disaggregation)

### 8.1 原理

将 Prefill 和 Decode 分离到不同节点，实现更好的资源利用率：

```
传统模式 (Prefill + Decode 在同一节点):
┌─────────────────────────────────────────────────────────────────────────────┐
│                              Single Node                                     │
│  ┌────────────────────┐          ┌────────────────────┐                     │
│  │      Prefill       │  → KV →  │      Decode        │                     │
│  │  (计算密集型)       │  Transfer │  (内存密集型)      │                     │
│  │  GPU利用率高        │          │  GPU利用率低        │                     │
│  └────────────────────┘          └────────────────────┘                     │
│                                                                             │
│  问题: Decode 阶段 GPU 大部分时间空闲                                         │
└─────────────────────────────────────────────────────────────────────────────┘

分离式推理:
┌────────────────────────────┐          ┌────────────────────────────┐
│       Prefill Node         │          │       Decode Node          │
│  ┌────────────────────┐   │   KV     │  ┌────────────────────┐    │
│  │      Prefill       │   │ Transfer │  │      Decode        │    │
│  │  高计算负载         │ ─────────► │  │  低计算负载         │    │
│  │  高 GPU 利用率      │           │  │  可服务更多请求      │    │
│  └────────────────────┘   │          │  └────────────────────┘    │
└────────────────────────────┘          └────────────────────────────┘
```

### 8.2 实现架构

**文件位置**：`python/sglang/srt/disaggregation/`

```python
# Prefill 节点模式
class SchedulerDisaggregationPrefillMixin:
    """Prefill 节点调度"""

    def event_loop_disagg_prefill(self):
        """Prefill 事件循环"""
        while True:
            # 1. 接收请求
            recv_reqs = self.recv_requests()
            self.process_input_requests(recv_reqs)

            # 2. 执行 Prefill
            batch = self.get_next_batch_to_run()
            if batch:
                result = self.run_batch(batch)

                # 3. 发送 KV Cache 到 Decode 节点
                self.send_kv_cache(batch, result)


# Decode 节点模式
class SchedulerDisaggregationDecodeMixin:
    """Decode 节点调度"""

    def event_loop_disagg_decode(self):
        """Decode 事件循环"""
        while True:
            # 1. 接收 KV Cache
            kv_transfers = self.recv_kv_cache()

            # 2. 将 KV Cache 放入内存池
            for transfer in kv_transfers:
                self.install_kv_cache(transfer)

            # 3. 执行 Decode
            batch = self.get_next_batch_to_run()
            if batch:
                result = self.run_batch(batch)
                self.process_batch_result(batch, result)
```

## 九、分布式初始化

### 9.1 初始化流程

**文件位置**：`python/sglang/srt/distributed/`

```python
def init_distributed_environment(
    tp_size: int,
    pp_size: int,
    dp_size: int,
    world_size: int,
    rank: int,
):
    """初始化分布式环境"""

    # 初始化 PyTorch distributed
    torch.distributed.init_process_group(
        backend="nccl",
        world_size=world_size,
        rank=rank,
    )

    # 创建各种并行组
    initialize_model_parallel(
        tensor_model_parallel_size=tp_size,
        pipeline_model_parallel_size=pp_size,
        data_parallel_size=dp_size,
    )


def initialize_model_parallel(
    tensor_model_parallel_size: int,
    pipeline_model_parallel_size: int,
    data_parallel_size: int,
):
    """初始化模型并行组"""

    world_size = torch.distributed.get_world_size()

    # 计算各维度
    num_tensor_model_parallel_groups = world_size // tensor_model_parallel_size
    num_pipeline_model_parallel_groups = world_size // pipeline_model_parallel_size
    num_data_parallel_groups = world_size // data_parallel_size

    # 创建 TP 组
    for i in range(num_tensor_model_parallel_groups):
        ranks = list(range(
            i * tensor_model_parallel_size,
            (i + 1) * tensor_model_parallel_size,
        ))
        group = torch.distributed.new_group(ranks)
        # 保存到全局状态

    # 创建 PP 组
    for i in range(num_pipeline_model_parallel_groups):
        ranks = list(range(i, world_size, num_pipeline_model_parallel_groups))
        group = torch.distributed.new_group(ranks)

    # 创建 DP 组
    for i in range(num_data_parallel_groups):
        ranks = list(range(i, world_size, num_data_parallel_groups))
        group = torch.distributed.new_group(ranks)
```

## 十、总结

### 10.1 策略选择指南

| 场景 | 推荐配置 | 说明 |
|------|----------|------|
| 单机8卡 | tp_size=8 | 充分利用 NVLink |
| 单机4卡，显存不足 | tp_size=2, pp_size=2 | 平衡通信与显存 |
| 多机推理 | tp_size=8, pp_size=N | 跨节点 PP 减少通信 |
| 高吞吐服务 | dp_size=N | 复制模型处理更多请求 |
| MoE 模型 | tp_size=4, ep_size=2 | 专家分布到不同 GPU |
| 超长序列 | cp_size=4 | 分割序列长度 |
| 低延迟服务 | Disaggregation | Prefill/Decode 分离 |

### 10.2 通信开销对比

| 策略 | 主要通信 | 通信量 |
|------|----------|--------|
| TP | AllReduce | O(hidden_size × batch_size) |
| PP | P2P | O(hidden_size × batch_size) |
| DP | 无 (独立请求) | 0 |
| EP | All-to-All | O(tokens × hidden_size) |
| CP | AllGather | O(seq_len × hidden_size) |
