## 1. 模块概述

### 1.1 PipelineEngine 核心职责

`PipelineEngine` 是 nanotron 流水线并行的调度引擎，负责协调多个微批次（micro-batches）在流水线各阶段（stages）之间的执行顺序。

```python
# src/nanotron/parallel/pipeline_parallel/engine.py
class PipelineEngine(ABC):
    def __init__(self):
        self.nb_microbatches: Optional[int] = None

    @abstractmethod
    def train_batch_iter(
        self,
        model: torch_nn.Module,
        pg: ProcessGroup,
        batch: Iterable[Dict[str, Union[torch.Tensor, TensorPointer]]],
        nb_microbatches: int,
        grad_accumulator: Optional[GradientAccumulator],
    ) -> Iterable[Dict[str, Union[torch.Tensor, TensorPointer]]]:
        """核心训练迭代接口，子类实现不同调度策略"""
        ...
```

**核心职责：**
1. **前向传播调度** - 控制微批次在各 stage 的前向执行顺序
2. **反向传播调度** - 协调梯度回传的时机和顺序
3. **通信管理** - 通过 `PipelineTrainBatchState` 管理跨 stage 的张量传输
4. **激活值管理** - 维护需要反向传播的激活值队列

### 1.2 1F1B vs AFAB 调度策略对比

nanotron 实现了两种流水线调度引擎：

| 特性 | `AllForwardAllBackwardPipelineEngine` (AFAB) | `OneForwardOneBackwardPipelineEngine` (1F1B) |
|------|-----------------------------------------------|----------------------------------------------|
| **执行模式** | 先执行所有微批次前向，再执行所有反向 | 1个前向后立即执行1个反向 |
| **峰值显存** | 高（需保存所有微批次激活值） | 低（仅保存部分激活值） |
| **流水线气泡** | 大（全文空闲等待） | 小（持续满负荷运行） |
| **适用场景** | 调试、小batch | 大规模训练、显存受限 |
| **微批次限制** | 无特殊限制 | `nb_microbatches >= pp_size - 1` |

**1F1B优势解析：**
- **显存效率高**：采用 "来一个回一个" 策略，及时释放已反向完成的激活值
- **计算通信重叠**：通过精心设计的时序，实现前向计算与梯度通信重叠
- **参考论文**：《Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM》（arxiv:2104.04473）

## 3. Pipeline 训练流程

### 3.1 三阶段执行模型（1F1B）

```python
# src/nanotron/parallel/pipeline_parallel/engine.py:242-348
class OneForwardOneBackwardPipelineEngine(PipelineEngine):
    def train_batch_iter(self, model, pg, batch, nb_microbatches, grad_accumulator):
        state = PipelineTrainBatchState()
        outputs = []
        batch = iter(batch)
        current_pp_rank = dist.get_rank(pg)

        with attach_pipeline_state_to_model(model=model, pipeline_state=state):
            # ═══════════════════════════════════════════════════════════════
            # STAGE 1: Warmup Phase (预热阶段)
            # ═══════════════════════════════════════════════════════════════
            # 高rank stage先执行足够的前向，为后续1F1B创造条件
            # 执行次数 = pg.size() - current_pp_rank - 1
            for _ in range(pg.size() - current_pp_rank - 1):
                micro_batch = next(batch)
                output = self.forward(..., micro_batch, model)
                outputs.append(output)
                # 发送激活值给下游stage
                flush_activation_sends(state)

            # ═══════════════════════════════════════════════════════════════
            # STAGE 2: 1F1B Steady State (稳定阶段 - 核心)
            # ═══════════════════════════════════════════════════════════════
            # 1个前向 + 1个反向交替执行，保持流水线满负荷
            for micro_batch in batch:
                # 前向
                output = self.forward(..., micro_batch, model)
                outputs.append(output)

                # 立即反向（1F1B核心：快速释放激活值占用的显存）
                self.backward(..., state, grad_accumulator)

            # ═══════════════════════════════════════════════════════════════
            # STAGE 3: Cooldown Phase (冷却阶段)
            # ═══════════════════════════════════════════════════════════════
            # 完成剩余所有反向传播
            # 此时剩余反向数 = pg.size() - current_pp_rank - 1
            for _ in range(len(state.microbatches_activations_requiring_backward)):
                self.backward(..., state, grad_accumulator)
                flush_grad_sends(state)

            state.check_buffers_empty()
            return outputs
```

### 3.2 各阶段详细说明

#### Warmup 阶段

```
计算每个rank需要执行的warmup步数：
┌────────────────────────────────────────────────────────┐
│  Rank 0: pp_size - 0 - 1 = 2 warmup forwards          │
│  Rank 1: pp_size - 1 - 1 = 1 warmup forward           │
│  Rank 2: pp_size - 2 - 1 = 0 warmup forward (最早进入1F1B) │
└────────────────────────────────────────────────────────┘

时间线 (3 stages, 4 microbatches):
───────────────────────────────────────────────────────────>
Rank 0: [F0] [F1] ────────────────── [B3] [B2] [B1] [B0]
Rank 1: ────── [F1] [F2] ──────────────── [B2] [B1] [B0]
Rank 2: ──────────── [F2] [F3] [B3] [B2] [B1] [B0]

Warmup目的：让高rank stage提前"填满"激活值队列，
为后续1F1B循环中：前向产激活、反向消费激活 建立平衡
```

#### 1F1B Steady 阶段

```python
def forward(self, context, state, micro_batch, model):
    """单个微批次前向传播"""
    state.nb_forwards += 1
    state.new_micro_batch_forward()  # 标记新微批次开始，创建激活值槽位

    with context:
        output = model(**micro_batch)

    # 损失归一化（除以微批次数量）
    if not isinstance(output["loss"], TensorPointer):
        output["loss"] = output["loss"] / self.nb_microbatches

    # 注册需要反向传播的激活值
    if not isinstance(output["loss"], TensorPointer):
        assert output["loss"].requires_grad
        state.register_activation_requiring_backward(output["loss"])
    return output

def backward(self, context, state, grad_accumulator):
    """单个微批次反向传播"""
    state.nb_backwards += 1

    # 取出最早注册、现在应该反向的激活值
    activations = state.pop_last_activations_requiring_backward()
    if len(activations) == 0:
        return

    with context:
        if grad_accumulator is None:
            sum(activations).backward()
        else:
            grad_accumulator.backward(sum(activations))  # 支持梯度累加
```

## 4. P2P 通信机制

### 4.1 P2P 类核心实现

```python
# src/nanotron/parallel/pipeline_parallel/p2p.py
class P2P:
    def __init__(self, pg: dist.ProcessGroup, device: torch.device):
        self.pg = pg
        self.device = device
        # 预分配元数据缓冲区，避免重复分配
        self.first_metadata = torch.empty(FIRST_METADATA_SIZE, dtype=torch.long, device=device)
        self.second_metadata = torch.empty(SECOND_METADATA_SIZE, dtype=torch.long, device=device)

    # ═══════════════════════════════════════════════════════════════
    # 异步通信接口（训练用）
    # ═══════════════════════════════════════════════════════════════
    def isend_tensors(self, tensors: List[torch.Tensor], to_rank: int, tag: int = 0) -> List[dist.Work]:
        """非阻塞发送一组张量"""
        futures = []
        for tensor in tensors:
            if to_rank != current_rank:
                self._send_meta(tensor, to_rank=to_rank, tag=tag)
                buffer = view_as_contiguous(tensor) if not tensor.is_contiguous() else tensor
                buffer = torch.view_as_real(buffer) if buffer.is_complex() else buffer
                futures.append(dist.isend(buffer, dst=global_rank, group=self.pg, tag=tag))
        return futures

    def irecv_tensors(self, num_tensors: int, from_rank: int, tag: int = 0):
        """非阻塞接收一组张量，返回 (buffers, futures)"""
        buffers = []
        futures = []
        for _ in range(num_tensors):
            meta = self._recv_meta(from_rank=from_rank, tag=tag)
            buffer = meta.create_empty_storage(device=self.device)
            futures.append(dist.irecv(buffer, src=global_rank, group=self.pg, tag=tag))
            buffer = meta.reshape(buffer)  # 应用原始shape/stride
            buffers.append(buffer)
        return buffers, futures
    # ═══════════════════════════════════════════════════════════════
    # 同步通信接口（验证/推理用）
    # ═══════════════════════════════════════════════════════════════
    def send_tensors(self, tensors, to_rank, tag=0):
        futures = self.isend_tensors(tensors, to_rank, tag)
        for future in futures:
            future.wait()  # 立即同步等待

    def recv_tensors(self, num_tensors, from_rank, tag=0):
        buffers, futures = self.irecv_tensors(num_tensors, from_rank, tag)
        for future in futures:
            future.wait()
        return buffers
```

### 4.2 张量元数据协议

通信前需要先交换元数据，接收方根据元数据预分配显存：

```python
@dataclasses.dataclass
class P2PTensorMetaData:
    shape: Sequence[int]           # 张量形状
    stride: Sequence[int]          # 张量步幅
    is_contiguous: bool            # 是否连续存储
    untyped_storage_size: int      # 底层存储大小
    storage_offset: int            # 存储偏移
    dtype: torch.dtype             # 数据类型
    requires_grad: bool            # 是否需要梯度

    def create_empty_storage(self, device: torch.device) -> torch.Tensor:
        """根据元数据在接收方创建同样大小的空张量"""
        buffer = torch.empty(
            size=(self.untyped_storage_size,),
            dtype=torch.int8,
            device=device
        ).view(dtype=self.dtype)
        buffer.requires_grad = self.requires_grad
        return buffer

    @staticmethod
    def to_first_metadata(tensor: torch.Tensor, device: torch.device) -> torch.Tensor:
        """将张量元数据编码为7个int64值"""
        return torch.tensor([
            len(tensor.shape),              # 维度数
            len(tensor.stride()),           # stride长度
            IS_CONTIGUOUS_TO_ID[tensor.is_contiguous()],
            get_untyped_storage(tensor).size(),  # 存储大小
            tensor.storage_offset(),        # 存储偏移
            DTYPE_TO_ID[tensor.dtype],      # 类型ID
            REQUIRES_GRAD_TO_ID[tensor.requires_grad],
        ], dtype=torch.long, device=device)
```

### 4.3 批量通信优化（BatchTensorSendRecvState）

```python
# 用于批量处理多个send/recv操作，减少同步开销
class BatchTensorSendRecvState:
    def __init__(self, p2p: P2P):
        self.p2p = p2p
        self.first_metadata_p2p_ops: List[dist.P2POp] = []
        self.second_metadata_p2p_ops: List[dist.P2POp] = []
        self.data_p2p_ops: List[dist.P2POp] = []
        ...

    def flush(self) -> List[torch.Tensor]:
        """执行所有累积的P2P操作，分三阶段进行：
        1. _send_recv_first_metadata()  - 交换基本元数据
        2. _send_recv_second_metadata() - 交换shape/stride
        3. _send_recv_data()            - 交换实际张量数据
        """
        # 使用 dist.batch_isend_irecv 批量执行，提升吞吐
        reqs = dist.batch_isend_irecv(self.first_metadata_p2p_ops + recv_ops)
        for req in reqs:
            req.wait()
```

### 4.4 TensorPointer 设计原理

```python
# src/nanotron/parallel/pipeline_parallel/tensor_pointer.py
@dataclasses.dataclass
class TensorPointer:
    """张量引用标记 - "谁持有这个张量的实际数据"

    设计背景：
    - PipelineBlock 可能分布在不同rank
    - 但所有rank的模型结构定义是完整的（只是未实例化本rank不负责的layers）
    - 需要在不持有实际数据的情况下 "传递" 张量引用

    工作流程：
    1. Rank 0 计算得到 hidden_states -> 但它知道下一步的 PipelineBlock 在 Rank 1
    2. 返回 {hidden_states: TensorPointer(group_rank=1)} 而非实际张量
    3. Rank 1 的 PipelineBlock 检查到输入是 TensorPointer，从 group_rank 发起 recv
    4. Rank 0 的 PipelineBlock 同时也发起了 send
    """
    group_rank: int  # 持有实际数据的rank编号
```

## 5. 激活值管理

### 5.1 PipelineTrainBatchState 状态机

```python
# src/nanotron/parallel/pipeline_parallel/state.py
@dataclasses.dataclass
class PipelineTrainBatchState(PipelineBatchState):
    # 通信队列 - FIFO顺序保证时序正确
    microbatches_activations_to_send: collections.deque  # 待发送激活值
    microbatches_activations_to_recv: collections.deque  # 待接收激活值
    microbatches_grads_to_send: collections.deque        # 待发送梯度
    microbatches_grads_to_recv: collections.deque        # 待接收梯度

    # 激活值管理 - 按微批次分层
    microbatches_activations_requiring_backward: collections.deque  # 队列的队列

    # 缓冲区 - 接收端临时存储
    activations_buffer: collections.deque   # 接收的激活值
    grads_buffer: collections.deque         # 接收的梯度

    # 计数器
    nb_backwards: int = 0
    nb_forwards: int = 0
```

**队列结构示意：**

```
microbatches_activations_requiring_backward (当前有3个微批次在"飞行中")
┌────────────────────────────────────────────────────────────────────────┐
│ batch_0_activations    batch_1_activations    batch_2_activations      │
│ ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐       │
│ │ loss_micro_0    │   │ loss_micro_1    │   │ loss_micro_2    │       │
│ │ intermediate_0  │   │ intermediate_1  │   │ intermediate_2  │       │
│ └─────────────────┘   └─────────────────┘   └─────────────────┘       │
│        ↑                                                              │
│      popleft() - 最早进入的要最先反向（FIFO）                          │
└────────────────────────────────────────────────────────────────────────┘
```

### 5.2 激活值生命周期

```python
def new_micro_batch_forward(self):
    """开启新微批次，创建该微批次的激活值槽位"""
    self.microbatches_activations_requiring_backward.append(collections.deque())

def register_activation_requiring_backward(self, activation: torch.Tensor):
    """注册需要反向传播的激活值到当前微批次"""
    # -1 表示添加到最新（当前）微批次
    self.microbatches_activations_requiring_backward[-1].append(activation)

def pop_last_activations_requiring_backward(self) -> List[torch.Tensor]:
    """取出最早微批次的所有激活值进行反向"""
    return self.microbatches_activations_requiring_backward.popleft()
```

### 5.3 通信时序控制

```python
def run_communication(self, send_only_activation: bool = False):
    """严格控制的通信顺序，避免死锁

    通信优先级：
    1. 发送激活值（send_activation）
    2. 接收激活值（recv_activation）
    3. 发送梯度     （send_grad）
    4. 接收梯度     （recv_grad）
    """
    # 1. 先发送本stage计算完的激活值给下游
    if len(self.microbatches_activations_to_send) > 0:
        send_activation = self.microbatches_activations_to_send.popleft()
        send_activation()  # 执行P2P发送

    # 2. 接收来自上游的激活值
    if len(self.microbatches_activations_to_recv) > 0:
        recv_activation = self.microbatches_activations_to_recv.popleft()
        recv_tensor = recv_activation()
        self.activations_buffer.append(recv_tensor)

    # 3. 发送本stage计算完的梯度回传
    if len(self.microbatches_grads_to_send) > 0:
        send_grad = self.microbatches_grads_to_send.popleft()
        send_grad()

    # 4. 接收来自下游的梯度
    if len(self.microbatches_grads_to_recv) > 0:
        recv_grad = self.microbatches_grads_to_recv.popleft()
        self.grads_buffer.append(recv_grad())
```

```python
    """并行配置参数

    Args:
        dp: Data Parallel 并行度（数据副本数）
        pp: Pipeline Parallel 并行度（stage数）
        tp: Tensor Parallel 并行度（每个layer内部分割）
        pp_engine: 流水线调度引擎 ("1f1b" | "afab")
        recompute_layer: 是否使用激活值重计算节省显存
    """
    dp: int
    pp: int
    tp: int
    pp_engine: Optional[PipelineEngine] = None  # 默认 AllForwardAllBackwardPipelineEngine
    recompute_layer: bool = False                # 默认 False

# 配置示例 (YAML)
"""
parallelism:
  dp: 2            # 2个数据并行副本
  pp: 4            # 4个流水线stage
  tp: 2            # 每个layer张量并行2路

```

```python
def cast_str_to_pipeline_engine(str_pp_engine: str) -> PipelineEngine:
```

## 7. 常见问题

### 7.1 流水线气泡（Pipeline Bubble）优化

**问题描述：**
流水线气泡指GPU空闲等待的时间。传统 AFAB（GPipe）策略存在大量空闲时间。

**1F1B 优化原理：**

```
【GPipe/AFAB 气泡问题】
┌────────┬────────┬────────┬────────────────────────────────────────┐
│ Stage0 │ FFFF   │  (idle)│                   BBBB                 │
│ Stage1 │ (idle) │   FFFF │  (idle)                BBBB            │
│ Stage2 │ (idle) │  (idle)│    FFFF  (idle)             BBBB       │
└────────┴────────┴────────┴────────────────────────────────────────┘
         F=Forward, B=Backward, 大段空闲 = 气泡

【1F1B 优化效果】
┌────────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬──────────┐
│ Stage0 │F0  │F1  │F2  │B0  │B1  │B2  │    F/B 交错几乎无空闲    │
│ Stage1 │    │F0  │F1  │F2  │B0  │B1  │B2  │                         │
│ Stage2 │    │    │F0  │F1  │F2  │B0  │B1  │B2  │                    │
└────────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴──────────┘
```

**关键条件：**
```python
# 微批次数量必须足够填满流水线
nb_microbatches >= pp_size - 1

# 计算示例：
# pp=4, microbatches=3 时仅能部分填充
# pp=4, microbatches=8 时可实现理想1F1B流水线
```

### 7.2 内存管理策略对比

| 策略 | 原理 | 峰值显存 | 计算开销 |
|------|------|----------|----------|
| **全缓存（AFAB）** | 保存所有微批次激活值 | O(M × L × H) | 1x |
| **1F1B** | 用 FIFO 队列管理，及时释放 | O(PP × L × H) | 1x |
| **激活值重计算** | 反向时重新计算激活值 | O(L × H) | 1.33x |

> M = microbatches, L = layers per stage, H = hidden size, PP = pipeline stages

### 7.3 配置检查清单

```python
# 启动前建议做以下检查：

def check_pipeline_config(pp_size, num_microbatches, hidden_size, num_layers):
    # 1. 微批次数量检查
    assert num_microbatches >= pp_size - 1, f"1F1B需要 at least {pp_size-1} microbatches"

    # 2. 层数可被PP整除（或者使用虚拟stage）
    assert num_layers % pp_size == 0, "建议每stage层数相等"
    layers_per_stage = num_layers // pp_size

    # 3. 显存估算（粗略）
    activation_per_layer = 4 * hidden_size * 1024  # seq_len=1024 为例
    peak_memory_1f1b = pp_size * layers_per_stage * activation_per_layer
    peak_memory_afab = num_microbatches * layers_per_stage * activation_per_layer

    return {
        "layers_per_stage": layers_per_stage,
        "peak_memory_1f1b_gb": peak_memory_1f1b / 1e9,
        "peak_memory_afab_gb": peak_memory_afab / 1e9,
    }

# 示例：7B模型，pp=4, microbatches=8
# layers=32, hidden=4096
# 1F1B峰值显存：约 4 * 8 * 4 * 4096 * 1024 * 4 bytes = 2GB per GPU (仅考虑激活值)
```

## 附录：完整的 1F1B 执行时序图

```
【4个Stage，8个Microbatches 的完整1F1B时序】

时间 ────────────────────────────────────────────────────────────────────────>

PP Rank 0 (最早完成):
    [F0] [F1] [F2] [F3] [B0] [B1] [B2] [B3] [B4] [B5] [B6] [B7]
    │ warmup:3 │    1F1B steady    │          cooldown:5          │
    └──────────┴───────────────────┴──────────────────────────────┘

PP Rank 1:
         [F0] [F1] [F2] [F3] [F4] [B0] [B1] [B2] [B3] [B4] [B5] [B6] [B7]
         │ warmup:2 │       1F1B steady         │    cooldown:6     │

PP Rank 2:
              [F0] [F1] [F2] [F3] [F4] [F5] [B0] [B1] [B2] [B3] [B4] [B5] [B6] [B7]
              │ warmup:1 │          1F1B steady            │  cooldown:7   │

PP Rank 3 (最晚开始，最早进入steady):
                   [F0] [F1] [F2] [F3] [F4] [F5] [F6] [B0] [B1] [B2] [B3] [B4] [B5] [B6] [B7]
                   │       warmup:0 (直接进入1F1B)        │       cooldown:8        │

关键规律：
- Warmup 步数 = PP_SIZE - current_pp_rank - 1
- Cooldown 步数 = current_pp_rank + 1
- Steady 步数 = num_microbatches - (PP_SIZE - 1)
- 总步数 = num_microbatches (前向) + num_microbatches (反向) = 2 * num_microbatches
- 理想情况下，当 num_microbatches >> PP_SIZE 时，逼近 100% GPU利用率
```
