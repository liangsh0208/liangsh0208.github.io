# 04_上下文并行CP

## 1. 目标论证

**为什么需要 Context Parallel？**

Attention计算复杂度O(n²)随序列长度急剧增加：
- 32K序列的注意力激活: 32K × 32K × 4bytes = 4GB(单头)
- 64K序列: 16GB - 超出单A100显存
- Ring Attention支持百万级token序列训练

**核心洞察：**
- Flash Attention的blockwise计算特性允许分块聚合
- 不需要完整的QK^T矩阵，可以增量计算softmax

## 2. 工作假设

**序列约束：**
- `seq_length % cp_size == 0` (序列能被CP进程数整除)
- 每个CP rank处理 `seq_len // cp_size` 个位置

**因果模式支持：**
- 因果注意力: 每个位置只能看到之前和当前位置的token
- 非因果: 双向注意力(Encoder场景)

## 3. 解决方案

### 3.1 Ring Attention核心思想

```
CP Rank 0: [Q0, K0, V0] ←── K1,V1 ──→ K2,V2 → ...
               ↓              ↓              ↓
             compute      compute        compute
             block 00     block 01       block 02

CP Rank 1: [Q1, K1, V1] ←── K2,V2 ──→ K0,V0 → ...
               ↓              ↓              ↓
             compute      compute        compute
             block 11     block 12       block 10
```

- 每个rank持有自己的Q块和本地KV块
- KV块沿环传递，与所有Q块计算局部attention
- 使用online softmax合并各块结果

### 3.2 Online Softmax合并

```python
def update_out_and_lse(out, lse, block_out, block_lse):
    """
    合并两个局部attention结果的numerically stable方式
    
    lse: log-sum-exp, 用于数值稳定性
    out: 当前累积的attention输出
    
    新lse = lse + log(1 + exp(block_lse - lse))
    新out = exp(lse - new_lse) * out + exp(block_lse - new_lse) * block_out
    
    等价形式(更稳定):
    """
    # 计算权重
    out_weight = torch.exp(lse - torch.maximum(lse, block_lse))
    block_weight = torch.exp(block_lse - torch.maximum(lse, block_lse))
    
    # 归一化
    new_lse = torch.maximum(lse, block_lse) + torch.log(
        out_weight + block_weight
    )
    new_out = (
        out * torch.exp(lse - new_lse).unsqueeze(-1) +
        block_out * torch.exp(block_lse - new_lse).unsqueeze(-1)
    )
    
    return new_out, new_lse
```

### 3.3 Ring Attention前向实现

```python
class RingAttentionFunc(torch.autograd.Function):
    @staticmethod
    def forward(ctx, q, k, v, sm_scale, is_causal):
        """
        q, k, v: [batch, num_heads, seq_per_cp, head_dim]
        """
        pgm = get_process_group_manager()
        cp_world_size = pgm.cp_world_size
        cp_rank = pgm.cp_rank
        
        # 当前状态
        current_out = torch.zeros_like(q)
        current_lse = torch.full(
            (q.shape[0], q.shape[1], q.shape[2]), 
            float('-inf'), 
            device=q.device
        )
        
        # 环状传递KV
        for step in range(cp_world_size):
            # 提前发送/接收下一个KV(双缓冲)
            if step + 1 != cp_world_size:
                next_k = p2p_send_recv(k, pgm.cp_send_rank, pgm.cp_recv_rank)
                next_v = p2p_send_recv(v, pgm.cp_send_rank, pgm.cp_recv_rank)
                comm.commit()
            
            # 判断此块是否合法(因果模式时)
            # rank处理第i块, 第step步收到的是第(i+step)%world_size块
            block_k_rank = (cp_rank + step) % cp_world_size
            
            if not is_causal or block_k_rank <= cp_rank:
                # 计算局部attention
                block_out, block_lse = ring_attention_forward(
                    q, k, v, sm_scale, is_causal and block_k_rank == cp_rank
                )
                
                # 合并到当前结果
                current_out, current_lse = update_out_and_lse(
                    current_out, current_lse, block_out, block_lse
                )
            
            # 等待通信完成，切换到下一个KV
            if step + 1 != cp_world_size:
                comm.wait()
                k, v = next_k, next_v
        
        ctx.save_for_backward(q, k, v, current_out, current_lse)
        ctx.sm_scale = sm_scale
        ctx.is_causal = is_causal
        
        return current_out
```

### 3.5 应用到模型

```python
def apply_context_parallel(model):
    """
    替换模型的Attention.forward为RingAttention版本
    """
    original_forward = model.forward
    
    def cp_forward(self, hidden_states, ...):
        # 分割序列到各CP rank
        pgm = get_process_group_manager()
        seq_len = hidden_states.shape[1]
        seq_per_rank = seq_len // pgm.cp_world_size
        
        start_idx = pgm.cp_rank * seq_per_rank
        end_idx = start_idx + seq_per_rank
        
        local_hidden = hidden_states[:, start_idx:end_idx, :]
        
        # 计算Q,K,V
        q = self.q_proj(local_hidden).view(...)
        k = self.k_proj(local_hidden).view(...)
        v = self.v_proj(local_hidden).view(...)
        
        # 使用Ring Attention(当CP > 1时)
        if pgm.cp_world_size > 1:
            attn_output = RingAttentionFunc.apply(
                q, k, v, self.sm_scale, self.is_causal
            )
        else:
            # CP=1时使用标准Flash Attention
            attn_output = flash_attn_func(q, k, v, causal=self.is_causal)
        
        # 继续投影和输出...
        return attn_output
    
    model.forward = cp_forward.__get__(model, model.__class__)
```

## 4. 故障模式

| 问题 | 可能原因 | 解决方案 |
|-----|---------|---------|
| `seq_length not divisible by cp_size` | 序列配置错误 | 调整seq_len或cp_size使整除 |
| Online Softmax数值溢出 | lse计算未使用稳定形式 | 检查是否使用 `max - log(sum exp)` |
| 因果注意力结果错误 | 块边界判断错误 | 验证 block_k_rank <= q_rank 条件 |
| Ring通信死锁 | Send/Recv不匹配 | 确保所有rank同时发送和接收 |
| 梯度不对称 | CP反向传播未正确合并 | 在CP组内对梯度额外All-Reduce |
| Attention结果不一致 | Flash Attention版本不匹配 | 统一使用2.5.0+版本 |

### 调试技巧

```python
# 验证Ring结果与标准Attention一致(CP=1时)
# 标准结果
standard_out = flash_attn_func(q, k, v, causal=True)

# Ring结果(单进程模拟)
ring_out = RingAttentionFunc.apply(q, k, v, 1.0, True)

# 对比
torch.allclose(standard_out, ring_out, atol=1e-3)
```
