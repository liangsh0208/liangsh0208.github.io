# SGLang 仓库整体架构介绍

## 一、项目概述

SGLang (Structured Generation Language) 是一个高性能的大语言模型推理框架，专注于提供极低的延迟和高吞吐量。其核心创新包括：

- **RadixAttention**：基于基数树的前缀缓存技术，实现 KV Cache 的高效复用
- **CUDA Graph 优化**：通过图捕获技术减少内核启动开销
- **灵活的调度策略**：支持前缀感知调度、连续批处理等
- **多后端注意力**：支持 FlashInfer、FlashAttention、MLA 等多种注意力实现
- **分布式推理**：支持张量并行(TP)、流水线并行(PP)、数据并行(DP)等多种并行策略

## 三、核心模块架构

### 3.1 多进程架构

SGLang 采用多进程架构，各组件通过 ZMQ 进行进程间通信：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              Engine (主进程)                                 │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │                        TokenizerManager                                │  │
│  │   - 运行在主进程中                                                      │  │
│  │   - 负责请求预处理、分词、多模态数据处理                                   │  │
│  │   - 通过 ZMQ 与 Scheduler 和 Detokenizer 通信                            │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
                    │                                    ▲
                    │ ZMQ PUSH                          │ ZMQ PUSH
                    │ (scheduler_input_ipc)             │ (tokenizer_ipc)
                    ▼                                    │
┌─────────────────────────────────────────────────────────────────────────────┐
│                           Scheduler (子进程)                                 │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │  - 每个 TP rank 一个 Scheduler 进程                                      │  │
│  │  - 管理请求队列、批处理构建、KV Cache 分配                                 │  │
│  │  - 调用 ModelRunner 执行模型推理                                          │  │
│  │  - 包含 RadixCache (基数树缓存)                                          │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
                    │
                    │ ZMQ PUSH
                    │ (detokenizer_ipc)
                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                       DetokenizerManager (子进程)                            │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │  - 负责将输出的 Token ID 转换为文本                                       │  │
│  │  - 实现增量解码，支持流式输出                                             │  │
│  │  - 将结果发送回 TokenizerManager                                         │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 核心数据结构层次

推理过程中数据结构经历以下转换：

```
GenerateReqInput              # 原始请求输入
       │
       ▼
TokenizedGenerateReqInput     # 分词后的请求
       │
       ▼
Req                           # 请求对象 (schedule_batch.py)
       │                      # 包含: rid, origin_input_ids, sampling_params
       │                      #       prefix_indices, output_ids 等
       ▼
ScheduleBatch                 # 调度批次
       │                      # 管理器级别数据，大部分在 CPU
       │                      # 包含: reqs, forward_mode, batch_size 等
       ▼
ModelWorkerBatch              # 模型工作批次
       │                      # TP Worker 和 Model Runner 之间的传递对象
       │                      # 是 ScheduleBatch 的子集
       ▼
ForwardBatch                  # 前向传播批次 (forward_batch_info.py)
       │                      # 底层张量数据，大部分在 GPU
       │                      # 包含: input_ids, positions, seq_lens
       │                      #       req_pool_indices, out_cache_loc 等
       ▼
LogitsProcessorOutput         # Logits 输出
       │
       ▼
Sampled Token IDs             # 采样结果
```

## 四、核心模块详解

### 4.1 SRT 核心运行时 (`python/sglang/srt/`)

SRT (SGLang Runtime) 是推理引擎的核心，包含以下子模块：

|--------|------|----------|

### 4.2 调度器 (`managers/scheduler.py`)

调度器是整个推理流程的核心，负责：

- **请求管理**：接收、排队、优先级排序
- **批处理构建**：PrefillAdder 管理令牌预算
- **KV Cache 分配**：与 RadixCache 协作
- **前向模式管理**：区分 Prefill (EXTEND) 和 Decode
- **连续批处理**：动态添加/移除请求

关键调度循环：
```python
def event_loop_normal(self):
    while True:
        # 1. 接收请求
        recv_reqs = self.recv_requests()
        self.process_input_requests(recv_reqs)

        # 2. 获取下一个批次
        batch = self.get_next_batch_to_run()

        # 3. 执行批次
        if batch:
            result = self.run_batch(batch)
            self.process_batch_result(batch, result)

        # 4. 更新状态
        self.last_batch = batch
```

### 4.3 RadixAttention 缓存系统 (`mem_cache/`)

SGLang 的核心创新是基于基数树的前缀缓存：

```
┌─────────────────────────────────────────────────────────────┐
│                      RadixCache                              │
│  ┌─────────────────────────────────────────────────────────┐│
│  │                    TreeNode 结构                         ││
│  │  ┌─────────┐                                           ││
│  │  │  Root   │                                           ││
│  │  └────┬────┘                                           ││
│  │       │                                                ││
│  │  ┌────┴────┐                                          ││
│  │  │ "Hello" │ key = [token_ids], value = KV indices    ││
│  │  └────┬────┘                                           ││
│  │   ┌───┴───┐                                            ││
│  │   │       │                                            ││
│  │ ┌─┴──┐ ┌──┴──┐                                        ││
│  │ │"World"│"there"│                                      ││
│  │ └─────┘ └─────┘                                        ││
│  └─────────────────────────────────────────────────────────┘│
│                                                             │
│  特性：                                                      │
│  - O(n) 前缀匹配                                            │
│  - 自动节点分裂                                              │
│  - 引用计数防止淘汰                                          │
│  - 多种淘汰策略 (LRU, LFU, FIFO)                            │
└─────────────────────────────────────────────────────────────┘
```

内存池层次：
```
ReqToTokenPool              # [num_reqs, max_context_len]
       │                    # 请求 → Token 位置映射
       ▼
TokenToKVPoolAllocator      # 管理 KV Cache 槽位分配
       │
       ▼
KVCache (MHATokenToKVPool)  # [layer_num][size, head_num, head_dim]
                            # 实际 KV 数据存储
```

## 五、关键配置参数

### 5.1 ServerArgs 核心参数

```python
@dataclass
class ServerArgs:
    # 模型配置
    model_path: str                    # 模型路径
    tokenizer_path: Optional[str]      # 分词器路径
    load_format: str                   # 加载格式 (auto/safetensors/gguf)

    # 并行配置
    tp_size: int = 1                   # 张量并行
    pp_size: int = 1                   # 流水线并行
    dp_size: int = 1                   # 数据并行

    # 内存配置
    mem_fraction_static: float = 0.9   # 静态内存比例
    chunked_prefill_size: int          # 分块 Prefill 大小

    # 调度配置
    schedule_policy: str = "lpm"       # 调度策略 (fcfs/lpm/random)

    # 服务配置
    host: str = "127.0.0.1"
    port: int = 30000
```

### 5.2 调度策略

| 策略 | 描述 | 适用场景 |
|------|------|----------|
| `fcfs` | 先到先服务 | 简单场景 |
| `lpm` | 最长前缀匹配优先 | 高缓存复用场景 |
| `dfs-weight` | 深度优先加权 | 复杂依赖场景 |
| `random` | 随机选择 | 负载均衡测试 |

## 六、并行策略支持

### 6.1 张量并行 (TP)

模型层分片到多个 GPU：
- **Column Parallel Linear**: 按输出维度切分
- **Row Parallel Linear**: 按输入维度切分

### 6.2 流水线并行 (PP)

模型层按层深度切分：
- 不同 GPU 负责不同层
- 微批次流水执行
- 需要 `scheduler_pp_mixin.py` 支持

### 6.3 数据并行 (DP)

请求分流到多个副本：
- `data_parallel_controller.py` 管理多个 Scheduler
- 适合高吞吐场景

### 6.4 分离式推理 (Disaggregation)

Prefill 和 Decode 分离到不同节点：
- `disaggregation/` 模块
- 支持 KV Cache 传输

## 七、扩展模型支持

### 7.1 添加自定义模型

1. 在 `models/` 目录创建模型文件
2. 实现模型类，继承基类
3. 在 `models/__init__.py` 注册模型

### 7.2 添加自定义内核

1. **JIT 内核**：在 `jit_kernel/` 添加，运行时编译
2. **AOT 内核**：在 `sgl-kernel/` 添加，预编译

**文件位置**：`python/sglang/srt/function_call/`

### 8.6 专家负载均衡 (EPLB)

**文件位置**：`python/sglang/srt/eplb/`

### 8.7 硬件后端抽象

**文件位置**：`python/sglang/srt/hardware_backend/`

抽象不同硬件平台的差异，支持 NVIDIA、AMD、Intel GPU/XPU 和 CPU 的统一接入。

### 8.8 批处理不变量与重叠

**文件位置**：`python/sglang/srt/batch_invariant_ops/`、`batch_overlap/`

- **不变量操作**：在调度循环外预处理不随批次变化的常量计算，减少调度开销

## 九、总结

SGLang 的核心设计理念：

1. **缓存优先**：RadixAttention 实现高效前缀复用
2. **异步流水线**：多进程架构 + ZMQ 通信
3. **灵活批处理**：连续批处理 + 分块 Prefill
4. **多后端支持**：可插拔的注意力/采样后端
5. **分布式友好**：原生支持 TP/PP/DP 混合并行
