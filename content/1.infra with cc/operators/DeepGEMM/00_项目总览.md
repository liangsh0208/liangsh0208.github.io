# DeepGEMM 项目总览

> 源码路径：`/deepseek/DeepGEMM/`  
> 版本：v2.4.2（2026-04-16 最新更新）  
> 支持架构：NVIDIA SM90（Hopper H100/H800）、SM100（Blackwell B200）

---

## 1. 项目定位

DeepGEMM 是 DeepSeek 开源的**统一、高性能 Tensor Core kernel 库**，服务于现代大型语言模型推理与训练的核心计算原语：

- **FP8 GEMM**（SM90 & SM100）
- **FP4/FP8 混合精度 GEMM**（SM100）
- **BF16 GEMM**（SM90 & SM100）
- **MoE 分组 GEMM**（Contiguous / Masked 两种布局）
- **Mega MoE**：融合 EP 调度、Linear1（FP8×FP4）、SwiGLU、Linear2（FP8×FP4）、EP 合并的单一 mega-kernel，NVLink 通信与 Tensor Core 计算完全重叠
- **MQA Logits**：DeepSeek v3.2 indexer 专用的 weighted ReLU MQA logits 计算
- **HyperConnection（HC）**：TF32 预归一化 GEMM

**核心设计哲学**：

1. **简洁**：只保留少量核心 kernel 函数，代码易于学习和审计
2. **运行时 JIT 编译**：所有 kernel 在首次调用时通过 NVCC/NVRTC 编译，安装无需 CUDA 编译
3. **不依赖 CUTLASS 重型模板**：借鉴 CUTLASS/CuTe 的概念，但不直接使用其繁琐的模板代数
4. **性能对标专家调优库**：在多种矩阵形状上与 cuBLAS 持平或超越

## 3. 核心功能一览

### 3.1 GEMM Kernel 族

| Kernel 函数 | 数据类型 | 布局 | 架构 |
|-------------|----------|------|------|
| `fp8_gemm_nt/nn/tn/tt` | FP8×FP8→FP32 | 全布局 | SM90 & SM100 |
| `fp8_fp4_gemm_nt/nn/tn/tt` | FP8×FP4→BF16/FP32 | 全布局 | SM100 |
| `bf16_gemm_nt/nn/tn/tt` | BF16×BF16→BF16/FP32 | 全布局 | SM90 & SM100 |
| `m_grouped_fp8_gemm_nt_contiguous` | FP8×FP8 | M 轴分组（连续） | SM90 & SM100 |
| `m_grouped_fp8_gemm_nt_masked` | FP8×FP8 | M 轴分组（masked） | SM90 & SM100 |
| `k_grouped_fp8_gemm_tn_contiguous` | FP8×FP8 | K 轴分组（权重梯度） | SM90 & SM100 |

### 3.2 命名约定

命名格式：`{dtype}_gemm_{layout}`，其中 `layout` 表示 `[A 是否转置][B 是否转置]`：

```
NT = A 不转置，B 转置   →  D = A @ B.T   （最常见：forward pass）
TN = A 转置，  B 不转置  →  D = A.T @ B   （最常见：weight gradient）
NN = A 不转置，B 不转置  →  D = A @ B
TT = A 转置，  B 转置    →  D = A.T @ B.T
```

### 3.3 缩放因子格式差异

| 架构 | SF 数据格式 | 特点 |
|------|-------------|------|
| SM90 | FP32 | 每 128 通道一个 FP32 scale |
| SM100 | 打包 UE8M0（4 个 UE8M0 打包进一个 `torch.int`）| UTCCP 硬件加速 |

## 4. 与 cuBLAS / CUTLASS 对比

| 特性 | cuBLAS/cuBLASLt | CUTLASS | DeepGEMM |
|------|----------------|---------|----------|
| 编程模型 | 黑盒库 API | C++ 模板库 | JIT 编译 + Python API |
| 自定义程度 | 低（预编译） | 高（重型模板） | 中（定制配置枚举） |
| 安装编译 | 不需要 | 需要编译 | 不需要（JIT） |
| FP8 支持 | 有限 | 有（CUTLASS 4.0） | 完整（FP8、FP4、混合） |
| MoE 分组 GEMM | 不支持 | 有（复杂） | 原生支持（Contiguous + Masked） |
| Mega MoE 融合 | 不支持 | 不支持 | 独有 |
| 学习友好性 | 差 | 中 | **高**（代码简洁） |
| H800 峰值性能 | ~1400 TFLOPS | ~1400 TFLOPS | **~1550 TFLOPS** |

DeepGEMM 相对 cuBLASLt 的核心优势：
- **更细粒度的 block size 枚举**：从 M=16 到 M=256、N=8 步长遍历，找到当前矩阵形状最优配置
- **TMA multicast 利用 SM cluster**：减少 L2 带宽消耗
- **编译时常数折叠**：将 M/N/K 编译为常数，使 NVCC 生成更优指令
- **两种不同的 scaling 策略**（1D1D / 1D2D）应对不同精度需求

```
DeepGEMM/

│   │       ├── common/           # 基础工具（TMA 拷贝、数学、类型）
│   │       ├── mma/              # WGMMA / UMMA 封装（SM90/SM100）
│   │       ├── scheduler/        # 持久化 block 调度器
│   │       ├── ptx/              # 内联 PTX 指令（ld/st、tcgen05、wgmma）
│   │       ├── epilogue/         # 输出变换（swizzle、head splits）
│   │       ├── layout/           # 对称内存、Mega MoE 布局
│   │       ├── comm/             # 跨 rank NVLink barrier
│   │       └── impls/            # 完整 kernel 实现（.cuh）
│   ├── mega/                     # Mega MoE Python 封装
│   ├── utils/                    # Python 工具函数（layout、math、dist）
│   ├── testing/                  # 测试辅助工具

│   ├── apis/                     # Python 暴露的高层 API（gemm、attention、layout 等）
│   ├── jit/                      # JIT 编译系统（compiler、cache、runtime）

│   └── utils/                    # C++ 通用工具
```

## 6. 快速上手

```python
import torch
import deep_gemm

# 基础 FP8 GEMM（SM90）
M, N, K = 4096, 4096, 4096
a = torch.randn(M, K, dtype=torch.float8_e4m3fn, device='cuda')
b = torch.randn(N, K, dtype=torch.float8_e4m3fn, device='cuda')
sfa = torch.ones(M, K // 128, dtype=torch.float, device='cuda')  # SM90 要求 FP32 scale
sfb = torch.ones(N, K // 128, dtype=torch.float, device='cuda')
d = torch.empty(M, N, dtype=torch.float, device='cuda')

deep_gemm.fp8_gemm_nt((a, sfa), (b, sfb), d)

# 性能调优工具
deep_gemm.set_num_sms(108)       # 限制使用的 SM 数量
deep_gemm.set_tc_util(80)        # 近似 TC 利用率（用于 config 选择）
deep_gemm.set_pdl(True)          # 启用 Programmatic Dependent Launch
```
