## 1. 分布式并行策略概览

TE 支持的并行策略：

| 策略 | 缩写 | 切分维度 | TE 支持程度 |
|------|------|---------|------------|
| 数据并行 | DP | batch | 通过 PyTorch FSDP/DDP |
| 张量并行 | TP | 权重矩阵 | 原生深度支持 |
| 序列并行 | SP | 序列/batch 维度 | 与 TP 联合支持 |
| 上下文并行 | CP | 序列维度（注意力） | Ring Attention |
| 流水线并行 | PP | 层维度 | 通过 Megatron-Core |
| 全分片数据并行 | FSDP | 参数分片 | FSDP2 原生兼容 |

## 2. 张量并行（Tensor Parallelism）

### 2.1 列并行 Linear（Column Parallel）

将权重矩阵沿输出维度（列）切分：

```
原始权重 W: [in_features, out_features]
TP=4 后：
  GPU 0: W_0 [in_features, out_features/4]
  GPU 1: W_1 [in_features, out_features/4]
  ...

前向：Y_i = X @ W_i          （每 GPU 独立 GEMM）
反向：dX  = AllReduce(dX_i)   （梯度需要汇总）
      dW_i = dY_i^T @ X       （局部权重梯度）
```

```python
# 在 TE 中启用列并行
model = te.Linear(
    4096, 4096,
    parallel_mode="column",
    tensor_parallel_group=tp_group,  # 张量并行通信组
    sequence_parallel=False,
)
```

### 2.2 行并行 Linear（Row Parallel）

将权重矩阵沿输入维度（行）切分：

```
原始权重 W: [in_features, out_features]
TP=4 后：
  GPU 0: W_0 [in_features/4, out_features]
  ...

前向：
  输入需要 AllGather：X_full = AllGather(X_i)（或 X 已经分片）
  局部 GEMM：Y_i = X_i @ W_i
  结果 AllReduce：Y = AllReduce(Y_i)

序列并行时 AllReduce 改为 ReduceScatter：
  Y_scatter = ReduceScatter(Y_i)   → 每 GPU 持有一部分输出
```

```python
model = te.Linear(
    4096, 4096,
    parallel_mode="row",
    tensor_parallel_group=tp_group,
    sequence_parallel=True,   # 使用 ReduceScatter 替代 AllReduce
)
```

### 2.3 标准 TP 模式下的 MLP

```
输入 x [S, B, H]（每 GPU 持有完整）
  ↓ AllGather（SP 模式下，从分片 x 恢复完整）
LayerNorm
  ↓
FC1（列并行）: [S*B, H] @ [H, 4H/tp] → [S*B, 4H/tp]
  ↓ 激活（每 GPU 独立）
FC2（行并行）: [S*B, 4H/tp] @ [4H/tp, H] → [S*B, H]（局部和）
  ↓ AllReduce 或 ReduceScatter（SP 模式）
输出（每 GPU 持有完整或分片）
```

## 3. 序列并行（Sequence Parallelism）

序列并行将 SP 维度（sequence 或 batch）切分到各 TP rank，降低非张量并行算子（LayerNorm、Dropout）的显存。

### 3.1 通信模式变化

```
标准 TP 模式：
  AllGather（列并行前） → 局部 GEMM → AllReduce（行并行后）

序列并行模式：
  AllGather（列并行前） → 局部 GEMM → ReduceScatter（行并行后）

效果：
  - AllGather 将分片 token 聚合为完整序列（列并行需要完整 X）
  - ReduceScatter 将结果求和后重新分片（SP 后续层只需分片）
  - 非 GEMM 层（LN、Dropout）始终只处理 1/tp 的序列 → 显存节省 tp 倍
```

```python
# 在 TransformerLayer 中启用序列并行
layer = te.TransformerLayer(
    hidden_size=4096,
    ffn_hidden_size=16384,
    num_attention_heads=32,
    set_parallel_mode=True,
    tp_group=tp_group,
    sequence_parallel=True,   # 开启
)
```

## 4. 通信-GEMM 重叠（UserBuffers）

这是 TE 最有特色的分布式优化，将 AllGather/ReduceScatter 通信与 GEMM 计算完全重叠。

### 4.1 原理

标准流程（串行）：
```
AllGather(X_shard) → X_full [通信等待]
GEMM(X_full, W)    → Y      [计算等待]
```

重叠流程：
```
将 X_full 分为 tp 个分片：X_0, X_1, ..., X_{tp-1}

时间轴：
  t0: 触发 AllGather(X_0)  [从 GPU 0 取 X_0]
  t1: GEMM(X_0, W_0) + AllGather(X_1)（重叠）
  t2: GEMM(X_1, W_1) + AllGather(X_2)（重叠）
  ...
  
最终结果是所有分片 GEMM 的叠加，等价于完整 GEMM
```

### 4.2 UserBuffers 初始化

```python
from transformer_engine.pytorch.module import initialize_ub, destroy_ub

# 训练前初始化 UserBuffers
initialize_ub(
    shape=[batch_size * seq_len, hidden_size],  # 最大 tensor 形状
    tp_size=tensor_parallel_size,
    use_fp8=True,                               # 通信缓冲区使用 FP8
    dtype=torch.bfloat16,
    ub_cfgs={
        "fc1_fprop": {"method": "ag"},      # AllGather 重叠
        "fc2_dgrad": {"method": "ag"},
        "fc1_dgrad": {"method": "rs"},      # ReduceScatter 重叠
        "fc2_fprop": {"method": "rs"},
    }
)

# 训练结束后清理
destroy_ub()
```

```cpp

// 核心：注册共享内存区域（NVLink 或 NVSwitch 直接访问）
// 不经过 NCCL，直接 GPU-to-GPU 写入

class UBufCommOverlap {
```

UserBuffers 要求：
- NVLink 或 NVSwitch 连接（PCIe 效果有限）
- 所有 TP rank 在同一台机器（或高速互联机器）上
- 激活内存需要额外 2× 的缓冲

## 5. FSDP 兼容

TE 模块完全支持 PyTorch FSDP（Fully Sharded Data Parallel）：

### 5.1 FSDP1（旧版）

```python
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP

model = FSDP(
    te.TransformerLayer(...),
    mixed_precision=MixedPrecision(
        param_dtype=torch.bfloat16,
        reduce_dtype=torch.float32,
    ),
)
```

### 5.2 FSDP2（推荐）

FSDP2 与 TE 的 Float8Tensor 深度集成：

```python
from torch.distributed._composable.fsdp import fully_shard

model = te.TransformerLayer(...)
fully_shard(model)  # Float8Tensor 权重在分片/聚合时保持 FP8 格式

# Float8Tensor 注册了 FSDP2 所需的 aten 算子：
# empty_like, slice, copy_, view, as_strided, clone 等
# 保证 FSDP 的 flatten/unflatten 操作对 FP8 权重透明
```

FP8 FSDP2 的显存优势：
- 权重分片以 FP8 存储（而非 BF16）
- all-gather 后保持 FP8，不展开为 BF16
- 显存：1 byte/param（vs FSDP1 BF16 的 2 bytes/param）

## 6. CudaRNGStatesTracker

TE 提供了 RNG 状态追踪器，确保模型并行下的 Dropout 数值一致性：

```python
from transformer_engine.pytorch.distributed import CudaRNGStatesTracker

rng_tracker = CudaRNGStatesTracker()
rng_tracker.add("model-parallel-rng", seed=12345)

# 在 TransformerLayer 中使用
layer = te.TransformerLayer(
    ...,
    rng_state_tracker=rng_tracker,
)
```

不同并行 rank 需要不同的 Dropout mask（确保梯度正确），CudaRNGStatesTracker 为每种并行场景维护独立的 RNG 状态。

## 7. Activation Checkpointing（梯度检查点）

### 7.1 标准 Checkpointing

```python
from transformer_engine.pytorch.distributed import checkpoint

# 使用 TE 版 checkpoint（比 torch.utils.checkpoint 更 FP8 友好）
output = checkpoint(
    transformer_layer_forward,
    hidden_states,
    attention_mask,
    use_reentrant=False,   # 推荐
)
```

### 7.2 FP8 Activation Recompute

标准 checkpointing 在重新计算时会用**当前步的 scale**量化，与原始前向的 scale 不一致，导致数值差异。

TE 的 FP8 Activation Recompute 解决方案：

```python
# 原理：在重新计算阶段复用前向的 scale
_FP8_ACTIVATION_RECOMPUTE_ENABLED = True  # 前向中保存 scale

# 重新计算时：
_FP8_ACTIVATION_RECOMPUTE_PHASE = True   # 使用保存的 scale，而非当前 amax

# 保证重新计算的结果与前向完全一致
```

```python
# 使用方式
from transformer_engine.pytorch.distributed import (
    is_fp8_activation_recompute_enabled,
    in_fp8_activation_recompute_phase,
)

# FP8 Recompute 会在 checkpoint 内自动处理
with te.fp8_autocast(enabled=True, ...):
    output = checkpoint(model_block, x, ...)
    # 内部：前向时记录 scale，重计算时复用
```

## 9. 通信组配置示例

完整的多维并行配置（DP × TP × PP）：

```python
import torch.distributed as dist

world_size = dist.get_world_size()  # 总 GPU 数
tp_size = 4  # 张量并行 4
pp_size = 2  # 流水线并行 2
dp_size = world_size // (tp_size * pp_size)

rank = dist.get_rank()

# 创建 TP 通信组
tp_ranks = [
    list(range(i * tp_size, (i + 1) * tp_size))
    for i in range(world_size // tp_size)
]
tp_group = dist.new_group(tp_ranks[rank // tp_size])

# TE 模块中使用
layer = te.TransformerLayer(
    hidden_size=4096,
    ffn_hidden_size=16384,
    num_attention_heads=32,
    set_parallel_mode=True,
    tp_group=tp_group,
    sequence_parallel=True,
)

# FP8 autocast 中传入 amax 同步组
with te.fp8_autocast(
    enabled=True,
    fp8_recipe=fp8_recipe,
    fp8_group=tp_group,   # amax 在 TP group 内同步
):
    output = layer(hidden_states, attention_mask)
```

## 10. 性能收益

以 8×H100 TP=8 训练 13B 模型为例（序列长 2048）：

| 配置 | 吞吐 (tokens/sec) | 显存/GPU |
|------|------------------|---------|
| BF16 + TP + SP | 基准 1× | ~72 GB |
| FP8 + TP + SP | ~1.7× | ~58 GB |
| FP8 + TP + SP + UserBuffers | ~2.0× | ~60 GB |
| FP8 + TP + SP + UB + FSDP2 | ~1.9× | ~36 GB |

UserBuffers 通信重叠效果：
- AllGather 通信延迟（NVLink TP=8）≈ 15ms
- GEMM 计算时间 ≈ 40ms
- 重叠后有效通信时间 ≈ 0ms（完全隐藏）
