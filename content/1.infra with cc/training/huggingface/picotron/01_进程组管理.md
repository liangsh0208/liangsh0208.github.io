# 01_进程组管理

## 1. 目标论证

**为什么需要 ProcessGroupManager？**

在4D并行中，进程需要在不同维度参与不同的通信组：
- Tensor Parallel(TP)组内的进程执行AllReduce
- Pipeline Parallel(PP)组内的进程执行P2P通信
- Data Parallel(DP)组内的进程执行梯度同步
- Context Parallel(CP)组内的进程执行Ring Attention

复杂拓扑需要全局rank到4D坐标的映射管理，避免通信混乱。

**问题严重性：**
- 无统一管理时，进程组创建代码重复且易出错
- 各并行策略假设的进程拓扑可能冲突
- 调试分布式通信问题极其困难

## 2. 工作假设

**前置条件：**
- PyTorch分布式环境已初始化 (`dist.init_process_group`)
- GPU设备已正确绑定 (`torch.cuda.set_device(local_rank)`)
- 总进程数满足: `world_size == dp_size × pp_size × cp_size × tp_size`

**接口契约：**
- 4D网格顺序固定为: [DP_SIZE, PP_SIZE, CP_SIZE, TP_SIZE]
- 进程组ID列表返回排序后的rank列表
- 相邻PP rank通过next/prev属性访问

## 3. 解决方案

### 3.1 4D网格创建

```python
# 核心代码: process_group_manager.py
class ProcessGroupManager:
    def __init__(self, dp_size, pp_size, cp_size, tp_size):
        self.world_size = dist.get_world_size()
        self.global_rank = dist.get_rank()
        
        # 4D网格: [DP_SIZE, PP_SIZE, CP_SIZE, TP_SIZE]
        self.grid = torch.arange(
            self.world_size
        ).view(dp_size, pp_size, cp_size, tp_size)
        
        # 获取当前rank在4D网格中的坐标
        self.dp_rank, self.pp_rank, self.cp_rank, self.tp_rank = (
            self.grid == self.global_rank
        ).nonzero().flatten().tolist()
```

### 3.2 进程组创建

```python
# Tensor Parallel 组: 同TP列的进程
self.tp_group_ids = self.grid[self.dp_rank, self.pp_rank, self.cp_rank, :].tolist()
self.tp_group = dist.new_subgroups_by_enumeration([self.tp_group_ids])[0]
self.tp_world_size = len(self.tp_group_ids)

# Context Parallel 组: 同CP列的进程  
self.cp_group_ids = self.grid[self.dp_rank, self.pp_rank, :, self.tp_rank].tolist()
self.cp_group = dist.new_subgroups_by_enumeration([self.cp_group_ids])[0]
self.cp_world_size = len(self.cp_group_ids)

# Pipeline Parallel 组: 同PP列的进程
self.pp_group_ids = self.grid[self.dp_rank, :, self.cp_rank, self.tp_rank].tolist()
self.pp_group = dist.new_subgroups_by_enumeration([self.pp_group_ids])[0]
self.pp_world_size = len(self.pp_group_ids)

# Data Parallel 组: 同DP列的进程
self.dp_group_ids = self.grid[:, self.pp_rank, self.cp_rank, self.tp_rank].tolist()
self.dp_group = dist.new_subgroups_by_enumeration([self.dp_group_ids])[0]
self.dp_world_size = len(self.dp_group_ids)

# CP+DP组合组: 同时同CP、同TP的PP链上的所有进程
self.cp_dp_group_ids = self.grid[:, self.pp_rank, :, self.tp_rank].flatten().tolist()
self.cp_dp_group = dist.new_subgroups_by_enumeration([self.cp_dp_group_ids])[0]
```

### 3.3 PP相邻rank计算

```python
# Pipeline前后级rank用于激活值传递
rank_in_pipeline = self.pp_group_ids.index(self.global_rank)

if rank_in_pipeline < self.pp_world_size - 1:
    self.pp_next_rank = self.pp_group_ids[rank_in_pipeline + 1]
else:
    self.pp_next_rank = None

if rank_in_pipeline > 0:
    self.pp_prev_rank = self.pp_group_ids[rank_in_pipeline - 1]
else:
    self.pp_prev_rank = None
```

### 3.4 Ring Attention通信对计算

```python
# Ring Attention中的KV传递方向
cp_idx = self.cp_group_ids.index(self.global_rank)
self.cp_send_rank = self.cp_group_ids[(cp_idx + 1) % self.cp_world_size]
self.cp_recv_rank = self.cp_group_ids[(cp_idx - 1) % self.cp_world_size]
```

## 4. 故障模式

| 问题 | 可能原因 | 解决方案 |
|-----|---------|---------|
| `ValueError: grid size mismatch` | 进程总数与DP×PP×CP×TP不等 | 确认配置 `torchrun --nproc_per_node` |
| `RuntimeError: group already exists` | 重复初始化 | 使用单例模式 `setup_process_group_manager()` |
| Rank坐标为None | grid计算错误 | 检查world_size和维度乘积 |
| `pp_next_rank`错误 | 边界rank判断错误 | 最后rank应为None |
| CP通信死锁 | send/recv rank计算错误 | 验证环状公式: `(cp_idx ± 1) % world_size` |
