# 05_数据并行DP

## 1. 目标论证

**为什么需要 Data Parallel？**

在TP/PP/CP切分后，模型可放入单个设备。数据并行让同一模型副本处理不同数据批次：
- 扩展训练吞吐量(线性扩展理想情况下)
- 支持更大全局批次大小
- 利用更多GPU资源

**梯度同步开销：**
- 朴素All-Reduce: 每次反向传播后立即同步
- Bucket优化: 聚合梯度减少通信次数

## 2. 工作假设

**数据分发：**
- 数据在DP组内均匀分割
- 各DP rank独立读取数据子集

**混合精度训练：**
- 前向/反向使用fp16/bf16
- 优化器状态保持fp32精度
- 需要 `main_grad` 累积梯度

## 3. 解决方案

### 3.1 BucketManager: 梯度分桶

```python
class BucketManager:
    """
    将参数分配到桶中，桶满时触发All-Reduce
    """
    def __init__(self, params, process_group, bucket_size):
        self.process_group = process_group
        self.bucket_size = bucket_size  # 字节数
        
        # 将参数按大小分组到桶
        self.buckets = []
        current_bucket = []
        current_size = 0
        
        for param in sorted(params, key=lambda p: p.numel(), reverse=True):
            param_size = param.numel() * param.element_size()
            
            if current_size + param_size > bucket_size and current_bucket:
                self.buckets.append(current_bucket)
                current_bucket = []
                current_size = 0
            
            current_bucket.append(param)
            current_size += param_size
        
        if current_bucket:
            self.buckets.append(current_bucket)
        
        # 每个桶的All-Reduce状态
        self.ready_params = [set() for _ in self.buckets]
        self.reduce_work = [None] for _ in self.buckets]
    
    def mark_param_as_ready(self, param):
        """标记参数就绪，若桶满则触发All-Reduce"""
        for i, bucket in enumerate(self.buckets):
            if param in bucket:
                self.ready_params[i].add(param)
                
                # 桶内所有参数就绪
                if len(self.ready_params[i]) == len(bucket):
                    self._reduce_bucket(i)
                return
    
    def _reduce_bucket(self, bucket_idx):
        """执行桶级All-Reduce"""
        # 收集桶内所有main_grad
        grads = [
            p.main_grad for p in self.buckets[bucket_idx]
        ]
        
        # 展平并连接
        flat_grad = torch.cat([g.view(-1) for g in grads])
        
        # 发起非阻塞All-Reduce(累加并平均)
        self.reduce_work[bucket_idx] = dist.all_reduce(
            flat_grad, 
            group=self.process_group,
            async_op=True
        )
        
        # 原地除以world_size实现平均
        flat_grad.div_(self.world_size)
    
    def wait(self):
        """等待所有桶的All-Reduce完成"""
        for work in self.reduce_work:
            if work is not None:
                work.wait()
```

### 3.2 DataParallelBucket模块

```python
class DataParallelBucket(nn.Module):
    def __init__(self, module, bucket_cap_mb=25, grad_accumulation_steps=1):
        super().__init__()
        self.module = module
        pgm = get_process_group_manager()
        
        # 使用CP+DP组合组完成梯度同步
        self.process_group = pgm.cp_dp_group
        self.world_size = pgm.cp_dp_world_size
        
        # 创建bucket管理器
        self.bucket_manager = BucketManager(
            module.parameters(),
            process_group=self.process_group,
            bucket_size=bucket_cap_mb * 1024 * 1024 // 2  # 假设fp32=4bytes
        )
        
        # 梯度累积控制
        self.grad_accumulation_steps = grad_accumulation_steps
        self.require_backward_grad_sync = True
        
        # 为每个参数创建main_grad
        self._register_main_grad_hooks()
    
    def _register_main_grad_hooks(self):
        """注册反向传播钩子处理梯度"""
        for param in self.module.parameters():
            if param.requires_grad:
                # 分配main_grad缓冲区(fp32)
                param.main_grad = torch.zeros_like(
                    param, dtype=torch.float32
                )
                
                # 注册梯度累加钩子
                param.register_post_accumulate_grad_hook(
                    self._make_param_hook(param)
                )
    
    def _make_param_hook(self, param):
        def param_hook(*unused):
            # 1. 累加梯度到main_grad
            if param.grad is not None:
                param.main_grad.add_(param.grad.data)
                param.grad = None
            
            # 2. 标记参数就绪，可能触发bucket All-Reduce
            if self.require_backward_grad_sync:
                self.bucket_manager.mark_param_as_ready(param)
        
        return param_hook
    
    def _post_backward(self):
        """反向传播后处理: 等待同步并复制回param.grad"""
        # 等待所有桶完成
        self.bucket_manager.wait()
        
        # 将main_grad复制给param.grad供optimizer使用
        for p in self.module.parameters():
            if p.requires_grad:
                p.grad = p.main_grad.to(p.dtype)
    
    def forward(self, *args, **kwargs):
        # 正常前向
        return self.module(*args, **kwargs)
    
    def backward(self, loss):
        # 反向传播
        loss.backward()
        
        # 梯度同步和准备
        if self.require_backward_grad_sync:
            self._post_backward()
```

### 3.3 损失平均

```python
def average_loss_across_dp_cp_ranks(loss, device):
    """
    在CP+DP组内平均损失
    确保各进程看到的梯度贡献一致
    """
    pgm = get_process_group_manager()
    
    loss_tensor = torch.tensor([loss], device=device)
    dist.all_reduce(loss_tensor, group=pgm.cp_dp_group)
    loss_tensor /= pgm.cp_dp_world_size
    
    return loss_tensor.item()
```

### 3.4 应用到训练循环

```python
# train.py中的DP使用流程

# 1. 包装模型(model经过TP/PP/CP处理后)
model = DataParallelBucket(
    model,
    bucket_cap_mb=config.get('dp_bucket_cap_mb', 25),
    grad_accumulation_steps=config['grad_acc_steps']
)

# 2. 优化器
optimizer = torch.optim.AdamW(model.parameters(), lr=learning_rate)

# 3. 训练循环
for step, batch in enumerate(data_loader):
    # 梯度累积边界控制
    model.require_backward_grad_sync = (
        step % grad_acc_steps == grad_acc_steps - 1
    )
    
    # 前向+反向
    loss = model(input_ids=batch['input_ids'], labels=batch['labels'])
    model.backward(loss / grad_acc_steps)  # 缩放损失避免梯度爆炸
    
    # 优化器步进
    if model.require_backward_grad_sync:
        optimizer.step()
        optimizer.zero_grad()
```

## 4. 故障模式

| 问题 | 可能原因 | 解决方案 |
|-----|---------|---------|
| 梯度不收敛 | DP未同步或同步时机错误 | 确保 `require_backward_grad_sync` 正确设置 |
| 收敛速度不一致 | 各rank数据分布不均 | 使用DistributedSampler保证数据不重复 |
| Bucket溢出 | 单个参数大于bucket容量 | 增大bucket_cap_mb或为超大参数单独处理 |
| 显存溢出(main_grad) | 同时持有[param, grad, main_grad] | 使用bf16减少main_grad显存占用 |
| 卡住(timeout) | 某些rank未触发All-Reduce | 确保所有rank都mark了相同数量的参数 |
| 精度损失 | fp16梯度累加溢出 | 使用grad scaling或bf16 |
