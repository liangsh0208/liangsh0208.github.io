## 配置策略速查

| 模型大小 | 推荐并行策略 | 显存/GPU | 适用场景 |
|----------|-------------|----------|---------|
| 7B | TP=8, PP=1 | ~40GB | 单机8×A100 |
| 14B | TP=8, PP=2 | ~38GB | 单机8×A100 |
| 70B | TP=8, PP=4 | ~45GB | 4机8×A100 |
| 405B | TP=8, PP=8, CP=2 | ~80GB | 8机8×H100 |

**并行配置优先级：**
1. **优先TP**：减少激活值重复计算，最佳加速比
2. **次选PP**：序列较长或激活值占用过大时用
3. **最后DP**：增加batch size，数据并行加速

## 配置1：Llama-2 7B (TP=8, PP=1) 单机配置

### 硬件需求
- 8× NVIDIA A100 40GB/80GB 
- 单机NVLink互联

### 完整配置

```yaml
# config_llama2_7b_1node.yaml

# ========== 模型配置 ==========
model:
  ddp_bucket_cap_mb: 25
  dtype: bfloat16
  init_method:
    std: 0.02
  make_vocab_size_divisible_by: 1
  model_config:
    is_llama_config: true
    hidden_size: 4096
    intermediate_size: 11008
    num_hidden_layers: 32
    num_attention_heads: 32
    num_key_value_heads: 32  # 非GQA
    max_position_embeddings: 8192
    vocab_size: 32000
    tie_word_embeddings: false
    rms_norm_eps: 1.0e-05
    hidden_act: silu
    pretraining_tp: 1
    
# ========== 并行策略 ==========
parallelism:
  tp: 8              # Tensor Parallel: 8 ranks
  pp: 1              # Pipeline Parallel: 1 stage (无流水线)
  dp: 1              # Data Parallel: 1 (TP已占满8卡)
  expert_parallel_size: 1
  context_parallel_size: 1
  pp_engine: 1f1b
  tp_mode: REDUCE_SCATTER          # 序列并行模式
  tp_linear_async_communication: true  # 异步TP通信
  
# ========== 训练配置 ==========
tokens:
  sequence_length: 4096
  train_steps: 100000
  micro_batch_size: 1        # 每GPU micro batch
  batch_accumulation_per_replica: 4  # 梯度累积4步
  # Global batch size = 1 * 4 * 1 = 4 samples = 16384 tokens
  
# ========== 优化器配置 ==========
optimizer:
  accumulate_grad_in_fp32: true
  clip_grad: 1.0
  learning_rate_scheduler:
    learning_rate: 3.0e-4
    lr_warmup_steps: 2000
    lr_warmup_style: linear
    lr_decay_steps: 98000
    lr_decay_style: cosine
    min_decay_lr: 3.0e-5
  optimizer_factory:
    name: adamW
    adam_beta1: 0.9
    adam_beta2: 0.95
    adam_eps: 1.0e-08
    torch_adam_is_fused: true
  weight_decay: 0.1
  zero_stage: 0              # TP+小模型，不需要ZeRO
  
# ========== 数据配置 ==========
data_stages:
  - name: Pretrain Stage
    start_training_step: 1
    data:
      dataset:
        hf_dataset_or_datasets: "HuggingFaceFW/fineweb-edu"
      seed: 42
      num_loading_workers: 4
      
# ========== 检查点配置 ==========
checkpoints:
  checkpoints_path: /checkpoints/llama2-7b
  checkpoint_interval: 1000
  save_initial_state: false
  save_final_state: true
  
# ========== 日志配置 ==========
general:
  project: "nanotron-llama2-7b"
  run: "7b-pretrain-%date_%jobid"
  seed: 42
  
logging:
  iteration_step_info_interval: 10
  log_level: info
  log_level_replica: info
```

### 启动命令

```bash
#!/bin/bash
# launch_llama2_7b.sh

export CUDA_DEVICE_MAX_CONNECTIONS=1
export NCCL_DEBUG=INFO

# 8卡单机
torchrun \
    --nproc_per_node=8 \
    --nnodes=1 \
    --master_addr=localhost \
    --master_port=6000 \
    run_train.py \
    --config-file config_llama2_7b_1node.yaml
```

### 关键参数计算

```
# 7B模型参数计算
参数量 = vocab_size * hidden_size * (2 if tie_embeddings else 1) 
       + num_layers * (3 * h * intermediate + 4 * h * h)
= 32000 * 4096 * 2 + 32 * (3 * 4096 * 11008 + 4 * 4096 * 4096)
= ~6.7B (Llama-2 7B约6.7B实际参数)

# 激活值内存估算 (seq_len=4096, batch=1)
每层激活值 = 2 * seq_len * batch * h * (num_heads / tp)
总激活值 = layers * 每层激活值 + attention(QKV)存储
= 32 * 2 * 4096 * 4096 / 8 (TP=8)
= ~100MB per GPU

# 优化器状态 (AdamW)  
参数: 7B / 8 (TP分片) = 0.875B per GPU
状态: 2 * 参数 * 4字节 (FP32) = 7GB per GPU
```

## 配置2：Qwen-14B (TP=8, PP=2) 单机配置

### 硬件需求
- 8× NVIDIA A100 80GB
- 单机NVLink互联

### 完整配置

```yaml
# config_qwen_14b_1node.yaml

model:
  dtype: bfloat16
  init_method:
    std: 0.02
  model_config:
    is_qwen2_config: true
    hidden_size: 5120
    intermediate_size: 13696
    num_hidden_layers: 40
    num_attention_heads: 40
    num_key_value_heads: 40  # 非GQA
    max_position_embeddings: 8192
    vocab_size: 151936      # Qwen的扩展词汇表
    tie_word_embeddings: false
    _use_doc_masking: true   # Qwen支持文档级掩码
    
# 关键：PP=2，8卡分为2个PP stage，每stage 4卡做TP
parallelism:
  tp: 4              # 每PP stage内TP=4
  pp: 2              # 2个PP stage
  dp: 1              # 总卡数 = 4 * 2 * 1 = 8
  
  # 性能优化
  tp_mode: REDUCE_SCATTER
  tp_linear_async_communication: true
  tp_recompute_allgather: false  # 启用可节省激活值内存
  recompute_layer: false          # 可选：激活重计算
  
tokens:
  sequence_length: 4096
  train_steps: 100000
  micro_batch_size: 2            # PP可用更大的micro batch
  batch_accumulation_per_replica: 2
  # GBS = 2 * 2 * 1 = 4 samples
  
optimizer:
  accumulate_grad_in_fp32: true
  clip_grad: 1.0
  learning_rate_scheduler:
    learning_rate: 1.5e-4        # 14B模型用小学习率
    lr_warmup_steps: 3000
    lr_decay_steps: 97000
    lr_decay_style: cosine
    min_decay_lr: 1.5e-5
  zero_stage: 0                   # TP+PP足够，不需要ZeRO
  
checkpoints:
  checkpoints_path: /checkpoints/qwen-14b
  checkpoint_interval: 500
  
general:
  project: "nanotron-qwen-14b"
  run: "14b-pretrain-%date_%jobid"
```

### 互连拓扑图

```
单机8×A100拓扑

GPU 0 ──NVLink── GPU 1 ──NVLink── GPU 2 ──NVLink── GPU 3
  │                 │                  │                  │
  │                 │                  │                  │
GPU 4 ──NVLink── GPU 5 ──NVLink── GPU 6 ──NVLink── GPU 7

PP=2, TP=4 分组:

PP Rank 0: [GPU0, GPU1, GPU2, GPU3]  (TP Group 0)
PP Rank 1: [GPU4, GPU5, GPU6, GPU7]  (TP Group 1)

P2P通信: GPU3 <-> GPU4 (PP间通信)
TP通信: 组内NVLink全互联
```

### 启动方式

```bash
#!/bin/bash
# launch_qwen_14b.sh

export CUDA_DEVICE_MAX_CONNECTIONS=1

# 自动检测本地rank
torchrun \
    --nproc_per_node=8 \
    --nnodes=1 \
    run_train.py \
    --config-file config_qwen_14b_1node.yaml
```

## 配置3：Llama-3 70B (TP=8, PP=4) 多机配置

### 硬件需求
- 4× 节点，每节点8× NVIDIA A100 80GB
- 总计32张GPU
- 节点间InfiniBand连接 (推荐400Gb/s HDR)

### 并行策略矩阵

```
总GPU数 = 32 = TP × PP × DP
         = 8 × 4 × 1

TP=8: 每节点内做Tensor Parallel (使用NVLink)
PP=4: 跨节点的Pipeline Parallel (4个stage)
DP=1:  Data Parallel在此配置下为1

Stage分配:
  Node 0: PP Stage 0, TP Ranks [0-7]
  Node 1: PP Stage 1, TP Ranks [0-7]  
  Node 2: PP Stage 2, TP Ranks [0-7]
  Node 3: PP Stage 3, TP Ranks [0-7]
  
PP通信: Stage 0 -> 1 -> 2 -> 3 (Node间IB通信)
```

### 完整配置

```yaml
# config_llama3_70b_4node.yaml

model:
  dtype: bfloat16
  ddp_bucket_cap_mb: 25
  init_method:
    std: 0.02
  model_config:
    is_llama_config: true
    hidden_size: 8192
    intermediate_size: 28672
    num_hidden_layers: 80
    num_attention_heads: 64
    num_key_value_heads: 8        # GQA配置
    max_position_embeddings: 8192
    vocab_size: 128256
    tie_word_embeddings: false
    _attn_implementation: flash_attention_2
    
# 关键：多机PP配置
parallelism:
  tp: 8              # 每节点内TP=8
  pp: 4              # 跨4个节点的PP
  dp: 1              # 32 = 8 * 4 * 1
  context_parallel_size: 1
  pp_engine: 1f1b
  
  # TP优化
  tp_mode: REDUCE_SCATTER
  tp_linear_async_communication: true
  
  # 内存优化 (70B需要)
  recompute_layer: true    # 激活值重计算，节省30%激活内存
  
tokens:
  sequence_length: 8192     # 长序列训练
  train_steps: 100000
  micro_batch_size: 1       # PP场景下保持较小
  batch_accumulation_per_replica: 4
  # GBS = 1 * 4 * 1 = 4 samples (32768 tokens)
  
optimizer:
  accumulate_grad_in_fp32: true
  clip_grad: 1.0
  learning_rate_scheduler:
    learning_rate: 1.5e-4   # 70B模型学习率
    lr_warmup_steps: 5000
    lr_decay_steps: 95000
    lr_decay_style: cosine
    min_decay_lr: 1.5e-5
  zero_stage: 0             # TP+PP足够时无需ZeRO
  
checkpoints:
  checkpoints_path: /shared_nfs/llama3-70b
  checkpoint_interval: 1000
  checkpoints_path_is_shared_file_system: true  # 共享存储
  
data_stages:
  - name: Main Training
    start_training_step: 1
    data:
      dataset:
        dataset_folder:
          - "/shared_nfs/data/fineweb-edu-tokenized"
          - "/shared_nfs/data/dclm-tokenized"
        dataset_weights: [0.7, 0.3]
      seed: 42
      num_loading_workers: 8    # 多机下增加workers
      
general:
  project: "nanotron-llama3-70b"
  run: "70b-pretrain-4node-%date_%jobid"
  seed: 42
```

## 高级优化配置

### 内存优化组合

#### 配置A：激活值重计算 (Activation Checkpointing)

```yaml
# 推荐：模型 > 14B 或序列长度 > 8192

parallelism:
  recompute_layer: true  # 每层前向传播时不存储激活值，反向时重计算

# 内存节省：约30-40%激活内存
# 性能损失：约20-30%额外计算
```

#### 配置B：梯度检查点 + ZeRO Stage 1

```yaml
# 推荐：显存极其受限场景

optimizer:
  accumulate_grad_in_fp32: true  # 必须用FP32累积
  zero_stage: 1                  # 优化器状态分片

parallelism:
  recompute_layer: true
  
# 内存节省：
# - FP32累积: 2×参数量的梯度存储
# - ZeRO-1: 优化器状态分片 (节省 (N-1)/N )
```

#### 配置C：Context Parallelism (长序列)

```yaml
# 推荐：序列长度 > 32K

parallelism:
  tp: 4
  pp: 1
  dp: 2
  context_parallel_size: 2  # 在TP×PP×DP之外增加CP维度
  
# 总GPU = 4 × 1 × 2 × 2 = 16
# 序列分片: 64K序列 / 2 = 32K per CP rank
```

### 性能优化参数

```yaml
# 1. 异步TP通信
parallelism:
  tp_linear_async_communication: true  # 重叠计算和通信

# 2. DDP Bucket大小
model:
  ddp_bucket_cap_mb: 25  # 增大可减少allreduce次数，但增加内存

# 3. Flash Attention
model:
  model_config:
    _attn_implementation: flash_attention_2  # 或 "sdpa"

# 4. Fused优化器
optimizer:
  optimizer_factory:
    torch_adam_is_fused: true  # 使用融合CUDA kernel
```

## 常见问题快速排查

### 问题1：训练启动时NCCL超时

**症状：**
```
RuntimeError: NCCL operation failed: unhandled system error
或
Timeout waiting for all ranks to join
```

**排查步骤：**
1. 检查网络连通性
```bash
# 测试NCCL
NCCL_DEBUG=INFO NCCL_DEBUG_SUBSYS=ALL torchrun --nnodes=2 ...  

# 测试IB
ibstatus  # 检查IB网卡状态
ib_write_bw  # 测试IB带宽
```

2. 检查环境变量一致性
```bash
# 所有节点必须一致
export NCCL_SOCKET_IFNAME=eth0    # 或ib0
export NCCL_IB_DISABLE=0          # 1=禁用IB
export NCCL_P2P_DISABLE=0         # 1=禁用P2P
```

3. 检查防火墙
```bash
# 确保端口开放
# PyTorch分布式使用master_port和master_port+1/2
```

### 问题2：训练过程中OOM

**症状：**
```
RuntimeError: CUDA out of memory
```

**排查步骤：**

1. 查看OOM位置
```python
# 检查前5步内存日志
if iteration_step < initial_iter_step + 5:
    log_memory(logger=logger, msg="Memory checkpoint")
```

2. 逐步调整参数
```yaml
# Step 1: 减小batch_size
tokens:
  micro_batch_size: 1  # 先降到最小
  batch_accumulation_per_replica: 8  # 增加累积保持GBS

# Step 2: 启用激活值重计算
parallelism:
  recompute_layer: true

# Step 3: 启用ZeRO
optimizer:
  zero_stage: 1  # 或2(更激进)

# Step 4: 使用更激进的序列并行
parallelism:
  context_parallel_size: 2
```

3. 估算内存瓶颈
```bash
# 使用nvidia-smi监控
watch -n 1 nvidia-smi

# 或启用PyTorch内存统计
export PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:512
```

### 问题3：数据加载成为瓶颈

**症状：**
- GPU利用率不稳定，大部分时间低于50%
- `dataloader_fetch`时间异常长

**排查配置：**
```yaml
data_stages:
  - data:
      num_loading_workers: 8  # 增加worker数量
      # 本地存储可增大，网络存储不宜过大

tokens:
  micro_batch_size: 2         # 增大batch减少数据切换频率
```

**数据优化：**
```python
# 1. 使用预token化的二进制格式(Nanoset)
# 避免运行时tokenizer处理

# 2. 确保数据在本地NVMe/SSD
# 网络存储(NFS/S3)会成为瓶颈

# 3. 启用pin_memory
dataloader_pin_memory: true
```

### 问题4：PP bubble时间过长

**症状：**
- 多PP配置下吞吐量低于理论值
- pipeline_engine.train_batch_iter时间异常

**优化策略：**
```yaml
# 增加micro batch数量填充pipeline bubble
tokens:
  micro_batch_size: 4          # 增大
  batch_accumulation_per_replica: 16  # 相应增加保持GBS

# 或使用更多DP减少PP依赖
parallelism:
  pp: 2  # 减少PP stage数
  dp: 4  # 增加DP
```

### 问题5：梯度发散/loss为NaN

**排查步骤：**
1. 检查学习率
```yaml
optimizer:
  learning_rate_scheduler:
    learning_rate: 1.0e-4  # 降低学习率测试
    lr_warmup_steps: 100   # 确保warmup
```

2. 启用梯度裁剪
```yaml
optimizer:
  clip_grad: 1.0  # 必须启用
```

3. 检查数据质量
```bash
# 检查数据分布
python -c "
from datasets import load_dataset
ds = load_dataset('path')
print('Max length:', max(len(x) for x in ds['input_ids']))
print('Vocab range:', min(min(x) for x in ds['input_ids']), 
                         max(max(x) for x in ds['input_ids']))
"
```

4. 混合精度检查
```yaml
model:
  dtype: bfloat16  # 比float16更稳定
  # 或尝试float32调试
```
