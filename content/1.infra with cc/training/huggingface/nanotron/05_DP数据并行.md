## 2. 模块概述

### 2.1 什么是数据并行 (DP)

数据并行 (Data Parallelism) 是最基础的分布式训练方法：
- 每个 GPU 保存完整的模型副本
- 不同的 GPU 处理不同的数据批次 (batch)
- 反向传播后通过 AllReduce 同步梯度
- 所有 GPU 保持参数一致

### 4.2 ddp_trigger_sync_in_bwd (DDP 反向钩子)

**文件**: `src/nanotron/parallel/data_parallel/utils.py` (10-26行)

```python
@contextmanager
def ddp_trigger_sync_in_bwd(model_ddp):
    """触发 DDP 在下一轮反向传播时同步梯度
    
    使用场景:
    - 梯度累积: n 次前向后一次性同步
    - 控制同步时机，优化通信与计算重叠
    
    原理:
    1. 将 require_backward_grad_sync 设为 True
    2. 调用 prepare_for_backward 准备同步
    3. 恢复原始状态
    """
    assert isinstance(model_ddp, torch.nn.parallel.DistributedDataParallel)
    
    # 保存原始状态
    old_require_backward_grad_sync = model_ddp.require_backward_grad_sync
    old_require_forward_param_sync = model_ddp.require_forward_param_sync
    
    # 启用同步
    model_ddp.require_backward_grad_sync = True
    model_ddp.require_forward_param_sync = True
    
    # 准备反向传播 (预先创建bucket，触发 hooks)
    # 参考 PyTorch: torch/csrc/distributed/c10d/reducer.cpp
    model_ddp.reducer.prepare_for_backward([])
    
    try:
        yield
    finally:
        # 恢复原始状态
        model_ddp.require_backward_grad_sync = old_require_backward_grad_sync
        model_ddp.require_forward_param_sync = old_require_forward_param_sync
```

**工作流程**:
```
┌─────────────────────────────────────────────────────────────────────┐
│                     梯度累积与同步控制流程                           │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  for i in range(gradient_accumulation_steps):                        │
│      if i == gradient_accumulation_steps - 1:  # 最后一步            │
│          with ddp_trigger_sync_in_bwd(model):                       │
│              loss.backward()   # 触发梯度同步                        │
│      else:                                                          │
│          with model.no_sync():  # 前 n-1 步不同步                    │
│              loss.backward()                                        │
│                                                                      │
│  optimizer.step()   # 同步后的梯度用于更新参数                       │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.3 sync_gradients_across_dp (梯度同步)

**文件**: `src/nanotron/parallel/data_parallel/utils.py` (28-53行)

```python
@torch.profiler.record_function("sync_gradients_across_dp")
def sync_gradients_across_dp(
    module: nn.Module,
    dp_pg: dist.ProcessGroup,
    reduce_op: dist.ReduceOp,
    grad_accumulator: Optional[GradientAccumulator],
    **sync_options,
):
    """跨数据并行组同步梯度
    
    两种同步路径:
    1. 使用 GradientAccumulator (ZeRO-1/DDP + FP32 累加)
    2. 直接 AllReduce (标准 DDP)
    
    参数:
        module: 需要同步梯度的模块
        dp_pg: 数据并行进程组
        reduce_op: 归约操作 (通常 SUM 或 AVG)
        grad_accumulator: 梯度累加器 (可选)
        sync_options: 额外选项 (如 reduce_scatter)
    """
    if grad_accumulator is not None:
        # 优化路径: 使用预分配的 FP32 缓冲区
        # ZeRO-1 模式下使用 ReduceScatter 替代 AllReduce
        grad_accumulator.sync_gradients_across_dp(
            dp_pg=dp_pg, reduce_op=reduce_op, **sync_options
        )
        return
    
    # 标准路径: 直接 AllReduce 每个参数的梯度
    for name, param in module.named_parameters():
        dist.all_reduce(param.grad, op=reduce_op, group=dp_pg)
```

```python
class FP32GradientAccumulator(GradientAccumulator):
    """将梯度累加到 FP32 缓冲区
    
    解决的问题:
    - 避免低精度 (bf16/fp16) 梯度累加的精度损失
    - 支持 ZeRO-1 的 ReduceScatter 同步
    - 提供连续的内存布局以优化通信
    
    内存布局:
    ┌─────────────────────────────────────────────────────────────┐
    │  params: List[param1, param2, ..., paramN]                  │
    │                     │                                       │
    │                     ▼                                       │
    │  flat_fp32_buffer: [fp32_p1 | fp32_p2 | ... | fp32_pN]     │
    │       ▲                                                     │
    │       └── 直接作为 optimizer 的输入参数                      │
    │                                                             │
    │  fp32_grad_buffer: [grad1 | grad2 | ... | gradN]           │
    │       ▲                                                     │
    │       └── 由 backward 后的半精度梯度累加而来                 │
    └─────────────────────────────────────────────────────────────┘
    """
    def __init__(self, named_parameters, grad_buckets_named_params=None):
        # 1. 构建 FP32 梯度缓冲区
        self.fp32_grad_buffers, self._contiguous_fp32_grad_buffer = \
            self.build_grad_buffers(named_parameters)
        
        # 2. 构建连续扁平化的 FP32 参数缓冲区
        # big_flat_buffer: [param1_fp32, param2_fp32, ..., paramN_fp32]
        big_flat_buffer = torch.empty(total_params, dtype=torch.float, device="cuda")
        
        # 3. 从半精度参数拷贝到 FP32 缓冲区
        for name, param in named_parameters:
            fp32_param = self.parameters[name]["fp32"]
            fp32_param.copy_(param)  # bf16/fp16 -> fp32
    
    def sync_gradients_across_dp(self, dp_pg, reduce_op, reduce_scatter=False):
        """同步梯度
        
        两种模式:
        1. reduce_scatter=False (DDP): AllReduce 所有梯度
        2. reduce_scatter=True (ZeRO-1): 各 rank 只接收自己需要的那部分
        """
        if reduce_scatter:
            # ZeRO-1: 每个 rank 只获得自己更新那部分参数的梯度
            dist.reduce_scatter_coalesced(
                output_tensor_list=[local_grad_shard],      # 本 rank 的分片
                input_tensor_lists=[split(full_grad)],       # 所有 rank 的完整梯度
                op=reduce_op, group=dp_pg
            )
        else:
            # 标准 DDP: 所有 rank 获得完整梯度
            dist.all_reduce(self._contiguous_fp32_grad_buffer, 
                          op=reduce_op, group=dp_pg)
```

### 4.5 ZeRO Distributed Optimizer (ZeRO-1 实现)

**文件**: `src/nanotron/optim/zero.py` (25-121行)

```python
class ZeroDistributedOptimizer(InheritFromOtherOptimizer):
    """ZeRO Stage 1 实现
    
    核心思想:
    - 将优化器状态 (AdamW 的一阶/二阶动量) 分片到各 DP rank
    - 每个 rank 只更新自己负责的那部分参数
    - 更新后通过 AllGather 同步给所有 rank
    
    内存节省:
    - 标准 AdamW: 参数量 * 4 (param + grad + exp_avg + exp_avg_sq)
    - ZeRO-1: 参数量 * (2 + 2/n) (n = DP size)
    
    示例 (1B 模型, DP=4):
    - 标准: 4GB (param) + 4GB (grad) + 8GB (优化器状态) = 16GB
    - ZeRO-1: 4GB (param) + 4GB (grad) + 2GB (优化器状态/4) = 10GB
    """
    
    def __init__(self, named_params_or_groups, optimizer_builder, dp_pg):
        self.dp_pg = dp_pg  # 数据并行进程组
        
        # 1. 将参数分片到各 DP rank
        # param_name_to_dp_rank_offsets: {param_name: {rank: (start, end)}}
        self.param_name_to_dp_rank_offsets = self._partition_parameters()
        
        # 2. 提取本 rank 负责的参数分片
        current_dp_rank = dist.get_rank(dp_pg)
        param_groups_in_rank = [
            {
                "named_params": [
                    (name, get_sliced_tensor(param, start, end))
                    for name, param in param_group["named_params"]
                    if current_dp_rank in self.param_name_to_dp_rank_offsets[name]
                ]
            }
            for param_group in self.zero_named_param_groups
        ]
        
        # 3. 用分片后的参数初始化底层优化器
        # 底层优化器只看到本 rank 负责的 1/n 参数
        optimizer = optimizer_builder(param_groups_in_rank)
        super().__init__(optimizer=optimizer)
    
    def step(self, closure=None):
        """执行优化器步骤"""
        # 1. 底层优化器只更新本 rank 的那部分参数
        loss = super().step(closure)
        
        # 2. AllGather 更新后的参数到所有 rank
        self._all_gather_params()
        return loss
    
    def _partition_parameters(self):
        """将参数均匀分片到各 DP rank"""
        for name, param in named_params:
            numel = param.numel()
            # 计算每个 rank 的元素数 (向上取整)
            padded_numel_per_dp = (numel - 1) // self.dp_pg.size() + 1
            
            # 分配空间，最后一个 rank 可能少几个元素
            sizes = np.full(shape=(self.dp_pg.size()), 
                          fill_value=padded_numel_per_dp)
            remainder = padded_numel_per_dp * self.dp_pg.size() - numel
            if remainder > 0:
                sizes[-remainder:] -= 1
            
            # 记录每个 rank 负责的起止索引
            end_offsets = np.cumsum(sizes)
            start_offsets = np.concatenate([[0], end_offsets[:-1]])
            
            param_name_to_dp_rank_offsets[name] = {
                dp_rank: (start_offsets[dp_rank], end_offsets[dp_rank])
                for dp_rank in range(self.dp_pg.size())
            }
    
    def _all_gather_params(self):
        """AllGather 更新后的参数"""
        dist.all_gather_coalesced(
            output_tensor_lists=[[
                tensor[rank_offsets] for rank in range(dp_size)
            ] for name, tensor in all_params],
            input_tensor_list=[
                tensor[current_rank_offsets] 
                for name, tensor in all_params
            ],
            group=self.dp_pg
        )
```

### 4.6 反向传播梯度 Hook

```python
def get_fp32_accum_hook(reduce_scatter: bool, reduce_op: dist.ReduceOp):
    """为 DDP 返回一个通信 hook
    
    这个 hook 在 DDP 的每个 bucket 准备好时调用，实现:
    1. 将低精度梯度累加到 FP32 缓冲区
    2. 执行异步梯度同步 (AllReduce/ReduceScatter)
    3. 与计算重叠，提升效率
    """
    def fp32_accum_hook(state: FP32GradBucketManager, bucket: GradBucket):
        dp_pg = state.dp_pg
        accumulator = state.accumulator
        
        # 1. 累加新到达的梯度到 FP32 缓冲区
        for param, grad in zip(bucket.parameters(), bucket.gradients()):
            name = state.param_id_to_name[id(param)]
            fp32_grad_buffer = accumulator.get_grad_buffer(name)
            fp32_grad_buffer.add_(grad)  # FP16/BF16 -> FP32 累加
        
        # 2. 同步梯度
        if dp_pg.size() == 1:
            fut = torch.futures.Future()
            fut.set_result(bucket.buffer())
            return fut
        
        if reduce_scatter:  # ZeRO-1 模式
            # 每个 rank 只获得自己需要的那部分梯度
            dist.reduce_scatter_coalesced(
                output_tensor_list=[local_shards],
                input_tensor_lists=[split(full_grad) for full_grad in grads],
                op=reduce_op, group=dp_pg, async_op=True
            )
        else:  # 标准 DDP 模式
            # 异步 AllReduce
            accumulator.fp32_grads_allreduce_handle = dist.all_reduce_coalesced(
                grad_buffer_tensor_list, group=dp_pg, async_op=True, op=reduce_op
            )
        
        # 3. 返回 Future (DDP 会等待并触发下一步)
        fut = torch.futures.Future()
        fut.set_result(bucket.buffer())
        return fut
    
    return fp32_accum_hook
```

## 6. 常见问题

### Q1: DDP 与 ZeRO-1 如何选择?

**A**: 根据模型大小和硬件配置:

| 场景 | 推荐配置 | 显存占用 (AdamW) |
|------|----------|-----------------|
| 小模型 (< 7B), 显存充足 | DDP only (zero_stage=0) | 4x 参数量 |
| 中等模型 (7B-20B) | ZeRO-1 (zero_stage=1) | ~2.5x 参数量 |
| 大模型 (> 20B) | ZeRO-1 + TP/PP/CP | ~2.5x + 切分收益 |

### Q2: 为什么需要 FP32 梯度累加?

**A**: 精度问题:
- bf16/fp16 累加会累积舍入误差，长序列或大批量训练时尤其明显
- FP32 累加减少精度损失，支持更大的 batch_accumulation
- 代价: 需要额外分配 FP32 缓冲区 (约 4x 参数量显存)

### Q3: sync_gradients_across_dp 何时调用?

**A**: 调用时机:
1. 每个 train step 结束时 (accumulation 最后一步)
2. 显式调用以提前触发梯度同步
3. 与 DDP 的 `no_sync()` 配合使用

代码模式:
```python
for i in range(num_batches):
    loss = model.forward(...)
    is_accumulation_step = (i % accumulation_steps) != 0
    
    if is_accumulation_step:
        with grad_accumulator.no_sync():  # 不同步
            grad_accumulator.backward(loss)
    else:
        grad_accumulator.backward(loss)  # 同步
        optimizer.step()
        grad_accumulator.zero_grad()
```

### Q4: ZeRO-1 如何与 TP 共存?

**A**: TP 和 ZeRO-1 是正交的:
- TP 在节点内拆分 (NVLink 通信，低延迟)
- ZeRO-1 在 DP 组内拆分优化器状态 (IB/PCIe 通信)
- 先应用 TP 切分，再对完整 model replica 应用 ZeRO-1
- 世界大小计算公式: `world_size = dp × pp × tp`

示例 8 卡机配置:
```yaml
parallelism:
  dp: 2   # 普通 IB 同步优化器状态
  pp: 1
  tp: 4   # 节点内 NVLink 通信
  
optimizer:
  zero_stage: 1  # 每个 DP 组内部优化器状态分片
```

### Q5: 梯度裁剪如何与累加器配合?

**A**: 在 sync 后、step 前进行:
```python
# 1. 同步梯度
grad_accumulator.sync_gradients_across_dp(...)

# 2. (可选) 梯度裁剪
if clip_grad is not None:
    torch.nn.utils.clip_grad_norm_(
        [p for p in optimizer.parameters()], clip_grad
    )

# 3. 优化器步骤
optimizer.step()
```

注意: 裁剪应在梯度已经聚合后 (是完整梯度)，而不是各 rank 的分片。

### Q6: 如何检查梯度同步是否正确?

**A**: 调试技巧:
```python
# 打印各 rank 的梯度范数
for name, param in model.named_parameters():
    if param.grad is not None:
        grad_norm = param.grad.norm().item()
        print(f"Rank {dist.get_rank()}: {name} grad_norm = {grad_norm}")

# 应该在同步后各 rank 打印相同的数值
```

### Q7: 为什么使用 reduce_scatter_coalesced?

**A**: 性能优势:
- 相比 `reduce_scatter_tensor` 遍历调用，coalesced 版本合并通信
- 两阶段执行: 将参数列表先合并成大 buffer，然后一次性通信
- 减少通信 kernel launch 开销，提升带宽利用率
