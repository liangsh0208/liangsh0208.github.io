# Slime 通信与并行模块实现原理与性能优化

> **【源码定位】** `slime/utils/distributed_utils.py`, `slime/backends/megatron_utils/cp_utils.py`  
> **【阅读建议】** 需理解 NCCL 集体通信、Megatron 并行策略设计  
> **【前置知识】** PyTorch DDP、Ring AllReduce、GPU 拓扑结构

## 1. 模块概述

通信与并行模块是 Slime 框架实现**大规模分布式训练**的关键组件，支持多种并行策略的组合，包括**张量并行（TP）、流水线并行（PP）、数据并行（DP）、专家并行（EP）和上下文并行（CP）**。该模块基于 Megatron-LM 的并行基础设施构建，并针对强化学习训练场景进行了优化。

**关键设计决策【重点】**：
1. **进程组隔离**：Actor、Critic、Rollout 使用独立通信组，避免互相干扰
2. **自定义 Gloo 组**：用于 CPU 数据收集（如日志、统计量）
3. **Ring Attention CP**：Zigzag 分布实现负载均衡的长序列训练
4. **序列均衡**：动态调整样本分配，最小化计算气泡

### 2.2 各并行策略职责

| 并行类型 | 切分维度 | 主要用途 | 通信特点 |
|---------|---------|---------|---------|
| **TP** (Tensor Parallel) | 层内参数切分 | 大模型单层参数过多 | 高频小通信，AllReduce |
| **PP** (Pipeline Parallel) | 层间切分 | 模型层数多 | 低频大通信，P2P |
| **DP** (Data Parallel) | 数据批次切分 | 扩大有效批次 | 梯度 AllReduce |
| **CP** (Context Parallel) | 序列长度切分 | 长序列训练 | Ring Attention |
| **EP** (Expert Parallel) | MoE 专家切分 | 稀疏专家模型 | AllToAll |

### 3.1 自定义进程组创建

```python
def init_process_group(
    backend="nccl",
    init_method=None,
    timeout=None,
    world_size=-1,
    rank=-1,
    store=None,
    group_name=None,
):
    """创建独立的进程组，支持多个 Main Group

    Megatron 默认只创建一个 WORLD 组，但某些场景需要多个独立组：
    - Actor 和 Critic 使用不同的进程组
    - 多个训练任务并行

    实现：复用 PyTorch 内部 API `new_process_group_helper()`
    """
    if store is not None:
        assert world_size > 0 and rank >= 0
    elif init_method is None:
        init_method = "env://"

    # 通过 rendezvous 创建分布式存储
    if store is None:
        rendezvous_iterator = rendezvous(init_method, rank, world_size, timeout=timeout)
        store, rank, world_size = next(rendezvous_iterator)
        store = PrefixStore(group_name, store)

    # 创建进程组
    pg, _ = _new_process_group_helper(
        world_size, rank, [], backend, store,
        group_name=group_name,
        timeout=timeout,
    )

    # 注册到全局映射表
    _world.pg_group_ranks[pg] = {i: i for i in range(world_size)}
    return pg
```

## 4. Context Parallel (CP) 实现

### 4.1 Zigzag Ring Attention

Slime 采用 Zigzag Ring Attention 对序列进行切分，实现 CP 并行：

```
┌─────────────────────────────────────────────────────────────────┐
│               Zigzag Ring Attention 数据分布                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  原始序列：[T0, T1, T2, T3, T4, T5, T6, T7]  (长度=8, CP=4)      │
│                                                                 │
│  Zigzag 分块：每个 rank 处理两个不连续的块                         │
│                                                                 │
│  Rank 0: [T0, T1] + [T6, T7]  <- 前端 + 后端                     │
│  Rank 1: [T2, T3] + [T4, T5]  <- 中前 + 中后                     │
│  Rank 2: [T4, T5] + [T2, T3]  <- 中后 + 中前                     │
│  Rank 3: [T6, T7] + [T0, T1]  <- 后端 + 前端                     │
│                                                                 │
│  优势：                                                          │
│  1. 负载均衡：每个 rank 处理相同数量的 token                      │
│  2. Ring Attention 兼容：支持 P2P 通信                           │
│  3. 梯度正确性：保持计算图的连续性                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 CP 数据切片实现

```python
def slice_with_cp(tokens, pad_value, qkv_format="thd", max_seq_len=None):
    """将 token 序列按 Zigzag 模式分片到各 CP rank

    Args:
        tokens: 原始 token 张量 [seq_len]
        pad_value: 填充值
        qkv_format: "thd" (推荐) 或 "bshd"
        max_seq_len: bshd 模式需要的最大序列长度

    Returns:
        切片后的 token 张量
    """
    cp_rank = mpu.get_context_parallel_rank()
    cp_size = mpu.get_context_parallel_world_size()

    token_len = len(tokens)
    # 计算每个块的大小（向上取整）
    chunk_size = (token_len + 2 * cp_size - 1) // (2 * cp_size)

    # 填充到 2 * cp_size * chunk_size
    pad = 2 * cp_size * chunk_size - token_len
    tokens = F.pad(tokens, (0, pad), value=pad_value)

    # Zigzag 切片：取两个块
    start_1, end_1 = chunk_size * cp_rank, chunk_size * (cp_rank + 1)
    start_2, end_2 = chunk_size * (2 * cp_size - cp_rank - 1), chunk_size * (2 * cp_size - cp_rank)

    return torch.cat([tokens[start_1:end_1], tokens[start_2:end_2]])
```

### 4.3 Log Prob 的 CP 处理

```python
def get_logits_and_tokens_offset_with_cp(total_length, response_length, qkv_format="thd", max_seq_len=None):
    """计算 logits 和 tokens 在 CP 分布下的偏移量

    返回值说明：
    - chunk_size: 每个块的大小
    - chunks_offset: 两个块的位置范围
    - logits_offset: 两个 logits 块的位置范围（注意 -1 偏移）
    - tokens_offset: 两个 token 块的位置范围
    """
    cp_rank = mpu.get_context_parallel_rank()
    cp_size = mpu.get_context_parallel_world_size()
    prompt_length = total_length - response_length

    chunk_size = (total_length + 2 * cp_size - 1) // (2 * cp_size)

    # 两个块的位置（从 prompt 开头算起）
    chunk_0 = (cp_rank * chunk_size, (cp_rank + 1) * chunk_size)
    chunk_1 = ((2 * cp_size - cp_rank - 1) * chunk_size, (2 * cp_size - cp_rank) * chunk_size)

    # logits 需要额外 -1 偏移（因为 next token prediction）
    logits_0 = (max(chunk_0[0], prompt_length - 1), min(chunk_0[1], total_length - 1))
    logits_1 = (max(chunk_1[0], prompt_length - 1), min(chunk_1[1], total_length - 1))

    # 处理空切片：当 chunk 完全落在 prompt 区域（无 response token）时为空
    if logits_0[0] < logits_0[1]:
        token_0 = (logits_0[0] + 1, logits_0[1] + 1)
    else:
        logits_0 = (0, 0)
        token_0 = (0, 0)

    if logits_1[0] < logits_1[1]:
        token_1 = (logits_1[0] + 1, logits_1[1] + 1)
    else:
        logits_1 = (0, 0)
        token_1 = (0, 0)

    return chunk_size, (chunk_0, chunk_1), (logits_0, logits_1), (token_0, token_1)
```

### 4.4 AllReduce 重组 CP 数据

```python
def all_gather_with_cp(tensor, total_length, response_length):
    """将 CP 分布的张量通过 AllReduce 重组为完整张量

    流程：
    1. 根据偏移量确定当前 rank 的数据位置
    2. 创建完整大小的张量（缺失位置填零）
    3. AllReduce 聚合所有 rank 的贡献

    注意：使用 dist.nn.all_reduce 保持梯度流
    """
    cp_group = mpu.get_context_parallel_group()
    cp_size = mpu.get_context_parallel_world_size()

    if cp_size == 1:
        return tensor

    _, _, logits_offset, _ = get_logits_and_tokens_offset_with_cp(total_length, response_length)
    prompt_length = total_length - response_length

    # 分离两个块
    chunk_0 = tensor[: logits_offset[0][1] - logits_offset[0][0]]
    chunk_1 = tensor[logits_offset[0][1] - logits_offset[0][0] :]

    # 创建零填充函数
    def zero(length):
        return torch.zeros([length], dtype=tensor.dtype, device=tensor.device, requires_grad=True)

    # 构建完整张量模板（使用 AllReduce 而非 AllGather，通过零填充让各 rank 只贡献有效位置）
    if chunk_0.shape[0] == 0 and chunk_1.shape[0] == 0:
        # 两个 chunk 均为空：全零张量，但保留梯度流
        full_tensor = zero(response_length)
    elif chunk_0.shape[0] != 0 and chunk_1.shape[0] == 0:
        # 只有第一个 chunk 有数据
        left = zero(logits_offset[0][0] - (prompt_length - 1))
        right = zero(total_length - 1 - logits_offset[0][1])
        full_tensor = torch.cat([left, chunk_0, right], dim=0)
    elif chunk_0.shape[0] == 0 and chunk_1.shape[0] != 0:
        # 只有第二个 chunk 有数据（边界 case：Zigzag 切片时只有一个 chunk 落在 response 区域）
        left = zero(logits_offset[1][0] - (prompt_length - 1))
        right = zero(total_length - 1 - logits_offset[1][1])
        full_tensor = torch.cat([left, chunk_1, right], dim=0)
    else:
        # 两个 chunk 均有数据
        left = zero(logits_offset[0][0] - (prompt_length - 1))
        mid = zero(logits_offset[1][0] - logits_offset[0][1])
        right = zero(total_length - 1 - logits_offset[1][1])
        full_tensor = torch.cat([left, chunk_0, mid, chunk_1, right], dim=0)

    assert full_tensor.shape[0] == response_length, f"Expected {response_length}, got {full_tensor.shape}"
    # AllReduce 聚合：各 rank 只填充自己负责的位置，其余为零，求和后即为完整张量
    full_tensor = dist.nn.all_reduce(full_tensor, group=cp_group)
    return full_tensor
```

### 4.5 CP 损失累加器

**文件**：`slime/backends/megatron_utils/cp_utils.py`

CP 场景下，每个 rank 持有 Zigzag 切片后的 chunk，本地 token 数和 loss mask 与完整样本不同。`get_sum_of_sample_mean` 提供两种累加模式：

```python
def get_sum_of_sample_mean(
    total_lengths, response_lengths, loss_masks,
    calculate_per_token_loss=False, qkv_format="thd", max_seq_lens=None
):
    """计算 CP 分布下的正确样本均值（用于 PPO/GRPO 损失）

    关键点：CP 时张量已按 Zigzag 切分，必须按 chunk 累加后除以完整样本的 mask 数，
    而不能直接用本地 chunk 的 token 数做平均，否则会导致梯度偏差。
    """
    cp_size = mpu.get_context_parallel_world_size()
    if cp_size == 1:
        # 无 CP：直接按 response 长度 split
        def sum_of_sample_mean(x):
            return sum([
                (x_i * loss_mask_i).sum() / torch.clamp_min(loss_mask_i.sum(), 1)
                for x_i, loss_mask_i in zip(x.split(response_lengths, dim=0), loss_masks)
            ])
        def sum_of_token(x):
            return sum([
                (x_i * loss_mask_i).sum()
                for x_i, loss_mask_i in zip(x.split(response_lengths, dim=0), loss_masks)
            ])
    else:
        # 有 CP：预先将完整 loss mask 按 Zigzag 偏移切分为 chunk 级别
        cp_chunk_lengths = []
        chunked_loss_masks = []
        for i, (total_length, response_length, loss_mask) in enumerate(
            zip(total_lengths, response_lengths, loss_masks)
        ):
            max_seq_len = max_seq_lens[i] if max_seq_lens is not None else None
            prompt_length = total_length - response_length
            _, _, _, tokens_offset = get_logits_and_tokens_offset_with_cp(
                total_length, response_length, qkv_format, max_seq_len
            )
            # 从完整 loss_mask 中切出对应本地两个 chunk 的部分
            loss_mask_0 = loss_mask[
                tokens_offset[0][0] - prompt_length : tokens_offset[0][1] - prompt_length
            ]
            loss_mask_1 = loss_mask[
                tokens_offset[1][0] - prompt_length : tokens_offset[1][1] - prompt_length
            ]
            chunked_loss_masks.append(torch.cat([loss_mask_0, loss_mask_1], dim=0))
            cp_chunk_lengths.append(chunked_loss_masks[-1].size(0))

        def sum_of_sample_mean(x):
            # x 是 CP 分布后的张量，按 cp_chunk_lengths split
            return sum([
                (x_i * chunked_loss_mask).sum() / torch.clamp_min(loss_mask.sum(), 1)
                for x_i, chunked_loss_mask, loss_mask in zip(
                    x.split(cp_chunk_lengths, dim=0), chunked_loss_masks, loss_masks
                )
            ])
        def sum_of_token(x):
            return sum([
                (x_i * chunked_loss_mask).sum()
                for x_i, chunked_loss_mask in zip(
                    x.split(cp_chunk_lengths, dim=0), chunked_loss_masks
                )
            ])

    return sum_of_sample_mean if not calculate_per_token_loss else sum_of_token
```

**使用场景**：
- `calculate_per_token_loss=False`（默认）：PPO/GRPO policy loss，需要 per-sample mean
- `calculate_per_token_loss=True`：KL 散度等需要 token 级别求和的场景

### 4.6 CP 对数概率切片

**文件**：`slime/backends/megatron_utils/cp_utils.py`

Rollout 阶段生成的 `log_prob` 按自然顺序排列，而训练阶段 Actor 计算出的 `log_prob` 是 CP 分布的（Zigzag chunk 顺序）。`slice_log_prob_with_cp` 用于对齐两者：

```python
def slice_log_prob_with_cp(
    log_prob, total_length, response_length, qkv_format="thd", max_token_len=None
):
    """将完整序列的 log_prob 重排为 Zigzag CP chunk 顺序

    输入：按自然顺序排列的完整 response log_prob（长度 = response_length）
    输出：按 Zigzag chunk 顺序拼接的 log_prob（与 CP 后 Actor 输出对齐）
    """
    assert len(log_prob) == response_length
    cp_size = mpu.get_context_parallel_world_size()
    if cp_size == 1:
        return log_prob

    prompt_length = total_length - response_length
    _, _, logits_offset, _ = get_logits_and_tokens_offset_with_cp(
        total_length, response_length, qkv_format, max_token_len
    )

    # 从完整 response 的 log_prob 中切出两个 chunk 对应的部分
    chunk_1 = log_prob[
        logits_offset[0][0] - (prompt_length - 1) : logits_offset[0][1] - (prompt_length - 1)
    ]
    chunk_2 = log_prob[
        logits_offset[1][0] - (prompt_length - 1) : logits_offset[1][1] - (prompt_length - 1)
    ]

    if isinstance(log_prob, list):
        return chunk_1 + chunk_2
    else:
        return torch.cat([chunk_1, chunk_2], dim=0)
```

**典型用法**：
```python
# Rollout 阶段保存自然顺序的 old_log_prob
old_log_prob_full = rollout_log_probs  # [response_length]

# 训练阶段 Actor 计算 CP 分布的 new_log_prob
new_log_prob_chunked = actor_forward(...)  # CP 分布

# 对齐 old_log_prob 到 CP chunk 顺序
old_log_prob_chunked = slice_log_prob_with_cp(
    old_log_prob_full, total_length, response_length
)

# 计算 policy ratio（两者均为 CP 分布）
ratio = torch.exp(new_log_prob_chunked - old_log_prob_chunked)
```

### 4.7 AllGather CP 模式 (DSA)

Slime 支持 AllGather CP 模式，适用于 DSA（Direct Sliding Attention）：

```python
# AllGather CP 模式：先拼接所有序列，再整体切片
if allgather_cp:
    # 1. 拼接所有样本
    cu_seqlens = [0]
    for t in tokens:
        cu_seqlens.append(cu_seqlens[-1] + t.size(0))
    tokens = torch.cat(tokens, dim=0)

    # 2. 全局填充，使能均匀切分
    global_pad_size = cp_size * pad_multiplier
    pad = (global_pad_size - tokens.size(0) % global_pad_size) % global_pad_size
    tokens = F.pad(tokens, (0, pad), value=pad_token_id)

    # 3. 按 CP rank 切片
    tokens = tokens.chunk(cp_size, dim=0)[cp_rank]
```

**AllGather CP vs Zigzag CP 对比**：

| 特性 | Zigzag CP | AllGather CP |
|-----|----------|-------------|
| 切片模式 | 每样本两块 | 全局一整块 |
| 通信模式 | Ring Attention | AllGather + AllReduce |
| 适用场景 | 短-中序列 | 超长序列 |
| 显存效率 | 更高 | 略低 |
| 通信效率 | P2P 点对点 | 集合通信 |

## 5. 分布式统计量计算

### 5.1 跨 GPU 白化归一化

PPO 训练需要对 advantages 进行全局归一化：

```python
def distributed_masked_whiten(values, mask, process_group=None, shift_mean=True, epsilon=1e-8):
    """使用全局统计量进行白化归一化

    计算流程：
    1. 各 rank 计算本地统计量（sum, sum_sq, count）
    2. AllReduce 聚合全局统计量
    3. 使用全局均值和方差进行本地归一化

    数学：
    whitened = (values - global_mean) / sqrt(global_var + epsilon)
    """
    # 1. 本地统计量
    local_sum = (values * mask).sum()
    local_sum_sq = ((values**2) * mask).sum()
    local_mask_sum = mask.sum()

    stats_tensor = torch.tensor([local_sum, local_sum_sq, local_mask_sum], device=values.device)

    # 2. AllReduce 聚合
    dist.all_reduce(stats_tensor, group=process_group)

    # 3. 计算全局统计量
    global_sum, global_sum_sq, global_mask_sum = stats_tensor
    global_mean = global_sum / global_mask_sum
    global_var = global_sum_sq / global_mask_sum - global_mean**2

    # Bessel 校正（无偏估计）
    if global_mask_sum >= 2:
        global_var *= global_mask_sum / (global_mask_sum - 1)

    # 4. 白化
    whitened = (values - global_mean) * torch.rsqrt(global_var + epsilon)

    if not shift_mean:
        whitened += global_mean

    return whitened
```

## 6. 序列长度均衡

### 6.1 Karmarkar-Karp 算法

用于将变长序列均衡分配到多个分区：

```python
def get_seqlen_balanced_partitions(seqlen_list, k_partitions, equal_size=False):
    """将序列均衡分配到 k 个分区

    算法：Karmarkar-Karp（差分法）
    1. 对序列长度降序排序
    2. 使用最大堆维护分区状态
    3. 每次将序列分配到当前最小的分区
    4. 合并分区状态直到只剩一个

    参数：
    - seqlen_list: 各序列的长度列表
    - k_partitions: 分区数量
    - equal_size: 是否要求各分区样本数相等

    返回：
    - partitions: k 个列表，每个包含样本索引
    """
    partitions = karmarkar_karp(
        seqlen_list=seqlen_list,
        k_partitions=k_partitions,
        equal_size=equal_size
    )
    return partitions
```

## 7. 同步原语与集合通信

### 7.1 常用集合通信

| 操作 | 用途 | 实现 |
|-----|------|-----|
| `all_reduce` | 聚合梯度和统计量 | `dist.all_reduce(tensor, group=group)` |
| `all_gather` | 收集所有 rank 的数据 | `dist.all_gather(tensor_list, tensor, group=group)` |
| `broadcast` | 从源 rank 广播数据 | `dist.broadcast(tensor, src=rank, group=group)` |
| `reduce_scatter` | 聚合后分片 | Megatron DDP 内部使用 |
| `all_to_all` | MoE 专家路由 | Megatron MoE 内部使用 |

### 7.2 异步通信优化

```python
# 异步通信模式
handles = []

# 发起异步操作
for tensor in tensors:
    handles.append(dist.all_reduce(tensor, async_op=True))

# 执行其他计算
do_other_work()

# 等待所有通信完成
for handle in handles:
    handle.wait()
```

## 8. 性能优化注意事项

### 8.1 并行度配置建议

```bash
# 原则：先 TP，再 PP，最后 DP
# TP 通信最频繁，尽量让同 TP 组的 GPU 在同一节点

# 小模型 (< 7B)
--tensor-model-parallel-size 1
--pipeline-model-parallel-size 1
--context-parallel-size 1

# 中型模型 (7B - 70B)
--tensor-model-parallel-size 4
--pipeline-model-parallel-size 2
--context-parallel-size 1

# 大模型 (70B+)
--tensor-model-parallel-size 8
--pipeline-model-parallel-size 4
--context-parallel-size 4  # 长序列场景

# MoE 模型
--expert-model-parallel-size 8
--expert-tensor-parallel-size 1
```

### 8.2 CP 优化建议

| 场景 | 推荐配置 | 原因 |
|-----|---------|------|
| 短序列 (< 4K) | `--context-parallel-size 1` | CP 开销大于收益 |
| 中序列 (4K-32K) | `--context-parallel-size 4` | Zigzag CP 足够 |
| 长序列 (32K+) | `--context-parallel-size 8` + `--allgather-cp` | DSA 模式更高效 |
| 超长序列 (128K+) | `--context-parallel-size 16` + `--qkv-format thd` | 必须用 THD 格式 |

### 8.3 通信优化配置

```bash
# 梯度同步重叠
--overlap-grad-reduce           # 反向传播时异步同步梯度
--align-grad-reduce             # 对齐梯度同步时机

# 参数同步重叠（Distributed Optimizer）
--overlap-param-gather          # 前向传播时异步获取参数
--align-param-gather            # 对齐参数获取时机

# NCCL 优化
export NCCL_ALGO=RING           # 大消息用 Ring
export NCCL_PROTO=SIMPLE        # 小消息用 Simple
export NCCL_MIN_NCHANNELS=4     # 增加通道数
```

### 8.4 常见问题与解决方案

#### 问题1：CP 通信死锁
```
原因：某些 rank 没有参与通信（空切片）
解决：添加 dummy loss 保持梯度流
```
```python
if args.allgather_cp and mpu.get_context_parallel_world_size() > 1:
    loss = loss + 0 * logits.sum()  # 强制梯度流
```

#### 问题2：TP 通信成为瓶颈
```
原因：TP 组跨节点，IB 带宽不足
解决：调整拓扑，使 TP 组在同一节点内
```

#### 问题3：CP 显存不均衡
```
原因：Zigzag 切片导致不同 rank 的有效数据量不同
解决：使用动态批次大小 + 序列长度均衡
```
