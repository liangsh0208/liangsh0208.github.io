# Slime 模型架构实现原理

> **【源码定位】** `slime/backends/megatron_utils/model_provider.py`, `slime/backends/megatron_utils/model.py`  
> **【阅读建议】** 需理解 Megatron-LM 的 ParallelTransformer 设计  
> **【前置知识】** HuggingFace Transformers 配置、Transformer 模型结构、LoRA/PEFT 基础

## 1. 模块概述

模型架构模块定义了 Slime 训练框架中的**核心模型结构**，包括 Actor（策略模型）、Critic（价值模型）、Reference Model 等角色的设计与创建。该模块基于 Megatron-LM 的 GPT 模型构建，支持通过 **HuggingFace Bridge** 从预训练模型初始化，提供灵活的参数冻结配置。

**关键设计决策【重点】**：
1. **统一架构**：Actor/Critic 共享底层 Transformer，仅输出层不同
2. **Bridge 机制**：支持从 HF 权重无缝初始化 Megatron 模型（自动映射并行维度）
3. **角色感知 ModelProvider**：根据 role="actor/critic/ref" 动态调整输出层维度
4. **参数冻结**：支持正则表达式匹配，可精确控制可训练参数范围

## 2. Actor-Critic 双模型架构

### 2.1 架构设计

```
┌─────────────────────────────────────────────────────────────────┐
│                    Actor-Critic 架构                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    Actor Model (策略模型)                 │   │
│  │                                                          │   │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────────┐  │   │
│  │  │ Embedding   │  │ Transformer │  │ Output Layer    │  │   │
│  │  │ Layer       │ ->│ Layers      │ ->│ (LM Head)      │  │   │
│  │  │ [vocab,dim] │  │ ×N layers   │  │ [hidden, vocab] │  │   │
│  │  └─────────────┘  └─────────────┘  └─────────────────┘  │   │
│  │                                                          │   │
│  │  输出：logits → log_probs → 用于 PPO 策略更新            │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    Critic Model (价值模型)               │   │
│  │                                                          │   │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────────┐  │   │
│  │  │ Embedding   │  │ Transformer │  │ Output Layer    │  │   │
│  │  │ Layer       │ ->│ Layers      │ ->│ (Value Head)   │  │   │
│  │  │ [vocab,dim] │  │ ×N layers   │  │ [hidden, 1]     │  │   │
│  │  └─────────────┘  └─────────────┘  └─────────────────┘  │   │
│  │                                                          │   │
│  │  输出：value (标量) → 用于 GAE 计算 returns              │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  共享：Embedding 和 Transformer 层结构相同                      │
│  差异：输出层维度不同（vocab vs 1）                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 角色职责

| 模型角色 | 输出 | 训练目标 | 在 PPO 中的作用 |
|---------|------|---------|----------------|
| **Actor** | logits → log_probs | 最大化 advantage | 策略优化，生成动作概率 |
| **Critic** | value (scalar) | 最小化 value error | 估计状态价值，计算 GAE |

### 2.3 Reference Model

```
┌─────────────────────────────────────────────────────────────────┐
│                    Reference Model 作用                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Actor Model (可训练)     Reference Model (冻结)               │
│  ┌─────────────────┐      ┌─────────────────┐                 │
│  │ 当前策略 π_θ    │      │ 初始策略 π_ref  │                 │
│  └─────────────────┘      └─────────────────┘                 │
│          │                        │                            │
│          ▼                        ▼                            │
│      log_probs              ref_log_probs                      │
│          │                        │                            │
│          └────────┬───────────────┘                            │
│                   ▼                                            │
│              KL 散度计算                                       │
│                                                                 │
│  KL(π_θ || π_ref) ≈ log_probs - ref_log_probs                  │
│                                                                 │
│  作用：防止策略偏离初始策略太远，保证训练稳定性                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 模型提供者 (Model Provider)

### 3.1 设计模式

模型提供者采用工厂模式，根据角色动态创建模型：

```python
def get_model_provider_func(args, role="actor"):
    """获取模型提供者函数

    三种创建路径：
    1. 自定义模型提供者（--custom-model-provider-path）
    2. HuggingFace Bridge（推荐，--megatron-to-hf-mode bridge）
    3. 原生 Megatron GPTModel
    """
    # 路径1：自定义模型
    if args.custom_model_provider_path:
        return wrapped_custom_model_provider

    # 路径2：HuggingFace Bridge
    if args.megatron_to_hf_mode == "bridge":
        bridge = AutoBridge.from_hf_pretrained(args.hf_checkpoint)
        provider = bridge.to_megatron_provider(load_weights=False)

        # 设置并行参数
        provider.tensor_model_parallel_size = args.tensor_model_parallel_size
        provider.pipeline_model_parallel_size = args.pipeline_model_parallel_size
        provider.expert_model_parallel_size = args.expert_model_parallel_size
        provider.context_parallel_size = args.context_parallel_size

        # Critic 特殊处理：替换输出层
        if role == "critic":
            return _critic_provider

        return provider.provide

    # 路径3：原生 Megatron
    return model_provider
```

### 3.3 配置验证

```python
def _hf_validate_args(args, hf_config):
    """验证 HF 配置与 Megatron 参数一致性

    防止因参数不匹配导致模型结构错误
    """
    errors = []

    # 必须相等的配置
    validations = [
        ("hidden_size", "hidden_size", equal),
        ("num_attention_heads", "num_attention_heads", equal),
        ("num_hidden_layers", "num_layers", equal),
        ("intermediate_size", "ffn_hidden_size", equal),
        ("rms_norm_eps", "norm_epsilon", equal),
        ("rope_theta", "rotary_base", equal),
        # 特殊：tie_word_embeddings 与 untie... 是相反的
        ("tie_word_embeddings", "untie_embeddings_and_output_weights", lambda x, y: not x == y),
    ]

    for hf_name, megatron_name, compare_fn in validations:
        if hasattr(hf_config, hf_name):
            if not compare_fn(getattr(hf_config, hf_name), getattr(args, megatron_name)):
                errors.append(f"Config mismatch: {hf_name} vs {megatron_name}")

    if errors:
        raise AssertionError("HF validation failed: " + "; ".join(errors))
```

## 4. Critic 输出层设计

### 4.1 LinearForLastLayer 实现

```python
class LinearForLastLayer(torch.nn.Linear):
    """Critic 模型的专用输出层

    与 Actor 的 LM Head 区别：
    1. 输出维度为 1（Value 预测，而非 vocab 大小）
    2. 支持 Sequence Parallel
    3. 自动转换为 FP32 提高数值稳定性
    """

    def __init__(self, input_size, output_size=1, config=None, bias=True):
        super().__init__(in_features=input_size, out_features=output_size, bias=bias)

        self.sequence_parallel = config.sequence_parallel
        if self.sequence_parallel:
            self.weight.sequence_parallel = True
            if bias:
                self.bias.sequence_parallel = True

        # 初始化
        self.weight.data.normal_(mean=0.0, std=0.02)
        if bias:
            self.bias.data.zero_()

    def forward(self, input_, weight=None, runtime_gather_output=None):
        # 前向计算
        logits = super().forward(input_)

        # 转换为 FP32（数值稳定性）
        logits = logits.float()

        # Sequence Parallel 时需要 gather
        if self.sequence_parallel:
            logits = tensor_parallel.gather_from_sequence_parallel_region(
                logits,
                tensor_parallel_output_grad=False
            )

        return logits, None
```

### 4.2 输出层替换流程

```python
def get_model_provider_func(args, role="actor"):
    # ... 获取 provider ...

    if role == "critic":
        _original_provide = provider.provide

        def _critic_provide(pre_process=True, post_process=True, vp_stage=None):
            model = _original_provide(pre_process, post_process, vp_stage)

            # 替换输出层为 Value Head
            if post_process:
                model.output_layer = LinearForLastLayer(
                    input_size=model.config.hidden_size,
                    output_size=1,  # 关键：输出为 1
                    config=model.config
                )

            return model

        return _critic_provide
```

## 6. 参数冻结

### 6.1 冻结策略

```python
def freeze_model_params(model, args):
    """选择性参数冻结

    用途：
    - 冻结底层参数，仅训练顶层（layer-wise fine-tuning）
    - 冻结特定模块（如 Embedding、attention）
    - 支持 LoRA 等参数高效微调
    """

    # 方式1：仅训练匹配的参数
    if args.only_train_params_name_list:
        for name, param in model.named_parameters():
            param.requires_grad = False  # 默认冻结
            for pattern in args.only_train_params_name_list:
                if re.search(pattern, name):
                    param.requires_grad = True  # 匹配的参数可训练
                    break

    # 方式2：冻结匹配的参数
    if args.freeze_params_name_list:
        for name, param in model.named_parameters():
            for pattern in args.freeze_params_name_list:
                if re.search(pattern, name):
                    param.requires_grad = False
                    break
```

### 6.2 常用冻结模式

```bash
# 仅训练最后几层
--only-train-params-name-list "layers\.3[0-9]\." "layers\.4[0-9]\."

# 冻结 Embedding 层
--freeze-params-name-list "embedding" "word_embeddings"

# 仅训练 Attention（LoRA 场景）
--only-train-params-name-list "attention" "query" "key" "value"
```

### 6.3 与模型提供者集成

```python
def wrap_model_provider_with_freeze(original_provider, args):
    """包装模型提供者，注入参数冻结逻辑"""

    def wrapped_provider(pre_process=True, post_process=True, vp_stage=None):
        model = original_provider(pre_process, post_process, vp_stage)

        # 创建模型后立即冻结参数
        freeze_model_params(model, args)

        return model

    return wrapped_provider

# 使用方式
model = get_model(
    wrap_model_provider_with_freeze(get_model_provider_func(args, role), args),
    ModelType.encoder_or_decoder
)
```

```python
from megatron.core.models.gpt import GPTModel
from megatron.core.transformer.transformer_config import TransformerConfig

def custom_model_provider(pre_process=True, post_process=True, vp_stage=None):
    """自定义模型提供者 - 添加特殊层或修改架构"""

    # 创建标准 GPT 模型
    config = TransformerConfig.from_args(get_args())

    model = GPTModel(
        config=config,
        transformer_layer_spec=get_gpt_layer_with_transformer_engine_spec(),
        vocab_size=args.padded_vocab_size,
        max_sequence_length=args.max_position_embeddings,
        pre_process=pre_process,
        post_process=post_process,
    )

    # 添加自定义层（例如：领域适配层）
    if args.add_domain_adapter:
        model.domain_adapter = DomainAdapterLayer(config.hidden_size)

    # 加载预训练权重
    if args.load:
        load_pretrained_weights(model, args.load)

    return model
```

```python
# critic_init.py
# 当 Critic 需要从不同架构初始化时

def create_critic_model(args):
    """Critic 可能与 Actor 不同架构（如更小的模型）"""

    # 保存原配置
    original_checkpoint = args.hf_checkpoint
    original_size = args.hidden_size

    # 改用 Critic 专用配置
    args.hf_checkpoint = args.critic_hf_checkpoint or args.hf_checkpoint
    args.hidden_size = args.critic_hidden_size or args.hidden_size
    args.num_layers = args.critic_num_layers or args.num_layers

    # 创建 Critic
    provider = get_model_provider_func(args, role="critic")
    critic_model = get_model(provider, ModelType.encoder_or_decoder)

    # 恢复 Actor 配置
    args.hf_checkpoint = original_checkpoint
    args.hidden_size = original_size

    return critic_model
```

## 9. 模型架构参数速查表

### 9.1 模型来源与加载

| 参数 | 类型 | 默认值 | 说明 | 使用建议 |
|------|------|--------|------|---------|
| `--hf-checkpoint` | str | None | HF 模型路径 | 训练起点，支持本地路径或 Hub ID |
| `--load` | str | None | Checkpoint 路径 | 断点续训时使用 |

### 9.2 模型结构参数

| 参数 | 类型 | 默认值 | 说明 | 关联并行策略 |
|------|------|--------|------|-------------|
| `--hidden-size` | int | None | 隐藏层维度 | 决定模型大小 |
| `--num-layers` | int | None | Transformer 层数 | 与 PP 切分相关 |

| `--vocab-size` | int | None | 词表大小 | 自动推断但可覆盖 |
| `--seq-length` | int | 4096 | 最大序列长度 | 影响显存和 CP 切分 |

## 10. 常见问题与排查

### 10.1 配置不匹配错误

**问题**：`hf_validate_args failed: hidden_size in hf config 4096 is not equal to hidden_size 8192`

**原因**：命令行参数与 HF config.json 不一致

**解决方案**：
```bash
# 方式1：不覆盖配置，让 Bridge 自动推断
python train.py \
    --hf-checkpoint "Qwen/Qwen2.5-7B" \
    # 不要手动设置 --hidden-size

# 方式2：覆盖时确保一致
python train.py \
    --hf-checkpoint "Qwen/Qwen2.5-7B" \
    --hidden-size 4096  # 与 HF config 完全一致
```

### 10.2 Critic 输出维度错误

**问题**：`size mismatch for output_layer.weight: copying a param with shape [vocab, hidden] from checkpoint, the shape in current model is [1, hidden]`

**原因**：从 Actor checkpoint 加载到 Critic 模型（Actor 输出为 vocab，Critic 输出为 1）

**解决方案**：
```bash
# 方式1：Critic 使用独立 checkpoint
--critic-load "/checkpoints/critic/iter_0000100"

# 方式2：Critic 从 HF 重新初始化
--hf-checkpoint "Qwen/Qwen2.5-7B" \
--load "/checkpoints/actor/iter_0000100" \
--critic-from-hf  # 特殊标记，表示 Critic 从 HF 初始化而非 --load
```

### 10.3 参数冻结不生效

**问题**：设置了 `--freeze-params-name-list` 但参数仍在更新

**检查步骤**：
```python
# Step 1: 查看实际参数名
model = provider(pre_process=True, post_process=True)
for name, param in model.named_parameters():
    print(f"{name}: requires_grad={param.requires_grad}, shape={param.shape}")

# Step 2: 验证正则匹配
import re
patterns = args.freeze_params_name_list or []
for name, param in model.named_parameters():
    for pattern in patterns:
        if re.search(pattern, name):
            print(f"Match: '{pattern}' -> '{name}'")

# Step 3: 检查冻结执行时机
# ⚠️ 冻结必须在 optimizer 创建之前！
freeze_model_params(model, args)  # 创建后立即冻结
optimizer = create_optimizer()    # 然后创建优化器
```

**常见错误对照表**：
| 错误写法 | 正确写法 | 说明 |
|---------|---------|------|
| `layer.30` | `layers\.3[0-9]\."` | 需要转义点号 `.` |
| `attention` | `self_attention` | 实际参数名需确认 |
| `--freeze_params_name_list` | `--freeze-params-name-list` | 命令行用短横线 |
| `['embedding', 'lm_head']` | `"embedding" "lm_head"` | 命令行不用方括号 |

### 10.4 Bridge 加载失败

**问题**：`AutoBridge.from_hf_pretrained` 失败

**诊断脚本**：
```python
# debug_bridge.py
import transformers
print(f"Transformers version: {transformers.__version__}")

# 检查 transformers 是否能加载
from transformers import AutoConfig, AutoModel
try:
    config = AutoConfig.from_pretrained("your-model", trust_remote_code=True)
    print(f"Config loaded: {config}")

    # 尝试加载模型（仅权重）
    model = AutoModel.from_config(config)
    print(f"Model created successfully")
except Exception as e:
    print(f"Load failed: {e}")
    import traceback
    traceback.print_exc()
```

**解决方案**：
1. 更新 transformers: `pip install -U transformers`
2. 添加 `--trust-remote-code`
3. 检查模型是否支持 Bridge 转换（部分自定义架构可能不支持）
4. 最后手段：使用 `--megatron-to-hf-mode raw` 降级到原始模式

## 12. 插件系统与自定义模型

Slime 通过 `slime_plugins/` 目录支持**插件化扩展**，允许在不修改核心代码的情况下接入自定义模型架构、注意力内核、桥接器和 Rollout Buffer。

### 12.1 插件目录结构

```
slime_plugins/
├── models/                    # 自定义模型组件
│   ├── flash_dot_product_attention.py
│   ├── learnable_softmax_attention.py
│   ├── glm5/                  # GLM5 + TileLang sparse MLA
│   ├── qwen3_5.py
│   └── gpt_oss.py
├── mbridge/                   # HF ↔ Megatron 桥接适配器
│   ├── glm4.py, glm4moe.py
│   ├── deepseek_v32.py
│   ├── qwen3_5.py, qwen3_next.py
│   └── gpt_oss.py, mimo.py
├── megatron_bridge/           # Megatron 专用桥接
│   └── glm4v_moe.py
└── rollout_buffer/            # 自定义 Rollout Buffer
    ├── buffer.py
    └── generator/
```

### 12.2 自定义 Attention 模块

当 Transformer Engine (TE) 不支持某些特性组合时（如 learnable softmax + THD packed sequences），可以通过 `slime_plugins/models/flash_dot_product_attention.py` 绕过 TE，直接使用 Flash Attention。

```python
from slime_plugins.models.flash_dot_product_attention import FlashDotProductAttention

# 在自定义 model provider 中使用
config.softmax_type = "learnable"  # 或 "vanilla", "off-by-one"
attention = FlashDotProductAttention(config, layer_number=1, attn_mask_type=AttnMaskType.causal, ...)
```

**支持特性**：
- THD packed sequences（变长序列批处理）
- Learnable softmax（per-head 可学习 offset，作为 attention sink）
- Sliding window attention
- Context Parallel (P2P)

### 12.3 模型桥接插件 (mbridge)

`mbridge/` 目录下存放特定模型的 **HF ↔ Megatron 权重映射和配置转换**逻辑。当官方 Bridge 不支持某模型时，可在此编写自定义映射：

| 文件 | 模型 | 说明 |
|-----|------|------|
| `glm4.py` / `glm4moe.py` | GLM-4 / GLM-4-MoE | 智谱模型桥接 |
| `deepseek_v32.py` | DeepSeek-V3.2 | DeepSeek 系列 |
| `qwen3_5.py` / `qwen3_next.py` | Qwen3.5 / Qwen3 | 阿里模型桥接 |
| `gpt_oss.py` | GPT-OSS | OpenAI OSS 系列 |
| `mimo.py` | MiMo | 特定架构 |

**使用方式**：训练时 `--custom-model-provider-path` 指向包含对应 logic 的文件，或在 `custom_hf_to_megatron` 中注册。

### 12.4 GLM5 与 TileLang 稀疏 MLA

`slime_plugins/models/glm5/` 是 Slime 插件系统的典型复杂案例：

- `glm5.py`：GLM5 主模型定义
- `ops/sparse_mla.py`：稀疏 MLA（Multi-Latent Attention）逻辑
- `ops/tilelang_sparse_mla_*.py`：使用 TileLang DSL 编译的稀疏 MLA CUDA 内核（前后向）
- `ops/tilelang_indexer_*.py`：索引操作的 TileLang 内核

这展示了插件系统可以承载**完整的高性能自定义内核**而不污染核心框架代码。

### 12.5 自定义 Rollout Buffer

`slime_plugins/rollout_buffer/` 支持替换默认的 Rollout Buffer 实现：

```python
from slime_plugins.rollout_buffer.buffer import CustomRolloutBuffer

# 在训练脚本中指定使用自定义 buffer
```

### 12.6 接入自定义模型

```bash
# 方式1：使用自定义 model provider（完全替换架构）
--custom-model-provider-path "slime_plugins/models/glm5/glm5.py:model_provider"

# 方式2：使用自定义 layer spec（仅替换层定义）
--spec "slime_plugins.models.flash_dot_product_attention:FlashDotProductAttention"

# 方式3：自定义 Bridge（权重映射）
--custom-hf-to-megatron "slime_plugins.mbridge.deepseek_v32"
```
