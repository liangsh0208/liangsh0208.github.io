# Slime 参数配置速查手册

> 源码: `slime/slime/utils/arguments.py` / `slime/backends/sglang_utils/arguments.py` / `slime/backends/megatron_utils/arguments.py`

## 一、运行模式

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--train-backend` | str | `megatron` | 训练后端，当前只支持 `megatron` |
| `--debug-rollout-only` | flag | — | 仅采集 rollout 数据（不启动训练/sglang），数据保存后退出 |
| `--debug-train-only` | flag | — | 仅执行训练，需配合 `--load-debug-rollout-data` 复用预采数据 |
| `--load-debug-rollout-data` | str | — | 加载预采样的 rollout `.pt` 数据路径 |
| `--debug-rollout-data-subsample` | float | — | 对预采数据按比例子采样，加速调试 |

## 二、集群资源（Ray）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--actor-num-nodes` | int | `1` | Actor 训练节点数 |
| `--actor-num-gpus-per-node` | int | `8` | Actor 每节点 GPU 数 |
| `--critic-num-nodes` | int | 默认同 actor | Critic 训练节点数 |
| `--critic-num-gpus-per-node` | int | 默认同 actor | Critic 每节点 GPU 数 |
| `--rollout-num-gpus` | int | — | SGLang/rollout 总 GPU 数。`--colocate` 时强制等于 actor GPU 总数 |
| `--rollout-num-gpus-per-engine` | int | `1` | 每个 SGLang engine 占用的 GPU 数（对应 SGLang TP size） |
| `--num-gpus-per-node` | int | `8` | 每节点 GPU 数（colocate 场景下用于非满卡部署） |
| `--colocate` | flag | — | 训练 Actor 与 SGLang engine **共享 GPU**（自动开启 offloading） |
| `--offload` | flag | — | 同时开启 `offload-train` + `offload-rollout` |
| `--offload-train` | bool | `False` | 训练时将 Actor 权重 offload 到 CPU |
| `--offload-rollout` | bool | `False` | rollout 时将 SGLang 权重 offload 到 CPU |

## 三、模型加载与 Checkpoint

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--hf-checkpoint` | str | — | 标准 HuggingFace 格式模型路径（提供 tokenizer + 初始结构） |
| `--model-name` | str | 自动推导 | 模型名称（影响 weight 转换时的 layer name 映射） |
| `--ref-load` | str | — | Reference 模型（分布式格式）路径 |
| `--ref-ckpt-step` | int | — | 加载 Reference 模型的指定 step |
| `--load` | str | — | 训练续接的 checkpoint 目录 |
| `--save` | str | — | checkpoint 保存目录（**必填**，当 `--save-interval` 被指定时） |
| `--save-interval` | int | — | 每 N 个 rollout 保存一次 checkpoint |
| `--async-save` | flag | `False` | 异步保存 checkpoint |
| `--no-save-optim` | flag | `False` | 保存时不含 optimizer state，减小体积，但不可 resume |
| `--save-hf` | str | — | **自动导出 HF 格式**路径，支持 `{rollout_id}` Python format，与 `--save` 同时触发 |

### 📌 自动导出 HF 格式的用法

```bash
CKPT_ARGS=(
   --save "/path/to/save"
   --save-interval 20
   --save-hf "/path/to/save_hf/iter_{rollout_id:05d}"    # 自动导出
)
```

> 注意：`{rollout_id:05d}` 是 **Python `.format()` 语法**，不是 shell 变量，会被 `model.py` 中的代码 format 成实际步号。

## 四、数据与 Batch

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--prompt-data` | str | — | 训练数据路径（`.jsonl`） |
| `--input-key` | str | `input` | 数据 JSON 中 prompt 字段名 |
| `--label-key` | str | — | 数据 JSON 中 label/答案字段名 |
| `--apply-chat-template` | flag | `False` | 对 prompt 应用 HF chat-template |
| `--apply-chat-template-kwargs` | JSON | `{}` | chat-template 额外参数 |
| `--metadata-key` | str | `metadata` | 元数据字段名 |
| `--tool-key` | str | `tools` | tools 字段名（function call 场景） |
| `--multimodal-keys` | JSON | — | 多模态映射，如 `{"image": "image_file"}` |
| `--rollout-batch-size` | int | **必填** | 每轮 rollout 采样的 prompt 数量 |
| `--n-samples-per-prompt` | int | `1` | 每个 prompt 生成回答数（GRPO 常用 8~16） |
| `--over-sampling-batch-size` | int | 同 rollout-batch-size | 抽样粒度，用于 partial rollout 场景 |
| `--num-rollout` | int | — | 总 rollout 步数（与 `--num-epoch` 二选一） |
| `--num-epoch` | int | — | 训练 epoch 数（自动计算 rollout 步数，需开启 global dataset） |
| `--rollout-shuffle` | flag | — | rollout 时打乱 prompt |
| `--rollout-seed` | int | `42` | rollout 采样随机种子 |
| `--start-rollout-id` | int | — | 从指定步数续训（默认同 `--load` 中已保存的步数） |
| `--rollout-global-dataset` | bool | `True` | 使用全局数据集（禁用需加 `--disable-rollout-global-dataset`） |
| `--global-batch-size` | int | — | 训练 global batch size（样本维度） |
| `--micro-batch-size` | int | `1` | 训练 micro batch size（每张卡的 batch） |
| `--num-steps-per-rollout` | int | — | 每个 rollout 分几步训练（等价于调整 gbs） |
| `--balance-data` | flag | — | DP rank 间用 karmarkar-karp 均衡 token 数 |
| `--use-dynamic-batch-size` | flag | — | 根据 `max-tokens-per-gpu` 动态拆分 micro-batch |
| `--max-tokens-per-gpu` | int | — | 单卡最大 token 数（动态 batch 阈值） |
| `--log-probs-max-tokens-per-gpu` | int | 同 max-tokens | 计算 log p 时的单卡 token 上限 |
| `--data-pad-size-multiplier` | int | `128` | 数据 padding 对齐倍数 |

### 📌 Batch Size 关系速查

```
总样本量 = rollout_batch_size × n_samples_per_prompt
训练步数 per rollout = 总样本量 / global_batch_size = num_steps_per_rollout 的等价含义
```

## 六、RL 算法核心

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--advantage-estimator` | str | `grpo` | 优势估计器：`grpo`/`gspo`/`reinforce_plus_plus`/`reinforce_plus_plus_baseline`/`ppo` |
| `--use-kl-loss` | flag | `False` | 使用 KL loss（GRPO 需单独开启） |
| `--kl-loss-coef` | float | `0.0` | KL loss 系数（加到最终 loss） |
| `--kl-loss-type` | str | `k1` | KL loss 计算方式：`k1`/`k2`/`k3`/`low_var_kl` |
| `--kl-coef` | float | `0.0` | **奖励 shaping 阶段**的 KL 惩罚（reward 信号中减） |
| `--use-unbiased-kl` | flag | `False` | 无偏 KL 估计 |
| `--eps-clip` | float | `0.2` | PPO / GRPO 截断范围下界 |
| `--eps-clip-high` | float | 同 eps-clip | PPO 截断范围上界 |
| `--eps-clip-c` | float | — | Dual-clip PPO 下界 |
| `--normalize-advantages` | flag | `False` | 标准化 advantages（`reinforce_plus_plus` 强制需要） |
| `--disable-grpo-std-normalization` | flag | — | 禁用 GRPO 组内 std 归一化（Dr.GRPO 论文做法） |
| `--disable-rewards-normalization` | flag | — | 禁用 reward 归一化 |
| `--entropy-coef` | float | `0.0` | 熵正则系数 |
| `--gamma` | float | `1.0` | GAE gamma |
| `--lambd` | float | `1.0` | GAE lambda |
| `--loss-type` | str | `policy_loss` | loss 类型：`policy_loss`/`sft_loss`/`custom_loss` |
| `--ref-update-interval` | int | — | Ref 模型更新间隔（从 actor 同步权重） |

### 📌 GRPO 常用配置示例

```bash
--advantage-estimator grpo
--use-kl-loss
--kl-loss-coef 0.00
--kl-loss-type low_var_kl
--eps-clip 0.2 --eps-clip-high 0.28
--disable-rewards-normalization
--disable-grpo-std-normalization
```

## 十八、SGLang 参数（`--sglang-*` 前缀）

> **底层来源**: `sglang.srt.server_args.ServerArgs`

所有 SGLang 原生参数都被 slime 自动以 `--sglang-<原参数名>` 注入。以下是训练脚本中最常配置的：

| 参数 | 说明 |
|------|------|
| `--sglang-mem-fraction-static` | 静态显存占用比例（`0.0~1.0`，默认由 SGLang 决定） |
| `--sglang-tp-size` / `--sglang-tensor-parallel-size` | Tensor Parallel size（通常由 `--rollout-num-gpus-per-engine` 自动推导） |
| `--sglang-dp-size` / `--sglang-data-parallel-size` | Data Parallel size（默认为 1） |
| `--sglang-pipeline-parallel-size` | Pipeline Parallel size（默认 `1`） |
| `--sglang-expert-parallel-size` | Expert Parallel size（MoE 模型用） |
| `--sglang-quantization` | 量化方式：`fp8`/`awq`/`gptq` 等 |
| `--sglang-max-model-len` | SGLang 最大模型长度 |
| `--sglang-trust-remote-code` | 信任远程代码（slime 已强制开启） |
| `--sglang-schedule-policy` | 调度策略：`fcfs`/`lora` 等 |
| `--sglang-enable-return-hidden-states` | 返回 hidden states |

### 📌 SGLang 常用配置

SGLANG_ARGS=(

    --rollout-num-gpus-per-engine 2
    --sglang-mem-fraction-static 0.7

## 参数作用域速查图

```
sys.argv
  ├─ _pre_parse_mode()
  │    └─ train-backend / debug-rollout-only / debug-train-only / load-debug-rollout-data
  │
  ├─ sglang_parse_args()
  │    └─ 所有 --sglang-* 参数 → 统一加 sglang_ 前缀
  │
  └─ megatron_parse_args(extra_args_provider=add_slime_arguments)
       ├─ Megatron 原生参数（--tp / --pp / --lr / --global-batch-size / ...）
       ├─ Slime 自定义参数（--actor-num-* / --rollout-* / --advantage-estimator / ...）
       │     ├─ cluster_arguments()
       │     ├─ train_arguments()
       │     ├─ rollout_arguments()
       │     ├─ fault_tolerance_arguments()
       │     ├─ data_arguments()
       │     ├─ eval_arguments()
       │     ├─ algo_arguments()
       │     ├─ on_policy_distillation_arguments()
       │     ├─ wandb_arguments()
       │     ├─ tensorboard_arguments()
       │     ├─ router_arguments()
       │     ├─ debug_arguments()
       │     ├─ reward_model_arguments()
       │     ├─ rollout_buffer_arguments()
       │     ├─ mtp_training_arguments()
       │     ├─ ci_arguments()
       │     └─ custom_megatron_plugins_arguments()
       │
       └─ 最后执行 slime_validate_args() 交叉校验
            └─ --custom-config-path YAML 覆盖 → 最终 args
```
